No test covers a lossy resolution of a renamed file: `test_pre_passes_when_git_carries_an_edit_onto_a_renamed_file` (`tests/test_merge_check.py:473`) walks only the clean merge, and `test_post_follows_a_rename_and_catches_taking_the_deletion` (`:559`) only deletes the new path.

The takeover test has to compare against the other parent's copy under either name — the path, the rename origin and the destination — not only against `other_blob_by_path[path]`:

```python
                if moved_to:
                    if side_key == "target":
                        finding.target_rename = moved_to
                    else:
                        finding.source_rename = moved_to
                # A moved file is not exempt from the P1.16 rule: compare the
                # result's blob with the other parent's copy under either name.
                result_blob = blob(moved_to or path)
                other_blobs = {
                    other_blob_by_path[path],
                    blob_of(other_commit, moved_to or path),
                }
                if origin:
                    other_blobs.add(blob_of(other_commit, origin))
                finding.takeover = result_blob is not None and result_blob in other_blobs
```
