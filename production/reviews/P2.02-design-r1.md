## Design interpretations and DCR verdicts

The handoff files no formal DCR. It lists five readings, and I judge each:

1. **The engine transition bypasses the docs/02 §2.3 gate and the §5 fx budget — support; no DCR required.** §2.3 defines a gate as "earliest stage the value is *offered*" (i.e. to the model) and §5 opens with "the model tends to over-cue", so both govern model picks. docs/01 §3 mandates the glitch on *every* stage change, including stage 1 and 2. The implementer's reading is the only one that satisfies both docs. It is recorded in `stages.json:3`, `Stages.gd:96-99` and the handoff, so it is not silent. The residual risk is a sibling task, not this code — DES-2.
2. **The transition instant is the Instability write, not the turn boundary — support.** Every production write path resolves between requests: turn close (`apply_turn_meters()`), the night roll (`advance_day()`), and the input-hook path (which runs while `_turn_in_flight` is false). P2.03 therefore gets the event with nothing in flight, which is what a server restart needs.
3. **One EVENT line per crossing, even when two bands are skipped — support.** A single glitch gets a single comment; the doc says "often", not "once per stage", and P2.08 can queue additional lines through the same queue.
4. **`STAGE_BANDS`/`STAGE_MAX` removed from `GameState` — support.** A GDScript `const` cannot be read from JSON; the accessors moved to `Stages` with the `Meters` precedent, and the migration is complete (no reference left in `game/`).
5. **`pending_events` is not part of the save snapshot — support (documented).** docs/08 §6 is a "this turn only" layer and a restore is not a crossing. The cost is narrow: a line queued between the last autosave and a quit is never delivered. That is consistent with "she often comments", not a guarantee.

Nothing here touches a pillar, a safety rule or a docs/09 §4 decision, so nothing needs escalation.

## Pillars (docs/01 §0)

1. **She is not scripted** — the crossing hands her a fact, not a line to recite; her voice is still the model's. One watch item, not a defect: four of the five lines also assert her interior state ("you are not sure it went back", "you remember being watched while it happened"). That is closer to narration than to the docs/08 §6 examples ("You waited."), and a 4B model may echo it. NAR can soften the prose in `stages.json` without a code change — the file is the content surface.
2. **The game owns the truth** — the stage, the crossing, the spec and the queue are engine values; the model can only move Instability by a clamped `mood.stress` (`GameState._apply_mood_meter()`), so it cannot announce or skip a stage.
3. **Three engines of dread** — the slow burn raises Instability toward the next band, a spike can jump bands, and both funnel into one monotone stage. The crossing is the point where the three meet.
4. **Her sickness is physical** — the crossing is exactly the trigger P2.03 restarts the steering dose on, so the pillar has its machine-readable event rather than a text effect.
5. **Fourth wall as a scalpel** — untouched: the lines are ordinary diegesis, no meta, no model-visible stage numbers.

## Follow-up seams (P2.03 / P2.15 / P2.19 and the one that is missing)

- **P2.03 (restart) — sensible, with one caveat.** The payload (`stage`, `name`, `duration_s`, `fx`, `cue` plus the signal's `previous`/`current`) is what a restart needs, and the event fires with no request in flight. Caveat: P2.03's own AC says "≤ 3.5 s measured" while the glitch is 2.5 s (hard ceiling 3.0 s). The handoff already tells P2.03 to fit inside `duration_s`; that sentence must reach P2.03's brief, or a restart that honours only the 3.5 s AC will outlive its own cover by a second.
- **P2.15 (glitch shader) — sensible, but incomplete without DES-2.** The handoff correctly says rendering, `Settings.photosensitive` and reduced-motion belong there (`Settings.gd:4-5` already carries both flags). What it does not say is "do not apply `casting.json`'s gate/cooldown to this effect".
- **P2.19 (day/night) — sensible.** `advance_day()` writes Instability, so a night crossing emits the event and queues the line for the next day's first prompt (`StagesTest.gd::test_stage_invariant_over_a_hundred_turns` exercises `advance_day()` in the same loop). The glitch will fire on the night screen, where nothing listens yet; the handoff says so.
- **P2.16 / AudioDirector — missing.** See DES-1.
- **P2.08 / P2.10 (triggers) — usable, with a convention to state.** `queue_event()` gives them exactly-once next-turn delivery, and the reordered `_turn_events.clear()` now lets hook lines survive (`Triggers.gd` is still a stub, so no behaviour changes today). Note the two conventions in the codebase: a scenario's `event` is stored bare and prefixed by `PromptBuilder._scene_layer()` (`EVENT_PREFIX`), while a queued line must carry its own `EVENT:`/`TRIGGER:` prefix (the stage lines do). One sentence in P2.08's brief avoids a bare line or a double prefix.
- **Capacity, not design:** `Director.gd` is now 992 lines against gdlint's 1000 cap (the journal records it), so P2.03/P2.19 cannot grow that file much.
