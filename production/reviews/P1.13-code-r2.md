This also blocks the box's log contract: a hidden `all_displayed` means `ChatUI._maybe_close_turn()` never learns the box went quiet. Fix: on `end_turn`/`reset`, hide the indicator when the queue is empty or fully revealed (add a drained check that accounts for the closed flag), and surface the empty-say state so the Director can clear it after its 3 s window. | ```gdscript
func end_turn() -> void:
	if not _beats.is_empty():
		_beats[_beats.size() - 1]["closed"] = true
	# Nothing is ever coming: clear the indicator so the box doesn't lie.
	if _beats.all(func(b: Dictionary) -> bool:
		return bool(b["closed"]) and str(b["text"]).length() == str(b["i"]).length()):
		hide_typing_indicator()
``` (equivalently export a `drained_or_empty` signal from Typewriter and have TextBox hide the indicator on it.) |
| CODE-2 | S1 | `game/scenes/ui/Typewriter.gd:63-81` | **Reveal rate bursts well past 45 chars/s whenever the front beat is fully revealed but still open (stream pause), and the pause is > 1/cps.** `-credit` banking resets only for the *empty-queue* case (`Typewriter.gd:80-81`); the **fully-revealed-but-open** front beat never banks, so `_credit` grows unbounded during server pauses (docs/02 §2: streamed pauses of hundreds of ms/turns are normal) and the next chunk lands with `floor(credit)` chars revealed at once. Not just a VN-feel nit: the doc's own stated purpose (docs/02 §4) is that the typewriter budget *never* reveals more than 1/40–1/45 s worth per tick while a turn is open — and it isn't just the user-visible markdown: ChatUI's log fed from this beat soaks up the "leap" too (probe-verified). Fix: treat a fully-revealed-but-open front beat the same as the empty-queue case for `reveal`-credit accumulation (hold at ~1/45 s per tick), so a stall never banks more than ms-worth of visible chars. | ```gdscript
if _available() == 0:

Everything else — criteria 1–4 met, deterministic tests, data-driven strings/limits, safety injection point ahead of display+log, keyboard-only contract — is solid and the full `tools/test.sh` is green from my own run. Fix the two state-machine holes, add regression tests for the empty / long-stall branches, and this can be approved on the next round.
