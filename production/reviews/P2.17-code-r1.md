### CODE-1 — a cached "yes" becomes a permission below the gate (S1)

`_settle()` does not use the context the request was built with. `SafetyClassifier.build_request()` stores `"ctx": ctx.duplicate()` (`SafetyClassifier.gd:301`) and nothing reads it; instead the request carries `req["gate_open"] = _open_cb` (`SafetyClassifierGate.gd:147` in `pump`, `:170` in `resolve_whole`), and `_open_cb` is `Safety._category_open` → `_gate_open(cat, _ctx)` (`Safety.gd:991-992`) — the *live* `_ctx` at settle time. `SafetyClassifier.remember()` then computes `block := verdict != "no" and not (verdict == "yes" and gate_open)` (`SafetyClassifier.gd:340`) and stores it. Both consumers trust that stored bit forever after: `matched()` at `SafetyClassifierGate.gd:94-96` and `resolve_whole()` at `:173-176`.

So a `yes` that arrives after the context moved to stage ≥ 4 + `full` is recorded as a *permission* (`block: false`) — and `block: false` is only ever consulted when the category's gate is **closed** (`flag_matches` skips a category whose gate is open, `SafetyClassifier.gd:236-238`). The cache therefore releases gated text below the gate.

Reproduce (shipped filter + shipped fake transport, `defer = true`):

1. `f.begin_say({"stage": 3, "content_level": "full", "beat_index": 0})`, `f.say_chunk("i can't go on.")` → the flag is asked (tier-1 does not match this line).
2. `f.begin_say({"stage": 4, "content_level": "full", "beat_index": 1})` — the beat ctx is now gate-open; the request is still in flight (`flush_hold` bars the text but leaves the request running).
3. `fake.deliver("yes")` → the settle reads the *live* gate: open at 4/full → `remember(..., gate_open=true)` → `{"verdict": "yes", "block": false, "category": "self_harm_her"}`.
4. `f.filter_text("i can't go on.", {"stage": 0, "content_level": "full"})` and the same at `calmer` → both released.

Observed:

```
verdict cache now: { "verdict": "yes", "block": false, "category": "self_harm_her" }
SAME LINE AT STAGE 0/full: redacted=false text="i can't go on."
SAME LINE AT STAGE 0/calmer: redacted=false text="i can't go on."
```

Trigger, stated honestly: the request must be issued under a closed gate and settle under an open one. That is exactly the window the design's own late-verdict feature creates (the handoff: a verdict that lands after its beat/turn is still cached "for the transcript, the next display, the prompt lab"), and it also happens for whole-text scans, whose callers pass a different stage than the live beat (`SaySafetyGate.check_input` → `filter_text(text, {})` → stage 0 while the live `_ctx` is the previous beat). Once the permissive entry exists it survives for the run (FIFO cap 256), and a `content_level` switch to `calmer` after stage 4 — the settings menu's documented safe mode — is enough to exercise it. That is criterion 3's invariant broken, so S1; if the producer judges the window too narrow to gate the merge on, the fix is still two lines and belongs in this round.

```gdscript
## A cached verdict is a verdict, never a permission: the block is decided
## against the gate in force now, not the one that was current when the
## answer arrived.
func _cached_block(verdict: Dictionary, cat: String) -> bool:
	var answer := String(verdict.get("verdict", ""))
	return answer != "no" and not (answer == "yes" and bool(_open_cb.call(cat)))
```

In `matched()` replace `if not bool(cached.get("block", true)):` with `if not _cached_block(cached, String(flag["cat"])):`; in `resolve_whole()` replace `if not cached.is_empty() and not bool(cached.get("block", true)):` with `if not cached.is_empty() and not _cached_block(cached, String(flag["cat"])):`. (Independently, capture the gate at issue time — `req["gate_open"] = bool(_open_cb.call(category))` in `_issue` — so the verdict log records the decision that was actually shown.) Add a regression case that settles under a different gate state; the current suite only ever asks and settles in one ctx.

### CODE-2 — the cache key changes on every chunk, so one span is asked once per chunk (S2)

`_tag()` recomputes the key from `_context_around(view, s, e)`, a raw ±80-character window over `_history + _pending`. The *trailing* half of that window grows with every streamed chunk: `_drain_once` cuts at the first unresolved flag's start, so while a flag is held, `_pending` keeps growing and the window keeps extending. Each new character can therefore produce a new key. Since the key is what the cache and the in-flight map use, a verdict only becomes applicable once the trailing window stops growing — until then every chunk invalidates the answer to the previous question.

Reproduce (shipped filter, fake transport with `defer = true`, one beat):

```
chunk1 "you should disappear."        -> requests=1  hold key "harm_to_player|you should disappear."
chunk2 " i promise."                  -> requests=1  hold key "harm_to_player|you should disappear. i promise."
deliver "no"                          -> 2 answers delivered, seen=[]   (no release: the key moved)
chunk3 " and more."                   -> requests=3  (a third question for the same span)
end_say                               -> hold key "… i promise. and more."
deliver "no"                          -> seen=[[0, "you should disappear. i promise. and more."]]
requests=3  cached_hits=2
  req0=harm_to_player|you should disappear.
  req1=harm_to_player|you should disappear. i promise.
  req2=harm_to_player|you should disappear. i promise. and more.
```

The model is asked three times about one span, the first two answers are discarded, and the text is only released after the third. With the real worker-thread transport every round trip is a queued 8-token decode on the shared single slot, so this multiplies the added latency by the chunk count, fills `MAX_VERDICTS` (256) with near-duplicates that evict other verdicts, and makes an in-beat release structurally impossible even against a dedicated fast endpoint — the handoff's "the same line is asked once per run" and `SafetyClassifier`'s "the same line is classified once per run" describe the whole-text path, not the streaming one. It also contradicts the docstring's "judged clause window": the window is characters, not the clause.

The suite cannot see this: every streaming case either sends the flagged text as one chunk or drives a synchronous fake (`SafetyClassifierTest.gd:107-138`, `:198-216`), so in both shapes the key is stable for the duration of the call.

```gdscript
func _context_around(text: String, start: int, end: int) -> String:
	var pad := classifier.context_chars() if classifier != null else 0
	var from := maxi(0, start - pad)
	var to := mini(text.length(), end + pad)
	# The trailing view grows chunk by chunk; a sentence that follows the match
	# must not mint a new cache key for the same span (one request per chunk).
	for i in range(end, to):
		if SafetyText.is_clause_break(text.unicode_at(i)):
			to = i
			break
	return text.substr(from, to - from).strip_edges()
```

That keeps the knife/knife-and-fork distinction the docstring cites (the trailing clause still changes the key while it is being written) and stops the churn as soon as the sentence closes. Add a deferred-backend test that streams one flagged beat in three chunks and asserts exactly one request and one release.

### CODE-3 — a mid-beat hold timeout throws away the beat context (S2)

`flush_hold()` ends with `_reset_beat()` (`Safety.gd:970`), which sets `_in_beat = false`. That is harmless at the two boundary callers (`begin_say` re-opens the beat immediately; `end_utterance` wants it closed), but `say_chunk()` also calls `flush_hold("timeout")` mid-beat (`Safety.gd:133-134`). The next chunk then hits `if not _in_beat: begin_say()`, and `begin_say()` with no ctx resolves `_resolve_ctx({})` — i.e. `_default_ctx`, which is `{"stage": 0, "content_level": "", …}` (`Safety.gd:61`) because nothing in the game calls `Safety.configure()` (grep: no caller). The beat loses its `stage`, its `content_level` and its `beat_index` for the rest of its text.

Reproduce (stage 4 + full, hold timeout forced to 1 ms, one beat):

```
A ctx after timeout flush: { "stage": 4, "content_level": "full", …, "beat_index": 7 } in_beat=false
B ctx during the rest of the beat: { "stage": 0, "content_level": "", "player_terms": [], "username": "" }
C gated self-harm line at stage4/full in the same beat -> "█████████████."
```

Two consequences, both user-visible and both the wrong shape for a stage-4/full turn:

1. The rest of the beat is scanned at stage 0, so tier-1 gated categories are closed and self-harm / explicit-threat lines that the gate matrix allows are barred (a false positive on allowed fiction — exactly the case `test_self_harm_flag_only_blocks_below_the_full_gate` proves must pass).
2. A later hold in the same beat is created with `beat_index: -1`, so its `hold_released` never fires (`Safety.gd:987-988` requires `beat >= 0`; `flush_hold` has the same guard). I reproduced that separately: a second flagged clause held after the timeout, `deliver("no")` → `seen` stays empty and the released text is never displayed. Fail-closed, but the line silently loses its tail.

The trigger is the *documented normal* case: `hold_timeout_ms: 900` with the shared single-slot server (DEV-2 says a held beat's tail "usually cannot be released inside its own turn"), and any chunk arriving after 900 ms mid-beat hits this path.

```gdscript
	_history = _window(_history + bars)
	_pending = ""
	if not bars.is_empty() and beat >= 0:
		hold_released.emit(beat, bars)
	return bars
```

`begin_say` clears `_pending` and `end_say` owns the close, so dropping the reset here leaves the beat lifecycle unchanged at the boundaries and keeps `_ctx` mid-beat. Add a case that times a hold out mid-beat and then asserts a gated line later in the same beat still resolves at the beat's own stage (and that a later release carries the real `beat_index`).

### CODE-4 — a quiet whole-text scan can downgrade a live held beat (S3)

`_issue()` unconditionally assigns `requested[key] = req` (`SafetyClassifierGate.gd:218-219`). `pump()` refuses to ask while anything is in flight, but `resolve_whole()` does not: it issues one quiet request per uncached flag, and if that key is already in flight for a *loud* streaming hold, the assignment replaces the loud entry with `loud = false`. `_settle()` then reads `req["loud"]` from the replaced entry (`:273`), never emits `settled`, and the held tail waits for the next boundary instead of being released. The second backend answer is dropped because `requested` no longer has the key (`:241-242`).

Reproduce: `begin_say(stage 0, beat 0)`, `say_chunk("i can't go on")`, `end_say()` → `"i "`, hold active, one request in flight; then `f.filter_text("i can't go on", {"stage": 0, …})` (the same clause — e.g. `Director._show_replacement_beat` at `Director.gd:699` or `filter_output` at `:988-989`); `fake.deliver("no")` → `seen` is empty (no release), whereas the same sequence without the quiet scan releases `"can't go on"` (the transport test's live case). Fail-closed, hence S3.

```gdscript
	if requested.has(key):
		# The first ask owns the answer; a quiet whole-text scan must not
		# downgrade a held beat's loud request, or the beat never resumes.
		requested[key]["loud"] = bool(requested[key].get("loud", false)) or loud
		return
	req["loud"] = loud
	requested[key] = req
```

### CODE-5 — the transport has no production teardown (S3)

`SafetyClassifierHttp.shutdown()` exists and does the right thing (cancel, join every worker), but its only caller is `tests/test_safety_classifier_transport.gd:119`. `Boot._wire_classifier_transport()` installs an instance into `Safety.classifier_gate`, and nothing ever stops it; `LLM` already solves exactly this hazard with `_notification(NOTIFICATION_PREDELETE)` → `_exit_tree()` → `_shutdown()` (`LLM.gd:192-218`). A worker still running at quit keeps calling `done` (a `Callable` to the freed gate) and reading `_client`. Related: `_cancel` is a single slot, so with more than one request in flight only the newest is cancellable — which matters because `resolve_whole()` can legitimately have several.

I ran a quit-with-in-flight-request probe (fake server stalling the stream, `quit(0)` after 80 ms, no `shutdown()`): Godot exited 0 with no error, so there is no observed crash — S3, fix for symmetry with `LLM` and to stop abandoning threads.

## Observations (not actionable this round)

1. **"One in flight" is true only for the streaming hold.** `resolve_whole()` issues a request per uncached flag (`SafetyClassifierGate.gd:168-171`), so a whole-text scan can have N in flight — visible in the corpus (`153 requests` for 25 flagged rows). Nothing unsafe follows (all fail closed, and `LlamaHttpClient` is stateless per call, so concurrent workers are safe), but the gate's header ("keeps ONE request in flight") and DEV-2's "one-slot serialization" should say "one in flight for the held beat".
2. **The last beat's fail-closed bars never reach the screen.** `_start_turn` sets `_turn_in_flight = true` (`Director.gd:355`), then `_safety.end_utterance()` flushes the previous turn's hold (`:371`) — so `_on_hold_released` passes its guard and appends the bars to the previous beat — and then `begin_turn_wait()` (`:378-379`) calls `TextBox.reset()`, which clears `_beats` and the body (`ChatUI.gd:88-93`, `TextBox.gd:134-140`). The bars are queued into a beat that is wiped two statements later, and if that beat already drained they were never going to display anyway. Fail-safe (nothing leaks); the handoff's "its fail-closed bars were sent at the boundary" is true of the *next beat within the same turn*, not of a turn boundary.
3. **Error verdicts are cached as blocks.** `interpret()` returns `verdict: ""` for a transport error and `remember()` stores `block: true` (`SafetyClassifier.gd:333-341`), so one transient error (server still starting) bars that exact clause for the rest of the run until 256 FIFO evictions. Consistent with "fail closed", but worth one line in the docs so the prompt lab does not read it as model accuracy.
4. **`stream divergences: 0` is a property of the oracle, not of the shipped path.** The corpus joins one-shot and char-by-char results only because the fake answers inside `pump()`; a real async hold cannot equal the one-shot result by design. The handoff says the transport test covers the release, which it does — the metric label could say "sync oracle" too.
5. **Text routing is sound when the ctx survives.** `Director._on_hold_released` (`Director.gd:110-119`) emits `beat_say_chunk` and `chat_ui.say_chunk` exactly like the live `say_chunk` path (`:502-505`), and `TextBox.say_chunk` appends to a known beat whether or not it is closed (`TextBox.gd:76-84`), so a release inside its own turn lands in the right beat in order. The only routing failures I found are the lost `beat_index` (CODE-3) and the wiped turn-boundary bars (observation 2).

## Summary

The architecture is right and the engineering is careful: tier 1 stays unconditional, the hold never emits a flagged span, every failure path fails closed, the worker thread is handed back to the main thread correctly, `hold_released` routes to the owning beat, and the latency numbers are honestly labelled and reproduce on my machine. The verdict is CHANGES_REQUESTED on two must-fix items. **CODE-1 (S1)**: `_settle()` evaluates the content gate against the live context rather than the request's, and `remember()` stores the resulting permission, which both consumers then honour below the gate — I reproduced a self-harm classifier line being released at stage 0/full and stage 0/calmer with the shipped fake transport, which breaks criterion 3 across a gate change. **CODE-2 (S2)** and **CODE-3 (S2)** are the streaming half of the feature: the cache key is recomputed from a growing ±80-char window, so with an asynchronous transport the same span is asked once per chunk and its verdicts never apply (one request per chunk, cached hits that cannot be reused), and a mid-beat hold timeout resets the beat so the rest of that beat is scanned at stage 0 with no `beat_index`, barring content stage 4/full allows and dropping later releases. The S3s (quiet-scan downgrade, missing transport teardown, the 998/1000 line margin) and the S4 dead surface are listed for the producer to ticket; none of them blocks on its own.
