## Note for the P1 gate reviewer (F3)

**F3 is player-visible and safety-adjacent, and I verified it at the code level:** `Director.submit_player_input`
(`game/autoload/Director.gd:288–290`) emits `turn_failed` and returns *before* the `_abort_turn()` path that every
other failure mode takes (both routes exist at lines ~828–851), and **no production code consumes `turn_failed`**
— `ChatUI` has an `abort_turn()` teardown built exactly for this and it is never called. The result, reproduced
deterministically in `diag_unsafe_input.json`: after Safety rejects a player line, the input box stays disabled and
the typing indicator ("Leila is typing..") stays up forever; the only exit is closing the game. It is trivially
player-triggerable ("What's your home address?"), so it will recur in any human round. The playtest deliverable
itself is still valid evidence (the round correctly counted and diagnosed it; the gate is honestly failed),
but the P1 gate should treat "F3 filed as a P2 task before any further playtest/human round" as a mandatory carry-over.
