## DCR verdicts

- **DCR-1 (the five vocabulary additions) — support.** `absence_hours_lt`, `mentions_memory`, `name_mention`, `text_match` and `{from_event: …}` are the minimum that lets the docs' M rows stay M and T21 stay one row; each is documented in `triggers.json`'s `doc`, in the Python contract and in `TriggerTable`. Fix the documentation target before accepting: the handoff cites "docs/07 §2's trigger row fields", but docs/07 §2 is the project layout — the row vocabulary lives in the data file's `doc` string and docs/08 §6. Schedule a real doc section, not a pointer to §2.
- **Model-only rows author double (T22/T23/T26/T28/T29/T30) — support.** It is the only way a docs-numbered model-only effect lands at docs strength under docs/02 §1.2's halving; it is the P2.10 convention, stated in the data file and pinned by the contract.
- **T25's single stage-tone line — support.** docs/01 §5 says "stage-gated", not "escalates with stage"; the prompt's stage layer supplies the tone. An `axis: stage` line array would re-encode the stage bands into data for no gain.
- **T17/T18's path-shaped reunion carried by the line — support.** The engine has no path channel and docs/01 §5 gives the clock rows no path condition; the prompt's path layer is the right owner.
- **T20's live setter = the photosensitive toggle — reject in part** (DES-1): it is a safety accommodation (docs/05 §0.4, `Settings.gd:4-10`), not a preference.
- **CODE-1…CODE-4 are not DCRs** — implementation defects against the docs, not design changes.
