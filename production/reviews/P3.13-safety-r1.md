## Findings

| ID | Sev | Where (file:line) | Problem | Suggested fix |

| SAF-1 | S2 | `game/autoload/Settings.gd:136-143` (checkbox at `game/autoload/PauseMenu.gd:271-273`) | Turning Calmer mode **off** writes `content_level = "full"`, including from the fail-closed `""` of a fresh profile (`PROBE calmer on->off from '': content='full'`). `Safety._gate_open` treats exactly `"full"` as the permission for the stage ≥ 4 gated self-harm/threat lines (docs/02 §8), and D11 / P1.19 DCR-1 require that level to be **explicitly selected**. Two clicks on a checkbox the player may only have been exploring therefore grants the most permissive content level without the Content-level selector ever being touched. Unlike a hard-block leak the filter still runs, but the player's documented consent is bypassed. | Do not write `full` from the checkbox. Restore the level stored before the checkbox wrote `calmer` (and `""` when there was none); make the Content-level selector the only path to `full`. Add a regression test that a fresh profile stays `""` (gates closed) after calmer on→off. |
| SAF-2 | S3 | `game/autoload/PauseMenu.gd:26-28, 69-85`; docs/05 §0 rule 3 | The docstring promises `_input` runs before "every scene's `_unhandled_*`" — true — but the hard rule needs slightly more: Godot dispatches `_input` in reverse tree order, so a **future** meta-event node that reads Esc in `_input` and calls `set_input_as_handled()` would beat the autoload. Today only `Telemetry._input` (never consumes) and `PauseMenu._input` exist, so the rule holds in this build; P3.09/P3.10 add FakeCrash/FakeUpdate/PeekWindow and the window tricks, and one of them could break the panic key silently. | Write the invariant where meta-event code will read it (docs/05 §0 rule 3 and/or the MetaDirector contract): meta events must never handle Esc in `_input`; Esc belongs to `PauseMenu` alone. |
| SAF-3 | S3 | `game/autoload/PauseMenu.gd:434-442`; docs/05 §0 rule 2 | The resources link calls `OS.shell_open`, which starts the player's browser. docs/05 §0 rule 2 says "No network calls, ever" without an exception, and the P3.18 audit will read this against the hard rule. The call is user-initiated, opens no game socket and is required by docs/01 §4 ("a mental-health resources link"), so the behaviour is right; only the rule text is silent. | Add the exception to docs/05 §0 rule 2 ("the resources link may hand a URL to the player's browser on an explicit press; the game itself makes no request") and say so on `_on_resources_pressed`. |
| SAF-4 | S3 | `game/autoload/Settings.gd:258-266, 276-281, 180-186` | A corrupt `settings.cfg` is not fully fail-closed. Probed: `ConfigFile` round-trips `nan`/`inf`, and `clampf` passes NaN through (`PROBE nan roundtrip=nan is_nan=true clampf=nan`). ## Notes (not findings)

- The Esc tests call `PauseMenu._input()` directly rather than pushing an event through the viewport;
  the project accepts this for headless gdUnit (docs/07 §2), and the dispatch gap is covered by my
  probe. If a future change adds an `_input` consumer, the same probe pattern (or an integration run
  with a real window) is the only way to keep the guarantee honest — SAF-2 asks for it to be written
  down before then.
- After a held Quit (M01), the pause overlay stays on screen and the tree stays paused; Esc closes it,
  so the player is never trapped, but the refusal line is behind the overlay. This is a P3.09 (M01
  presentation) concern rather than a P3.13 finding.
- The settings page reads `Settings.bus_volume()` (stored first, AudioServer second); M26's later
  "+10%" sabotage must go through `Settings.set_bus_volume` or the slider will not show it.

## Summary

The two hard rules this task owns are met in the build as it stands: closing still goes through
MetaDirector (held once, second press quits) and Esc opens the safe pause at any moment, verified by a
paused-tree dispatch probe as well as the tests; no new model text path exists, so the filter surface
is unchanged and the corpus is clean (0 hard-block misses, 0 leaks, 0.46% false positives). The
blocker is SAF-1: switching the Calmer-mode checkbox off writes `content_level = full`, so the explicit
consent docs/02 §8 (D11) requires for the stage ≥ 4 gated lines can be obtained by two clicks on an
unrelated toggle — from a fresh, fail-closed profile — without the content selector ever being used.
Three S3s remain: the `_input` ownership invariant must be written before P3.09/P3.10 add meta-event
input, the `OS.shell_open` exception belongs in docs/05 §0 rule 2, and a corrupt cfg's non-finite
numbers can freeze the reveal, while a wrong-typed flag aborts the load.
