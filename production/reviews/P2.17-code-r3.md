## Observations (not actionable this round)

1. The round-3 summary says "**+9** safety cases"; the delta adds **11** (8 in `SafetyClassifierGateTest`,
   7 → 15 per `results.xml`, plus 3 in the new `SafetyClassifierWiringTest`). The per-file list in the
   same handoff says "8 new cases" and is right; only the total is a slip. Doc-only.
2. `MAX_QUIET_IN_FLIGHT = 4` now spans a 30 s window instead of 900 ms
   (`SafetyClassifierGate.gd:43-45,468-479`). A whole-text payload with more than four uncached flagged
   clauses bars the overflow spans and cannot ask about them until an earlier four settle (the transport
   answers within its 10 s read bound). That is fail-closed and matches the cap's own comment, but the
   transient false-positive surface is wider than in round 2 — worth watching when P2.03 raises the
   number of flagged rows.
3. `MIN_QUIET_TIMEOUT_MS = 12000` is a compile-time constant (`SafetyClassifier.gd:40`); if P2.03 ever
   configures `SafetyClassifierHttp.read_timeout_ms` above 12 s, the loader floor stops meaning "≥ the
   transport bound". No caller sets it today (Boot passes only `base_url`), and
   `test_shipped_quiet_timeout_outlives_the_transport_read_bound` only covers the shipped constants.
4. `Safety._build_lists` still replaces the gate on `reload()`, so a production reload would drop Boot's
   transport and `config_provider` (fail closed — tier 2 just goes quiet). Unchanged from round 2, no
   production caller, already disclosed in the handoff's follow-ups.
5. `_issue` counts a policy refusal as a request (`note_request` before the `has_backend()` check,
   `SafetyClassifierGate.gd:370`), so `requests`/`ms_avg` include zero-latency `no_backend`/
   `steered_backend` entries. Pre-existing (the `no_backend` path always did), tuning-only.
