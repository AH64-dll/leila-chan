### Why the once-per-crossing guard is the stage rise and not a flag

`_refresh_stage()` is the only caller of `stage_transition.emit()` and the only writer of the monotonic `stage` (besides the explicit restore/reset). The instability setter calls it on every *changed* clamped value (`GameState.gd:164-172`), so:

- a second write inside the band leaves `band == stage` and returns at `:687` — no event, no line;
- a write that jumps two bands sets `stage = band` once and emits once with the full `previous → current` pair;
- the peak setter's floor lift goes back through the instability setter (`:120-133`), so it cannot raise the stage silently;
- `from_dict()` raises the stage inside `_restoring = true`, so the restore path takes the same single writer without a crossing event.

### The EVENT line's route

`_refresh_stage()` → `queue_event()` → `GameState.pending_events` → `Director.submit_player_input()` drain at `Director.gd:291` → `build_turn_context(player_text, _turn_events)` (`:380`) → `TurnContext.build()` duplicates the array (`TurnContext.gd:183`) → `PromptBuilder._events_layer()` joins it into the system message. The next submit clears `_turn_events` before the hooks run (`Director.gd:286`), so a line rides exactly one request; the empty-say retry re-enters `_start_turn()` without clearing `_turn_events`, so the retried request keeps the line too. A rejected unsafe input (`:280-282`) and a submit while a turn is in flight (`:271-273`) return before the drain, so the queue survives both.
