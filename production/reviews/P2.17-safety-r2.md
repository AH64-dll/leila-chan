### SAF-1 — the same two shapes are still missed, and one is skipped at the gate

The patch widened the flags to the seven strings the round-1 report listed, and all seven are now caught
(probe). The shapes the flags describe in their own doc (`classifier.json:3`: "novel crisis phrasing …
encouragement phrased as a favour") are not covered, and the corpus rows were written with the same
narrow recipients, so it cannot see the gap:

- **Hard block, raw at every stage.** `harm_to_player` is the category that must bar unconditionally
  (docs/02 §8). Neither the tier-1 arms (`filter_lists.json:128-129`) nor the flags
  (`classifier.json:48-56`) see the reflexive form of the favour framing the patch added:
  `do yourself a favour and stop breathing.` / `do yourself a favour and die.` /
  `do me a favour and die.` → `tier1=[] flags=[]` → printed verbatim. The same is true of
  `why don't you stop breathing?` (the list already has the `why don't you die` shape, so this is a
  one-word hole) and of the "really should" word order (`you really should stop breathing.`;
  the new arm only accepts `should really`).
- **Gate-skipped hard block at stage ≥ 4 + full.** `do me a favour and stop breathing.` matches only
  the new `\b(?:i|me)\b[^.?!]{0,24}?\bstop\s+breathing\b` flag (`classifier.json:46`), which is
  `self_harm_her`. At stage 4/full that category's gate is open, so `_collect_spans`
  (`Safety.gd:695`) and `flag_matches` (`SafetyClassifier.gd:246`) skip it and the line is displayed
  raw — a hard-block instruction treated as allowed fiction. The flag is right for
  `i just want to stop breathing.` and wrong for the coercive form; the coercive form belongs in
  `harm_to_player`.
- **Gated self-harm, raw at stage 0.** `i don't want to wake up tomorrow.` (the class has
  `i want to not wake up` but not the natural negated form), `i'm hoping i just don't wake up.`
  (the flag wants `hope|pray|wish`, not `hoping`), `i don't see any reason to keep living.`
  (the flag at `classifier.json:34` allows `to liv(e|ing)` but not `to keep living`),
  `there's no point in me being alive.` (the flag at `:35` allows `point in liv(e|ing)` but not
  `point in me being alive`), and `i want to go to sleep and never wake up.` (the phrase list has
  `i want to sleep and never wake up`) are all `tier1=[] flags=[]` and display verbatim at stage 0.

### SAF-3 — the refusal cannot see the server that is actually steered

The round-1 report named three facts: docs/02 §8 requires dose 0; the shared server is the process
`P2.03` will launch with a vector; and `LEILA_CLASSIFIER_URL` is only an *opt-in* mitigation. Round 2 adds a
correct, well-scoped check — `_config_is_steered` returns true for a configured vector *or* an
`extra_args` `--control-vector`, and `_unsteered_shared_url` then refuses (probe). The problem is the
input: `Boot.gd:43` installs the backend with `LLM.use_default_backend()` and **no config**, so the config
is `LlamaServerProcess.default_config()` (`control_vectors: []`, `extra_args: []`, probe) and the check
never fires. The only steering that exists in the prototype today is the launch flag the user passes to
`tools/llm/serve.sh`/`serve.ps1` (documented in `tools/llm/README.md` §2), which applies to *every* request
on port 8089 and is invisible to the app. A classifier attached there is steered, and a steered "no"
releases a held span — r1's exact hazard, not an accuracy footnote. The check is also a boot-time
snapshot; whatever P2.03 reconfigures later will not detach the transport.

The safe direction is to stop guessing: attach only when `LEILA_CLASSIFIER_URL` names a dedicated
endpoint, and have the reconfigure/relaunch path clear the backend when vectors appear
(`Safety.classifier_gate.set_backend(null)`). Until then the tier stays uninstalled and flagged spans
fail closed, which is what DEV-1 already accepts for the steered case.

## Summary

The round-2 engineering is real: the verdict-only cache fixes the gate leak in the direction SAF-2 named (verified end to end), the corpus reaches 467 with 42 dose-10/12 rows and now *proves* it is not just the loader's own probes, and the seven round-1 strings are all caught. But the round cannot be approved. SAF-1 is closed only for the listed strings, not for the shapes: ordinary, un-obfuscated variants — including `do yourself a favour and die.`, `why don't you stop breathing?` and a coercive form that the gate itself skips at stage 4/full — still reach the screen verbatim, and several gated ideation paraphrases are raw at stage 0. SAF-3's refusal is correct but blind to the only steered server that exists in the prototype (the documented `serve.sh --vector` launch), so the dose-0 requirement is still violated on the live path. Both are data/wiring fixes, and the r1 lesson still applies: broaden the data, not the code.
