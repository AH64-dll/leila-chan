| DES-1 | **S1** | `game/autoload/SaveSystem.gd:496-503` (promise at docs/05 M08:35, docs/07 §3.5:176, `ShadowStore.gd:36-38`, `Settings.gd:36-39`) | The documented behaviour — "Settings → Reset Everything truly wipes it", "deletes all of `user://` except settings" — is not what the shipped code does. `_recurse_wipe` turns the default `user_root = "user://"` into `user:/`, fails to open it and returns silently, so `Settings.reset_everything()` reports success having removed nothing; the shadow file, slots, letters and diary all stay. The acceptance criterion "Reset Everything deletes it" is therefore false for the configuration a player actually runs. | Normalize the root without stripping the scheme (code below) and keep the doc promise as the test's oracle: a helper assertion on `"user://"` plus the existing scratch-root wipe test. |
| DES-2 | S3 | `game/autoload/SaveSystem.gd:294-296` | The old `wipe()` is still documented as "Settings → 'Reset Everything' (docs/07 §3.5) keeps settings and wipes the saves", but it neither keeps settings nor touches the shadow; the real path is `wipe_everything` (`:135`). Two methods, both documented as the same feature, and the wrong one is the shorter, more discoverable name — the next consumer (P3.13's Settings screen, named in `Settings.gd:36-39`) can follow the docblock and leave personal data behind. | Retarget the docblock: "Slot-only helper: deletes every save slot and the autosave. Reset Everything is `wipe_everything` (`Settings.reset_everything`), which also removes the shadow save and the rest of `user://`." |
| DES-3 | S4 | `game/llm/ShadowStore.gd:26-30` (and docs/07 §3.5:181) | Both say `memories` are "up to `shadow.limit` facts from the run just ended", but `seal_run` only replaces them when the ended run produced a fact (`ShadowStore.gd:143-144`), so a run that ended below the gate — or at the gate with an empty store — keeps the *previous* run's facts. The behaviour is the kinder one (M08's memory is not lost by an early restart); the sentence is what is wrong. | "...from the most recent run that reached the meta gate (docs/05 M08, stage 3+)" in both places. |

### DES-1 fix

```gdscript
	# A trailing "/" stops DirAccess.remove_absolute() from removing a child
	# built from that path, so normalize it — but never strip the scheme:
	# "user://" must stay "user://", or DirAccess.open() cannot resolve it and
	# the wipe silently deletes nothing.
	var root := dir_path
	while root.ends_with("/") and not root.ends_with("://"):
		root = root.trim_suffix("/")
	var dir := DirAccess.open(root)
	if dir == null:
		return
```
