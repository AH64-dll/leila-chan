### DES-1 — the ambience test asserts the wrong invariant (S3)

`test_p3_15_ambience_is_backed` checks that the scenario value is a key of `cue_map["system"]` starting with
`"ambience."`. The runtime does not use that key: `Date.gd:365` builds `StringName("amb." + amb_id)` unless the value
already starts with `amb.`, so `"ambience.paper"` becomes `"amb.ambience.paper"` (proven in headless Godot, above),
which `AudioDirector.play_system()` denies as `unknown` (`AudioDirector.gd:202-214`). D05, I02 and D12 therefore play
no ambience, and the test that was written to prevent that says they are fine. The root cause is pre-existing —
`P2.18-content-r1` already flagged `amb.ambience.paper` for D01 and the P2.18 design reviews filed it as a P1.15/P2.16
wiring ticket. Two facts make the claim unrealisable in this tree, not just for these three files:

- the two audio maps disagree on the key (`cue_map.json` names `ambience.paper`/`ambience.dishes`;
  `audio_rules.json` defines only `amb.rain`), so no value resolves through `Date.gd:365`'s `amb.` lookup;
- **no ambience bed ships at all**: `game/assets/audio/amb/` holds only `.gdkeep`, and the cue_map's
  `sfx_100/100-CC0-SFX_0/paper_01.ogg` / `dishes_01.ogg` paths are not in the repo (the tree ships 53 audio files:
  the music beds, a heartbeat and vocal samples, none under `amb/`) — so `_existing_paths()` would deny the cue even
  with the keys fixed.

Fixes, both inside this patch's reach:

1. **Ship silence until the wiring ticket lands (cheapest):** set D05/I02 to `"ambience": "none"` and D12 to `"none"`
   — the value 17 of the 21 rows already use — and leave the bed to the audio ticket.
2. **Fix the contract end to end (audio-owned):** add `amb.paper`/`amb.dishes` system keys to `game/data/audio_rules.json`
   and to both `cue_map.json` copies, ship the two beds under `game/assets/audio/amb/`, then set the three values to
   `"paper"`/`"dishes"`.

Either way the test must stop claiming a playback guarantee nothing in this tree can deliver. This version pins the
name and says where the guarantee lives:

```python
@pytest.mark.parametrize("name", P3_15_SCENARIOS)
def test_p3_15_ambience_names_a_cue_map_key(name: str) -> None:
    """The scene's ambience is 'none' or names a cue_map system key.

    Playback is not asserted: game/assets/audio/amb/ ships no bed and audio_rules.json defines only
    'amb.rain', so Date.gd:365's 'amb.' + id lookup cannot resolve a cue yet (P1.15/P2.16 wiring ticket).
    This test pins the name the wiring fix must honour, and must not read as a playback guarantee.
    """
    cue_map = json.loads(CUE_MAP_PATH.read_text(encoding="utf-8"))
    backed = {key for key in cue_map["system"] if key.startswith("ambience.")}
    ambience = _scenario(name)["ambience"]
    assert ambience == "none" or ambience in backed, (
        f"{name}: ambience {ambience!r} is neither 'none' nor a cue_map ambience id"
    )
```
