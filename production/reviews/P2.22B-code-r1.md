## Non-blocking notes

- `TriggerEffects.scale/merge/add_path` are exact extractions; the only semantic delta in `_fire` is
  the new `first_effects` merge on `step == 1`, which is off for every other shipped row (empty
  parsed group), so the extraction is behaviour-preserving.
- `campaign_sim._apply_effects` deliberately re-implements `Triggers._apply`'s GameState write loop
  (the header says "without the line queue") so the tool runs without the autoload tree. The
  duplication is acceptable for a dev tool, but the sim now tracks production only as long as the
  two loops agree; if it becomes a maintained gate, share the loop.
- `Meters.DOCS_TABLE` carries the DCR-1 `writers` block even though it is not a docs number; the
  comment says so, and `test_meters_table_matches_docs` still pins only the doc numbers. Fine, but
  the constant's name now over-promises.
- The handoff's open question on T01 recall is real: with `requires: "all"` a genuine name mention
  whose model read is not `jealousy_bait` no longer fires. The recorded run's three keyword hits did
  agree (turns 30/54/81 of the committed transcript are `jealousy_bait` lines; the transcript
  labels the begin-turn firings one turn early), but a prompt-lab pass on the `read` labels is still
  the measurement that would size the loss.
- `game/tools/campaign_sim.gd` is a `SceneTree` tool, not loaded by the game; the `.uid` files are
  the only new binaries and they are text.
