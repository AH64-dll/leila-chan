## Pillars (docs/01 §0)

1. **She is not scripted** — the line is the model's `inner`; the game only decides whether to surface it. ✓
2. **Game owns truth, model owns voice** — the leak chance/gate are game rules; the thought is hers. ✓
3. **Three engines of dread** — a slow-burn signal keyed to the stage (docs/06 §4 row 4 is exactly this). ✓
4. **Her sickness is physical** — the leak reads `GameState.stage`, so it advances with the real dose, not with text FX. ✓
5. **Fourth wall as a scalpel** — 5–30%, staged, once per turn, no input capture, no file/OS surface. ✓

## DCR verdicts

- **DES-DCR-1 — "behind the text box" given a drawable meaning (leak at z −1, tucking 2 px under the
  box's top border; ChatLog lowered to z −2).** **Support.** The shipped panels are opaque (`ChatLog`
  0.75, `TextBox` 0.92 alpha), so a literal z-below-everything draw reads as near-black; the shipped
  form keeps the "surface from behind the panel" read and the render proves it. Update docs/03 §5 with
  one sentence: the ghost sits at the top edge of the text box and is clipped by it.
- **DES-DCR-2 — alignment, `behind_overlap` and the red line's 0.22 s/word + 1.6 s hold are data, not
  docs numbers.** **Support.** docs/03 §5 is silent on both; the values live in
  `game/data/inner_leak.json` and can be retuned without code.
- **DES-DCR-3 — the leak fires on `turn_completed`, not on the `inner` field closing mid-stream.**
  **Escalate** (see DES-1): it changes the ordering the doc's own justification rests on, and the fix
  needs a Director-side signal (the Director is at gdlint's 1000-line cap). The producer/user should
  decide whether that is P3.08 scope or a P2.07 rework.
- **DES-DCR-4 — the leaked line does not run through the Corruption filter.** **Support.** docs/07 §3.4
  places Corruption on the `say` pipeline; docs/03 §5 defines the leak's look only, and keeping the
  earliest warning readable is the point.
