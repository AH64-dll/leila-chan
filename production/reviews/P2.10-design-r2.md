### DES-5 — the offer's reason outlives the offer

docs/05 §2's example is introduced by "(Prompt line (only on turns with an offer))". Round 2 satisfied the positive half:
`MetaDirector.offers()` queues the sentence while `_offer_open` (`game/autoload/MetaDirector.gd:93-97`), and the submit path
drains the queue *before* `_start_turn` calls `offers()` (`game/autoload/Director.gd:307` then `:388`), so the sentence
queued on turn N rides turn N+1 — this is what makes every open turn carry it. The negative half is missing: when the model
answers with `refuse_exit`, `Director._close_turn_success` calls `execute_after_text` (`Director.gd:767-768`), which only
flips `_offer_open` in `_close_offer()` (`MetaDirector.gd:162-166`). The copy queued at `:96` therefore remains pending, and
the next submit drains it into the prompt while `offers()` returns `[]` — the model is told a close attempt just happened
and an action is available when the schema's enum is `["none"]`.

My probe mirrors the real order (drain → `offers()` → `execute_after_text` → drain):
`PROBE des4 turn2 stale_line=true offered=[]`. This is on the offer's success path, not a rare edge: any playthrough where
the model takes the offer gets one turn carrying the false close sentence. The round-2 test cannot see it because it drains
at `game/tests/TriggersT09T15Test.gd:265` and `:267` before consuming at `:269`, so its "A consumed offer stops both"
assertion runs against an empty queue.

I rate this S3, matching round 1's DES-4 for the same sentence and the same class of prompt drift (no state, safety or
gating consequence: the action is still unselectable once `offers()` is empty). The fix is three lines and one test step;
the producer may pull it into this task or ticket it. Suggested patch:

```gdscript
func _close_offer() -> void:
	if not _offer_open:
		return
	_offer_open = false
	GameState.pending_events.erase(_opportunity_line())
	offer_changed.emit()
```

`reset_session()` goes through `_close_offer()`, so it also stops a new session from inheriting a dead offer sentence.

## Notes (checked, not findings)

  `lines=[] flag=true`) and so mutes T04. docs/01 §5's T03/T04 are K rows, i.e. the design's own detector is "the phrase
  appears"; T03 already read that sentence as a confession before Day 3, so this is the literal K reading extended to a
  state flag, not a new rule. If the producer wants it tightened, the lever is the T03 keyword pattern (a sentence-start
  anchor or a negation exclusion) — data only, no DCR.
- **One-content-word facts cannot be contradicted.** With the CODE-3 floor at 2, a fact whose content words collapse to
  one (`You have a sister` → `[sister]`, because "have" is a stopword) can never reach T13 (probe: `one-word-fact lines=[]`).
  This is the precision trade-off round 1's suggested fix asked for; P3.07 can revisit if single-word facts need guarding.
- **Same-turn T03 → T04 relies on catalogue order.** `_observe` writes the current `ctx` flags copy and `_observe` runs
  per row in catalogue order, so T03 must precede T04 for the Day-12 confession case. Shipped order is correct and the
  test pins it, but the data file's `doc` string explains `observe` without saying that order matters — one sentence there
  would protect a future data edit.
- **T13's source is heuristic.** `MemoryRules.grounding_input` takes the newest window message that shares a content word
  with the fact. That is always a verbatim player line (better than the paraphrase) but not a guaranteed causal
  attribution when several messages share a word; docs/02 §6 rule 1 only requires one shared word, so this is the
  strongest attribution the seam can offer without model cooperation.
- **T04 still needs the night check.** It fires on the first submit on/after Day 10 (unchanged round-1 follow-up for
  P2.19); round 2 does not move that.
