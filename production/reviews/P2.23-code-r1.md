| CODE-1 | S3 | `game/tests/DateSceneTest.gd:66-68` | The new "cleared on exit" assertion cannot fail: in the pinned engine a freed Object Variant compares `== null`, so `assert_object(Director.chat_ui_node).is_null()` passes whether the Director holds `null` or the freed ChatUI. The handoff's criterion-3 row ("frees the scene, and asserts the registration is cleared (`:68`)") therefore overstates what the test proves, and a regression that drops the clear would go unnoticed. `is_same()` does distinguish the two states (false when cleared, true when dangling), so capturing the UI before the free pins it. | Capture `ui` before the free and assert `is_not_same(ui)` after it (snippet below). |
| CODE-2 | S3 | `game/tests/DateSceneTest.gd:57-68` | The identity guard in `_exit_tree` (`Date.gd:123`, "Another date's live ChatUI is never touched") has no regression test. With the body replaced by an unconditional `Director.register_chat_ui(null)`, `DateSceneTest`, `DirectorFallbackTest` and `SceneFlowTest` are all green. The guard is load-bearing: in a two-Date probe (old scene still in the tree while the new one registers, as `change_scene_to_file` does) the mutant leaves the survivor unregistered and its unsafe-input refusal never releases the input box (`b_input_enabled_after_refusal=false` vs `true` on the real code) — the same silent lockup P1.31/F3 fixed. No current shipped flow keeps two Dates alive at once, so this is transition/future protection rather than a live bug, but it is one cheap test away from being covered. | Add a two-Date case (snippet below). |
| CODE-3 | S3 | `game/scenes/Date.gd:113-122` | `if not is_instance_valid(registered): Director.register_chat_ui(null)` is unreachable: a registration that points at a freed node already compares `== null`, so the early return at `:119-120` runs before `is_instance_valid` can clear it (probe: freed Variant `eq_null=true`, `typeof=24`). Nothing breaks today because every Director consumer tests `!= null` and a freed Variant reads as null there, but the branch and its comment describe behaviour the code cannot perform. | Drop the unreachable branch and state the actual contract (snippet below). |
