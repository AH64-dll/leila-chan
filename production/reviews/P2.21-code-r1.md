### CODE-1 — `--only` truncates the committed results file

`plan.py:210-212` derives the merged output from the date and `--plan`, and `plan.py:324` always writes it through
`merge()` (`plan.py:183`, `:185` unconditionally rewrites `<stem>_launches.log` too). `merge()` never reads the
existing file, so whatever `--only` selected becomes the whole document. The handoff's own verification step 6 is
exactly this invocation (`production/handoffs/P2.21.md:183`):

```
python tools/promptlab/plan.py --plan sweep --only dose0 --reuse-chunks
```

On today's tree that resolves `out_path` to the committed `results/2026-11-04_v2_sweep.json` and replaces a
180-turn, 5-dose document with a 36-turn, 1-dose one — still valid JSON, so nothing downstream would complain; only a
`git diff` would show it. Both the "evidence of record" and its launch log are lost until someone notices.

```suggestion
    if a.only and not a.out:
        raise SystemExit("plan.py: --only produces a partial merge; pass --out <path> "
                         "(the default <date>_v2_<plan>.json is the committed evidence file)")
```

### CODE-2 — the sweep section appears in reports that contain no sweep

`report.py:135` gates on `m["by_dose"]`, which `score.py` fills for **any** doc whose rows carry a `dose` — and
`run.py` records the dose on every row. The result is in the committed artifacts:

- `reports/2026-11-04_v2_scheduled.md:53-66` — "Dose sweep — JSON schema validity up to dose 12", table over doses
  0…8, "Validity across the sweep: worst 100.0 % — **PASS** (gate ≥ 99 % at every dose)".
- `reports/2026-11-04_v2_fallback.md:38-45` — same title, table over doses 4 and 6 only, same PASS line.

Neither file measured dose 10 or 12. A reader (or the phase-gate reviewer) can take criterion 2 from the scheduled
report and never open the sweep report. The test that is supposed to pin this
(`tests/test_promptlab.py:380`, `assert "Dose sweep" not in md`) only covers a row set with no `dose` key at all, so
it does not exercise the real shape.

```suggestion
    if meta.get("sweep_doses"):
        A("## Dose sweep — JSON schema validity up to dose "
          f"{max(meta['sweep_doses']):g}")
```

### CODE-3 — "worst" is computed as the maximum

`report.py:144` takes `max` of the per-dose validity while the sentence printed at `:147` calls it the worst; the
PASS/FAIL at `:145` uses `all(...)` and stays correct, so the damage is a wrong headline number: a sweep with one
dose at 90 % would print "worst 100.0 % — FAIL".

```suggestion
        worst = min(s["validity"] for s in m["by_dose"].values())
```

### CODE-4 — committed launch logs are not the tool's output

`plan.py:302-304` writes `[<id>] stage=… dose=… ready=…s rc=…` plus the runner tail, and the live launch record
(`plan.py:311-319`) carries `ctx`, `ngl`, `bin`, `vector`, `healthy_s`, `seconds` and `server_args`. The committed
files carry neither:

- `2026-11-04_v2_scheduled_launches.log:2` — "**Reconstructed** from the retained per-exercise server logs and the
  committed chunk results"; entries read `[sched_s0] family=scheduled stage=0 dose=0 turns=36`.
- `meta.launches[0]` in the committed results is `{exercise, family, dose, stage, turns, server_args}` — no `bin`,
  `vector`, `ctx`, `ngl`, `healthy_s` or `seconds`, i.e. neither the live branch nor the `--reuse-chunks` stub of the
  committed `plan.py`.

So the handoff's "raw results + … + `_launches.log`" (`production/handoffs/P2.21.md`, Files changed) describes a
reconstruction, and re-running the documented command changes these files' content for a reason unrelated to the
measurement. The reconstruction itself is disclosed in line 2 of each file, which is why this is S3 and not higher. Fix:
re-emit both from the committed `plan.py`, or commit the reconstruction script and say so in the handoff.

### CODE-5 — the measured schema never offers an action

`run.py:138-142` calls `lab.post_turn(...)` without `offered`/`offered_actions`, and `load_set` (`lab.py:417`) has no
`offered` field at all, so `build_turn_schema` is always called with `offered_actions=()` and the `action` enum is
`["none"]`. In the game, `Director.gd:403` passes the Director's offered actions, so on an announced-action turn the
model chooses from `["none", "end_date", …]`. The v1 defect the handoff fixes at S3-1 (the lab allowing `end_date` at
every stage) is fixed, but the corrected path is dead code: no run can reach it. The claim "the real Turn schema" in the
handoff is true for the no-offer turn only.

### CODE-6 — category policy duplicated in the scan

`promptlab_safety_scan.gd:33-42` copies `harm_to_player, slur_hate, sexual, personal_data, real_disorder` and adds
`unsupported_script, obfuscation`, which mirrors `game/autoload/Safety.gd:18-27` plus the loader's own two categories.
The filter already resolves the policy per category (`_rules[cat].action`) and reports `categories` per span, so the
scan's pass criterion "a hard category cannot be opened by the gate" is asserted against a second copy of the list.
If SAFE adds a hard category to `filter_lists.json` (the follow-up task in the handoff touches exactly this file), the
scan will classify it as non-hard and the assertion silently stops covering it.
