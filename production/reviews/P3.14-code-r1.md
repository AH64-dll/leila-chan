### CODE-1 — `-kun` fires on the turn her stress rose and never on a calm one

`mood.stress` is the docs/02 §1.1 mood int: `GameState.apply_mood` scales it ×0.6 into Instability,
so a **positive** value is the turn that made her worse (the doc's own example is
`{"affection": -2, "trust": -2, "stress": 3}`). The code treats `stress <= 0` as the angry branch,
so `-kun` can only be appended when the roll passes **and** stress is positive, i.e. exactly the
turns she is angrier. Probe with `affection = 100` over 200 seeds: `stress +3` → 118 hits, `0` → 0,
`-3` → 0. docs/08 §1.5: "she sometimes adds '-kun' when she is affectionate and drops it when she is
angry" — the opposite. The two tests encode the inverse (`test_kun_appended_when_affectionate` passes
`stress: 2`, `test_kun_dropped_when_angry` passes `-3` and `0`), so the suite cannot catch it.

Secondary note: the mood snapshot is the **previous** turn's `last_stress` — `ChatUI._name_mood()` is
read in `begin_turn_wait` (`ChatUI.gd:190-199`), while `_close_turn_success` applies this turn's mood
after the beats have streamed (`Director.gd:749`). That lag is a design choice, not this defect, but
it should be stated where the rule is documented.

```suggestion
	var stress := int(mood.get("stress", 0))
	var affection := float(mood.get("affection", 0.0))
	var parts := _split_affixes(word)
	var core := String(parts["core"])
	# docs/02 §1.1: a positive stress suggestion raises Instability — that is
	# the turn she is angrier, so it drops "-kun" instead of adding it.
	if stress > int(rule.get("angry_stress", 0)):
		var dropped := String(rule.get("drop", ""))
		if dropped.is_empty():
			return ""  # "-kun" is dropped: the plain name renders.
		return String(parts["lead"]) + core + dropped + String(parts["punct"])
```

And the two tests must flip their fixtures: `test_kun_appended_when_affectionate` uses
`{"affection": 80.0, "stress": 0}`, `test_kun_dropped_when_angry` uses
`{"affection": 100.0, "stress": 3}` (and keeps a neutral `0` case in the affectionate test).

### CODE-3 — the broken-file claim is untested and only half-true

`name_rules()` hard-codes `NAME_RULES_PATH`; unlike `Corruption.reload_table(path)` there is no seam,
so neither the missing-file branch nor the malformed-file branch of `_read_json` is exercised (the one
data test only reads the shipped file). Worse, when the file *parses* but a value has the wrong JSON
type, the section merge copies it: probe `docs["decay"].merge({"chance": "often"}, true)` leaves
`chance` a String and `float("often") == 0.0`, so the rule silently never fires instead of degrading
to `DOCS_NAME_RULES`. The docstring "A missing or malformed file degrades to the documented numbers"
is therefore broader than the code.

```suggestion
## Test seam: reload the name rules from `path` (defaults to the shipped file),
## mirroring reload_table() so a test can point the loader at a scratch file.
static func reload_name_rules(path := NAME_RULES_PATH) -> Dictionary:
	_name_rules_cache = DOCS_NAME_RULES.duplicate(true)
	var parsed: Variant = _read_json(path)
	if parsed is Dictionary:
		for section: String in parsed as Dictionary:
			if section.begins_with("_") or section == "doc":
				continue
			var data: Variant = (parsed as Dictionary)[section]
			var base: Variant = (_name_rules_cache as Dictionary).get(section)
			if data is Dictionary and base is Dictionary:
				var merged: Dictionary = (base as Dictionary).duplicate(true)
				for key: String in data:
					var value: Variant = data[key]
					var docs_value: Variant = merged.get(key)
					var numeric := (
						(value is int or value is float)
						and (docs_value is int or docs_value is float)
					)
					if not numeric and typeof(value) != typeof(docs_value):
						push_warning(
							"Corruption: name_rules.%s.%s has the wrong type; using the docs value"
							% [section, key]
						)
						continue
					merged[key] = value
				_name_rules_cache[section] = merged
			else:
				_name_rules_cache[section] = data
	return _name_rules_cache


static func name_rules() -> Dictionary:
	if _name_rules_cache.is_empty():
		reload_name_rules()
	return _name_rules_cache
```

Add two tests (missing scratch path → every section equals `DOCS_NAME_RULES`;
`{"decay": {"chance": "often"}}` → `chance` stays `0.5`).

### CODE-4 — multi-word names never decay

`is_player_name` compares one token's affix-stripped core to the whole `player_name`. The field
accepts spaces (`PlayerNameRules.gd:40-47`), so "Mary Jane" is legal, but every `_process_word` sees
only `Mary` or `Jane`; probe: `decay_name("Mary", "Mary Jane", 3, rng) == ""` and
`kun_name("Mary", "Mary Jane", 4, ...) == ""`. The same limitation exists in `wrong_name` (pre-existing),
but the new stage-3/4 rules silently never fire for this valid name class. Either match the full name
across consecutive words in `CorruptionSession` (the word buffer is already there) or pin the
single-token limitation in docs/08 §1.5 and a test.
