## Detailed Audit

### 1. Vector Extraction and GGUF Build (`dump_residuals.cpp`, `build_path_vectors.py`)
- `tools/steering/dump_residuals.cpp`: Extended cleanly with `--pairs <FILE.tsv>` and `--means-out <FILE.npy>`. In pair mode, lines format as `context<TAB>reply`. Context and reply are correctly chat-templated with thinking disabled, matching server prefill. The reply token span is located through prefix tokenization comparisons (`common_tokenize`), and residuals are averaged over reply tokens only. If any pair prompt is truncated or skipped, the tool aborts immediately with exit code 1 to prevent row desynchronization.
- `tools/steering/build_path_vectors.py`: Computes the per-layer mean activation difference across all 200 pairs, normalizes each layer to unit L2 norm, and outputs GGUF control vectors with standard `direction.10` through `direction.20` tensor naming. Shipped GGUF files match the format required by `llama_set_adapter_cvec`.

### 2. Blind-Read Harness (`tools/steering/blind_read.py`)
- Generator extensions:
  - `--base-url` allows targeting a running llama-server instance (e.g. for `none` condition and judging), eliminating unnecessary server restarts.
  - `--completion` executes `llama-completion` directly per prompt with `--control-vector-scaled`, allowing steered generation without interrupting the live unsteered game server.
  - Generates 70 transcripts across 10 held-out prompts (`tools/steering/prompts/held_out_v1.txt`) × 7 conditions with deterministic seeds (`70001+i`).
- Judge:
  - Uses unsteered model with temperature 0.0, shuffled label presentation (`SHUFFLE_SEED + number`), and prompt instructing 1-word label selection with explicit trait definitions.
  - Scoring computes condition confusion matrices, accuracy, and maps against `KEEP_THRESHOLD = 0.70`.
  - Retention probe inspects transcripts for session retention / cross-run logging claims, confirming 0% retention claims for `aware` at scale 0.5.

### 3. Date Scene Fix (`game/scenes/Date.gd`)
- `Date.gd`: Added `var _date_started: bool = false` guard to `start_date()`. In tests like `DateSceneTest`, tests invoke `start_date()` synchronously, while `_ready()` schedules a deferred `start_date.call_deferred()` when `auto_start` is true. The guard ensures idempotency, preventing re-execution of the opening sequence and resolving pre-existing test flakes.

### 4. Judge-Validity Control Analysis
- Control deck `experiments/steering/blind_control_v2`: Evaluated 36 human-authored texts (6 per trait) designed to clearly exhibit each trait. The zero-shot 4B judge scored only 44% overall (possessive 0.67, aware 0.50, contempt 0.50, unstable 0.33, hollow 0.33, lucid 0.33).
- Are the fallbacks real or judge-limited?
  - `lucid` is primarily judge-limited: at +0.5 scale on a neutral prompt, lucid produces grounded, calm replies ("That's wonderful to hear! I'm really glad you arrived safely...") that an unsteered 4B judge with 7 options classifies 10/10 as `none`. Even on human text, lucid scored only 33%. Furthermore, `lucid` is designed as an ANCHOR vector to be applied at negative scale against malice/unstable drift, so a +scale blind test on stage-0 prompts inevitably collapses into baseline.
  - `unstable` (0.20), `contempt` (0.10), and `hollow` (0.30) are a combination of real vector limitations and judge limitations: at 0.5 scale, the vectors produce blended or subtle effects (e.g. contempt produces theatricality and meta-commentary rather than cold cruelty; unstable produces panic with possessiveness; hollow produces third-person fiction with melodramatic horror tropes). The judge struggles to differentiate these nuances.
  - Falling back to prompt-only modules for these four vectors is the safe, design-mandated decision per docs/06 §5.
