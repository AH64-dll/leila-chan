## Design interpretations / DCR verdicts

The handoff files no formal DCR; it labels four readings as "docs were silent — flagged for the design reviewer". My verdicts:

- **Monotonic stage — support.** The SYS playbook explicitly asks for "stage monotonic within ratchet rules"; it prevents band-edge flapping and keeps the stage-3 path lock coherent. Follow-up for P2.02: docs/01 §3's stage table and docs/02 §9 key the steering dose to stage, so a good-day Instability dip does not lower the dose. If design wants the dip to lower dose, that is a docs/01 §3 vs docs/02 §9 clarification for P2.02, not a P1.04 blocker.
- **`read` → counter map (compliment→flattery, leaving as cold) — support.** docs/01 §2 does not specify the mapping; it lives in `game/data/profile_map.json`, so retuning is one data file. P2.12 should validate the resulting path distributions.
- **All meters start at 0 — support.** docs/01 gives ranges, not starting values; P1.15 scenario data can seed a warmer first meeting without a code change.
- **`inconsistency` warm/cold tone map — support.** It counts warm↔cold swings per docs/01 §2; neutral reads do not break the swing; leaving is cold-toned.

None requires escalation: the monotonic-stage reading stays compatible with pillar 4 (stage still drives the dose; the Instability dip remains visible in the meter), and the other three are balance/mapping choices. Nothing here touches the safety rules (docs/02 §8, docs/05 §0) or a docs/09 §4 decision.
