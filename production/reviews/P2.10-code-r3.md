## Notes (checked, not findings)

- **Why one `erase()` is enough.** `queue_event` drops duplicates and trims (`GameState.gd:490-496`), `TurnSchema.opportunity_line` also strips edges (`TurnSchema.gd:116-123`), and the fallback constant has no edge whitespace — so the queued string and `_opportunity_line()` are byte-identical and at most one copy can exist. Probe `queue_size=1`.
- **`_close_offer()` is the only writer of `GameState.pending_events` outside `GameState`.** The array is a public autoload field that `NightLoop` already reads (`game/llm/NightLoop.gd:64`, `:88`), so this is consistent with the existing seam surface; no behavioural effect. Not a finding.
- **No consumer is skipped by the removal.** `offer_changed` and `close_held` have no listeners outside `MetaDirector`, and `MetaDirector.state()` is read by the overlay/tests only; the F3 view reports `offer_open=false` and still `exit_refused=true`, which is the documented outcome.
- **`erase()` depends on the gates data not changing mid-session.** `_opportunity_line()` re-reads `data/stage_gates.json` through a cache (`TurnSchema.gd:100-123`); a hypothetical live edit between queue and close would make the erase miss. No shipped path reloads that file mid-run, and the test pins the data/fallback pair, so this is a robustness remark, not a defect.
