## Findings
| ID | Sev | Where (file:line) | Problem | Suggested fix |
|---|---|---|---|---|
| CODE-1 | S4 | `production/tools/track.py:69` (`HANDOFF_AGENT_RE`) | The regex only matches a comma between the date and `agent:` in a handoff header (`## Round 1  (2026-11-02, agent: swe2)`). If a future handoff is written as `## Round 1  (2026-11-02 - agent: swe2)` or with another non-comma separator, the implementer declaration is silently not parsed — that handoff then counts as "no declared backend", weakening validation for such rounds. | Broaden the regex separator between the header fields (e.g. match `[,;\\s-]+` before `agent:` instead of just `,`), or document the exact expected header format where the protocol shows the handoff template, plus a test that a dash between the fields also matches. |
| CODE-2 | S4 | `production/tests/test_track.py:759` (`test_review_rejects_a_second_verdict_for_the_same_kind_while_not_in_review`) | The duplicate (kind, round) verdict guard exercised by this test only runs when the task status is not `in_review`. If a task somehow re-enters `in_review` for the same round (a producer re-running `set … in_review` through a permitted transition), the guard is bypassed and a second verdict for the same (kind, round) can be recorded. Guarding the duplicate check on the task's status rather than on the recorded pairs makes the protection narrower than its purpose. | Move the duplicate (kind, round) check out of the "not in_review" branch and run it regardless of status, so the same review kind of the same round can never be recorded twice. |
