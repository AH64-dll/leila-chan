Traced items that were checked and judged correct (not findings):

- **Silent drop policy matches design**: `FX.trigger` emits `fx_dropped` with a reason and returns `false` — docs/02 §5 says over-budget picks "are dropped silently, never sent back to the model"; `fx_dropped` feeds only the dev overlay. `test_drops_report_reasons_and_stay_silent` pins this.
- **Cross-boundary dispatch**: producer `FX.trigger`/`debug_trigger` → consumer `Character.play_fx(name)`. All five `IMPLEMENTED` names have a `match` branch (`Character.gd:188-203`); the `_` default returns `"unimplemented"`, surfaced by `FX.trigger` as a `skipped` drop. Nothing can be silently discarded at the boundary.
- **Cooldown semantics**: fire on T locks T+1..T+N (`_on_cooldown` uses `turn_count - last <= gap`), refire at T+N+1 — both the data comment, docs/10 §2.2 and the test agree. Drops never book (`_record` only runs after a successful host play), proven by `test_unimplemented_names_drop_before_cooldown`.
- **`max_per` window**: window opens at the first firing, expires when `turn_count - start >= turns`, and a post-expiry drop path returns `false` from `_over_window` before the count resets, so the next firing re-opens cleanly (`_record`). `test_max_per_window_cap` covers expire/refire/expiry-refuse; only `shake_big`/`glitch` carry caps (docs/02 §5).
- **`zoom_face` await race**: the 1 s hold uses `create_timer`; a concurrent `set_camera` during the hold defeats both the `_zoom_token` guard and the `_cam_live == "bust"` check, so the stale return cannot fire (`test_zoom_face_return_loses_to_a_newer_camera_move`). If the scene exits mid-hold, the resume runs on a freed node — guarded by `token == _zoom_token` and the weakref host semantics; the scene is project-lifetime so exposure is nil.
- **Host lifecycle**: `register_host` uses a weakref; dead hosts drop on access; `unregister_host` only clears when it owns the ref (no clobbering a newer registration). `FXTest.gd` verifies the freed-host path.
- **Reduced motion**: shake and both particle loops cut; in-flight particles are removed synchronously via `remove_child` + `queue_free`. Drifting particles are owned by their own tweens so two fires in one turn double the particles by design (not per-turn unique); not a spec conflict. This is behavioural, matches docs/02 §2.3.
- **Photosensitivity**: sparkle and twitch chromatic-split use colour/alpha only, no luminance flash > 3 Hz; the shader uses `hint_screen_texture` with no flash bloom (docs/02 §2.3 flicker/invert_flash are not implemented and drop as unimplemented).
- **Palette / pixel-art constraint**: `COL_*` come from `palette.json` ramps and `_pixel_tex` is authored ×2 / displayed at ×0.5, matching body-art texel density; palette test samples HTML-triplet membership against the authoritative file.
- **Dev-only guard**: `FxMenu` is created only from the F6 handler which returns on non-debug builds; `_unhandled_input` doesn't call `get_viewport().set_input_as_handled()` on debug-overlay miss.
- **Threading/typiness**: static typing and early-return guards throughout both new files; signals (`fx_triggered`, `fx_dropped`, `turn_ended`) are the cross-boundary contract rather than direct calls into other systems.
- **Permissions/data**: generated outputs (`casting.fx` in both copies + docs/10 §2.2) re-render with 0 diff; bridge reports 66 files in sync — the generator is the single source, no fork.
