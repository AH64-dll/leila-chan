Why the slice belongs in the snapshot and not in the prompt layer:

- The only writer of the history array is `submit_player_input()` (`game/autoload/Director.gd:285`, declared
  `Array[Dictionary]` at `:20-21`); the append must stay, because the next window needs the line and an
  unanswered line stays said.
- The only reader of `ctx["history"]` in `game/` is `PromptBuilder._window` (`game/autoload/PromptBuilder.gd:364-406`),
  whose contract is "history = prior exchanges". `_messages()` (`:458-469`) appends the window and then
  `player_message` once, so the sent array is now `[system, prior pairs…, this line]` — the docs/08 §1 shape.
- No other ctx consumer touches history: `Steering.dose_for`, `TurnSchema.build_turn_schema`, and
  `_log_turn_record` (`Director.gd:878-908`, which records `prompt`/`schema`/`output`, not `ctx`).
- The one other consumer of a *recorded* prompt's user messages is `replay_turn()` (`Director.gd:917-924`),
  which keeps the last user message; that text is identical before and after the fix, so replay is unchanged.
- `get_current_dose()` calls `build_turn_context("")` (`Director.gd:229`); the empty-text guard keeps that path
  bit-for-bit as before.
