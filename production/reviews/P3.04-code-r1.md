## Detailed audit

### 1. `dose.json` data model (v2)

- `stages` keeps `malice` identical to `sampling.json`'s `dose` column and docs/02 §9 (0/2.5/3.5/4.5/6/8) — `SteeringTest` enforces the match. `path_mix` is now explicitly the *pre-assignment interim* weight: 0/0.1/0.2 flat from stage 2 on.
- `weight_curves` gives each keep vector its own per-stage ramp 0→0.5. Both curves are identical today; the per-vector structure is what docs/06 §3's "each with its own weight curve" asks for and leaves room for divergence (e.g. `aware` peaking earlier) without a schema change.
- `path_vectors` uses `null` (JSON) for the four D21 fallbacks — an explicit decision, distinct from a missing key. `_map_from` stores only non-empty strings, so `null` → no entry → `_vector_for` returns `""` → `_weight` returns 0 and `schedule_for` emits no path key. Verified in `SteeringTest.test_fallback_paths_schedule_no_path_weight` and by re-running the dose map for every stage × path × `{""] , six ids, "YANDER"}`.
- Band math: every scheduled path-side weight is ≤ 0.5 (the measured coherent ceiling); `path_mix` max is 0.2. Malice unchanged (≤8 base, ≤12 clamped). The 104-turn matrix ran the worst case (`malice=8` + `possessive=0.5`/`aware=0.5`) at 100% validity.
- Divergence note (not a defect): `path_mix` is flat 0.2 at stages 2–5 while the keep-vector curve ramps to 0.5. A stage ≥2 turn *before* path assignment therefore schedules 0.2 where docs/06 §3's "path weight" column reads 0.3/0.4/0.5. The doc table describes the keep-vector curve; `path_mix` is documented as pre-assignment interim. In practice the window is narrow (path soft-assigns at the stage-2 crossing, before the next turn's dose), so the flat 0.2 is defensible — but see DES/CODE-2 below.

### 2. `Steering.gd` resolution logic

- `schedule_for` now resolves `path` → `vector` → `weight` before the calmer cap, and the cap is applied **component-wise** to the bound vector's stage-3 curve weight (`_weight(vector, path, CALMER_STAGE, cap)`), not the row's `path_mix`. This is correct: a calmer stage-5 YANDERE turn is exactly a stage-3 YANDERE turn (malice 4.5 + possessive 0.3), pinned by `test_calmer_mode_caps_the_vector_curve_at_stage_3`.
- Fail-closed on unknown paths: `{"stage":4,"path":"YANDER"}` → `{"malice":6.0}` only — no vector, no `path_mix`. Pinned by `test_an_unknown_path_schedules_no_path_weight`. Correct: a typo'd path must not inherit the interim weight.
- `_weight` falls back to `row[PATH_MIX_KEY]` with a `push_warning` when a bound vector lacks a curve entry for the stage — a degrade, not a silent zero. Acceptable; the data files always carry all six stages.
- `reload_table` missing/malformed handling now resets all three caches (`_table`, `_path_vectors`, `_weight_curves`) — no stale-map leak between reloads. `_map_from`/`_curves_from` degrade to `FALLBACK_*` only when the whole block is absent; an explicit `null`/`{}` decides. This matches the D21 contract precisely.
- `offset_dose` (docs/02 §7 retry −2) still lands once on `malice` only; the path weight is untouched — verified by `DirectorFallbackTest` update (path_mix 0.1 after retune).
- `describe()` renders the path slot as `possessive 0.3` (no `/12` suffix — only malice gets it, matching docs/06 §1's malice-axis curve). Cosmetic, documented in the comment.

### 3. Call-site wiring

- `Director._start_turn` passes the full `ctx` (which carries `path` from `TurnContext.build` → `GameState.path`) — so per-turn dose and stage-relaunch dose agree.
- `Director.get_current_dose` and `full_run_driver` now pass `{"stage", "path": GameState.path}` explicitly — the F3 overlay shows the bound vector, not `path_mix`, once a path exists.
- `LLM._dose_for_stage` reads `GameState.path` at binding time — the stage-change relaunch (`apply_stage_steering` on `stage_transition`) binds the keep vector if the path was assigned by `_evaluate_path`. Ordering check: `_refresh_stage` emits `stage_transition` *before* `_evaluate_path()` runs `assign_path`, so the relaunch triggered by the stage-2 crossing computes the dose while `GameState.path` is still `""` → it binds `malice` + reports `path_mix` unbound. The *next* turn's `dose_for(ctx)` carries the assigned path and the request-side dose is correct, but the server relaunch bound at the crossing does not include the keep vector until the next crossing or reset. **This is a real behavioural gap** — see CODE-1.
- Wait — re-checking: `apply_stage_steering` → `_dose_for_stage(stage)` → `dose_for({"stage","path"})`. At the stage-2 crossing, `stage_transition` fires inside `_refresh_stage` before `_evaluate_path`, so `GameState.path == ""` → dose = `{malice:3.5, path_mix:0.2}` → `path_mix` unbound → server relaunches with malice only. Then `_evaluate_path` assigns e.g. YANDERE. Subsequent turns' `TurnRequest.dose` says `{malice:3.5, possessive:0.2}` but the running server was launched without `possessive.gguf` — the prototype's dose is a launch flag, so the keep vector is **never bound** until the next stage transition or `state_reset`. The dose map on the request and the server's actual bound vectors diverge for the entire stage-2..N-1 window. This defeats the feature's purpose for exactly the stages it was built for. **CODE-1 (S1).**

## Summary

The data model, retune, D21 fallback handling, prompt-lab plumbing and test coverage are all solid — the schedule data is coherent, every bound weight rides the measured ≤0.5 band, and the 104-turn matrix proves 100% JSON validity at the band ceiling. Fix the ordering (or re-apply on `path_assigned`), add a crossing-order test, correct the handoff's `mods` claim (CODE-2), and surface the pre-existing gdformat red (CODE-3) rather than absorbing it.
