## Summary

The feature is real and well tested: both acceptance criteria are met, all 812 suites pass, the Esc
architecture is right (`_input` + `PROCESS_MODE_ALWAYS`, verified live by a headless probe), every
setting persists and reaches its consumer, and the M26 row appears at stage 4. Two S2 defects block
approval. The Calmer-mode checkbox and the Content-level dropdown write the same field but never
refresh each other, so the screen can show a safety control in a state the store does not have
(CODE-1). Closing the overlay never restores keyboard focus, so after a pause the player's typing goes
nowhere until they click or press Tab (CODE-2). The S3s are cleanup and robustness: unreachable scene
Esc handlers with one test asserting the dead path, a disk write per slider step, non-finite numbers
passing `clampf` (plus a wrong-typed flag aborting the load), option labels hard-coded in the node,
and one personal path in the handoff.
