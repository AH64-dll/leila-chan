## Findings

| ID | Sev | Where (file:line) | Problem | Suggested fix |
|---|---|---|---|---|
| CODE-1 | S3 | `tools/llm/serve.sh:37`, `tools/llm/fetch_llama.sh:21,51` | Both scripts run under `set -u` and reference `$OS`. On Linux `OS` is normally unset, so they abort before starting/fetching: `env -u OS bash tools/llm/serve.sh` → `OS: unbound variable`, exit 1; same for `fetch_llama.sh`. Git Bash sets `OS=Windows_NT`, which is why the handoff's Windows run passed. The README and handoff explicitly claim Linux support. | Use `case "${OS:-}" in`, `[ "${OS:-}" = "Windows_NT" ]`, or branch on `$OSTYPE` / `uname -s`. |
| CODE-2 | S3 | `tools/llm/serve.sh`, `tools/llm/fetch_llama.sh` (index mode) | Both are tracked as `100644`, but `tools/llm/README.md`'s bash examples invoke them directly (`tools/llm/serve.sh`, `tools/llm/fetch_llama.sh`). On a Linux checkout that is `Permission denied`; Git for Windows ignores the mode, which is why `./tools/llm/serve.sh --help` works here. Same class as the P0.13 `tools/godot.sh` carry-over. | `git update-index --chmod=+x tools/llm/serve.sh tools/llm/fetch_llama.sh` and commit the mode change. |
| CODE-3 | S4 | `tools/llm/smoke.py:47-52` | `TURN VALID` only proves the eight top-level keys exist. A key-complete object with a wrong enum (`read`/`music`/`fx`/`action`), wrong beat count, missing nested beat field or out-of-range `mood` would still print `TURN VALID` and exit 0. The server's grammar makes this unlikely, but the smoke does not itself prove schema conformance, and it prints `TURN VALID` before touching `beats`/`mood` (a malformed nested value would traceback after the success line). | Validate with `jsonschema.validate(turn, schema(opt.stage))` (or check enums, beat count and mood ranges) before printing `TURN VALID`; print the full object on failure. |
| CODE-4 | S4 | `tools/llm/serve.ps1:50` | The banner prints `llama-server b12024` unconditionally, even when `-Bin` points at another build — exactly the Vulkan/CPU fallback path in the P0 risk table. The banner would misstate the running build. | Print `$Exe` (already printed) and run `& $Exe --version` once, or drop the hard-coded build name. |
