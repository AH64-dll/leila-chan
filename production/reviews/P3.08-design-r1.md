## Observed behaviour (I ran it, not only read it)

I drove the real `Director` turn path headless with the scripted backend and the test-double safety filter
(`./tools/godot.sh --headless --path game -s /tmp/p308_prompt_probe4.gd` / `…probe5.gd` / `…probe6.gd`;
each script calls `GameState.set_meter`/`stage`, `MetaDirector.load_catalog()` + `set_seed_base(7)` +
`reset_session()`, then `Director.submit_player_input` and prints the turn's `_current_prompt`,
`_current_schema` and `GameState.pending_events`).

**Turn 1, stage 4** — two offers, enum correct, reason missing:

```
PROBE submit=true stage=4 turn=0
PROBE last_offered_actions=["she_closes_game", "rename_window"]
PROBE enum=["none", "she_closes_game", "rename_window"]
PROBE offer_lines_in_prompt=["Offered this turn — music: keep, … action: none, she_closes_game, rename_window."]
PROBE pending_events=["OPPORTUNITY (optional): She is deciding whether to end the date herself. …",
                      "OPPORTUNITY (optional): She wants to leave a mark on the screen itself. …"]
```

**Turn 2** — the reasons arrive, but for the offers that just expired, while the enum offers something else:

```
PROBE turn2_offers=["hide_ui", "fake_crash"]
PROBE turn2_enum=["none", "hide_ui", "fake_crash"]
PROBE turn2_prompt=["OPPORTUNITY (optional): She is deciding whether to end the date hersel…",
                    "OPPORTUNITY (optional): She wants to leave a mark on the screen itself…",
                    "Offered this turn — …, action: none, hide_ui, fake_crash."]
```

**"Never two in a row"** — one event at turn index 0, then three submits:

```
PROBE turn_index_before=0 submit=true offers=["she_closes_game", "rename_window"] last_event_turn=-1
PROBE turn_index_before=1 submit=true offers=[]                                  last_event_turn=1
PROBE turn_index_before=2 submit=true offers=[]                                  last_event_turn=1
PROBE turn_index_before=3 submit=true offers=["write_note", "fake_crash"]        last_event_turn=1
```

The author's unit test sees one quiet turn because it stamps `_last_event_turn` at the pre-turn index; the
Director calls `execute_after_text` **after** `apply_turn_meters()` advanced `turn` (`Director.gd:749`,
`:768`; `GameState.gd:384`).

## Pillars (docs/01 §0)

1. **She is not scripted** — the catalogue only supplies the frame/fallback lines; the model chooses whether and how. Fine.
2. **The game owns the truth, the model owns the voice** — the scheduler, caps and gates are game code; the model's only input is one enum value. Fine.
3. **Three engines of dread** — the scheduler is a spike source, untouched otherwise; DES-2 hurts its pacing.
4. **Her sickness is physical** — no change.
5. **Fourth wall as a scalpel** — rare/gated/offered/capped. The mechanism is undermined while the reason line is missing (DES-1) and while an event can be taken without its why; otherwise the shape is right.

## Summary

The scheduler's shape is faithful — 0–2 offers, `["none"]` otherwise, one-turn offers, per-event cap kinds,
data-driven caps/weights/notes — and the M01 seam still closes on the second press. But the contract that
makes the whole mechanism work, docs/02 §2.4's "tell the model why, this turn", is off by one: the reason
always arrives on the next turn, with the wrong enum, and is lost entirely when the offer is taken. Three
further doc numbers are wrong without a DCR: "never two in a row" is really two quiet turns, M22's
path weight contradicts docs/05 §3, and M31's documented St 2 gate is unreachable. The scene cap is not re-checked at execution. DES-1 (S2) alone blocks the
merge.
