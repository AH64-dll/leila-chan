### DES-1 — how the duplicate was removed

`submit_player_input()` still appends this turn's line to `Director.history` (`Director.gd:285`); that
is deliberate (the next window needs it, and an unanswered line stays said). The step-1 snapshot now
sends the array through `_prior_history(history, player_text)` (`TurnContext.gd:99`, body
`:112-122`), which drops **one** trailing `user` entry when its stripped `text`/`content` equals this
turn's stripped line. `PromptBuilder._messages()` then appends `player_message` once
(`PromptBuilder.gd:458-469`), so the sent prompt is `[system, prior pairs…, this line]`.

Observed behaviour from my run — `DirectorTest.test_step_2_prompt_history_holds_prior_exchanges_only`
asserts on the request object the backend received (`FakeLLMBackend.seen_request`), not on a helper:

- turn 0: exactly 2 messages, `[system, line]`;
- turn 1: exactly 4 messages; `ctx["history"]` is 2 prior entries and none equals the new line; the new
  line appears once and no `user` message directly follows another.

The test discriminates: on the pre-fix code `PromptBuilder` appended the history array (which held the
just-appended current line) **and** `player_message`, so turn 0 would have had 3 messages and turn 1
would have ended in two `user` entries — both assertions fail. This is the invariant docs/08 §1 states
(`docs/08_PROMPTS_AND_CONTENT.md:18`).

Edge paths I checked by reading, not just the happy path:

- **retry** (`_start_turn(_current_player_input)`): the tail is still this line, so exactly one copy is
  dropped and no duplicate is introduced;
- **same line twice in a row**: only the trailing copy is dropped, so the earlier legitimate occurrence
  survives — the prompt is correct, not deduplicated beyond the boundary;
- **failed/cancelled turn**: its `user` line is never answered, so two player lines can legitimately be
  adjacent (data, not duplication);
- **`get_current_dose()`** passes `""` (`Director.gd:229`), and `_prior_history()` returns early for an
  empty line, so that debug path is unchanged;
- **consumers**: the only reader of `ctx["history"]` in `game/` is `PromptBuilder._window`
  (`PromptBuilder.gd:136`), whose contract (history = prior turns) is exactly what the snapshot now
  delivers. No other subsystem can regress from the change.

### DES-2 — what the auto-fill tests now prove

Positive case (`DirectorTest.gd:257-301`): `FakeFXHost` (`:18`) is installed with
`FX.register_host()`, then `AudioDirector.cue_played`/`cue_denied` and `FX.fx_triggered`/`fx_dropped`
are spied. The test awaits the threaded cue load (up to 4 s) and asserts `giggle` played,
`blush_glow` fired, the effect reached the host (`host.fired`), and only then that
`quiet_turn_streak == 0`.

Negative case (`:306-347`): streak 2 → one quiet turn → 3 with nothing played; stage 2 → streak zeroed
with nothing played. `FX.trigger` is inline, so a leaked fill cannot hide behind the threaded cue load,
and the streak assertions cannot pass if the streak or stage gate were removed. `FX.reset()` in
`before_test` (`:38`) stops the 3-turn cooldown from deciding a later case.

The code agrees with the test: `_handle_auto_fill` (`Director.gd:780-818`) gates on `stage > 1`,
`quiet_turn_streak < 4` and `max_intensity < 2`, keeps counting when nothing could be played, and sets
`filled` only from the two calls; `AudioDirector.play_engine_cue` (`AudioDirector.gd:204-218`) skips
the model's token bucket but still requires existing files; `FX.trigger` (`FX.gd:76-92`) emits
`fx_triggered` only after the host accepts. `blush_glow` is `gate: 0` and implemented, and `giggle`
resolves to files that exist under `game/assets/audio/vocal/`.
