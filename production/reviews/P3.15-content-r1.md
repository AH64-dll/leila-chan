### CON-2 — "Aya" is outside T01's vocabulary and is not in the design table (S3)

The stage-1 opening beat (`I08_rival_appears.json:62`) says *"That's Aya, isn't it? You've known her a while…"*.
Three problems meet here:

- docs/01 §6.2 describes I08 as *"A classmate is mentioned"* — no name;
- the handoff says *"no scenario file hard-codes a rival name"* (`production/handoffs/P3.15.md:239-240`), which this
  line contradicts;
- T01 is the trigger the same file binds (events[2], `on_trigger: "T01"`), and its keyword row
  (`game/data/triggers.json`, `T01.detect.keyword.any[0]`) has ~44 names — including `maya` and `yara` — but **not
  `aya`**. I compiled the row's regex and ran it over the committed player lines
  *"Aya said hi. We had a class together last year."* and *"Aya? She's my friend. Why is she on there?"*: both return
  `False`. The scene's own rival name therefore never reaches the keyword detector; only the model's
  `jealousy_bait` label can fire T01, at half strength (docs/02 §1.2).

Fixing the beat keeps P3.15 self-contained and matches the design table and the handoff. If the producer wants "Aya"
as canon instead, the other end is one word in the T01 name list.

```json
        "say": "That's the girl from your class, isn't it? You've known her a while — you don't have to answer."
```

  **0 violations**, 1–3 beats per turn (the schema's `maxItems` is 3). The tool's number is still "parsed", not
  "validated"; the gate check above is what makes the evidence schema-valid.
- **All 14 ends are turn caps.** The harness offers no action set (`get_allowed_actions(stage, [])` returns only
  `none`), so `end.on_goal: "end_date"` cannot fire in a playthrough; the end rule is covered by
  `game/tests/test_scenario_loader.gd:96-122` instead. The handoff reports this honestly in its `end` column.
- **`--fires` is one firing by construction.** The set-pieces bind T01/T06, which are `behavior: "repeatable"`
  (cooldowns 1/3) in `game/data/triggers.json`; the scenario schema has no once-only flag. Today only
  `game/tools/scenario_playthrough.gd` reads `on_trigger` lines, so nothing re-delivers them in-game; when a
  trigger→scene wiring lands, the set-piece's line would repeat inside its 3–6-turn window. Worth deciding then.
- **Music gate vs stage.** I05/I15 request `music_box`, which docs/04 §2 and `audio_rules.json` gate to stage ≥ 2, and
