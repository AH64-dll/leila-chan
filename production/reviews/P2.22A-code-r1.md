## Findings

### CODE-1 — the `_exit_tree` clear is claimed by the test docstring but never exercised (S3)

`DateFlowWiringTest.gd:198` says the case also proves that "a scene that simply leaves the tree" must not leave its goal behind, but the test body only calls `date._check_scenario_end()` (`:210`), which clears at `Date.gd:321`. `Date._exit_tree`'s own clear (`Date.gd:215`) is never reached with a non-empty `Director.scene_info`: the end check has already emptied it, and `after_test` frees the date afterwards. The production code is correct; the coverage claim is not. Suggested fix, appended to the same case after the end assertions:

```gdscript
	# A date that leaves the tree mid-date (no end rule) clears its layer too.
	date._apply_director_scene(1)
	assert_bool(Director.scene_info.is_empty()).is_false()
	date.queue_free()
	await get_tree().process_frame
	assert_bool(Director.scene_info.is_empty()).is_true()
```

(`after_test` already tolerates a freed `_date` via `is_instance_valid`.)

### CODE-2 — the P2.22 harness's `start_date()` is not inert; the handoff says it is (S3)

Open question 2 of the handoff claims the P2.22 driver's remaining copies are no-ops because "`start_date()` is called only when `auto_start` is false". `game/tools/full_run_driver.gd` on `task/P2.22` has no such guard: `_attach_date` calls `date.start_date()` **unconditionally** (`:323`) and never touches `auto_start`. With this Date, the driver's call and the deferred self-start queued by `_ready` both fire in the same frame: `date_started` twice, a second `SpriteResolver.reset_scene()` / `request_music` / `play_opening_beats` that resets the just-started greeting, a second scene-entry autosave, and `_current_turn` reset to `_saved_turn`. Deleting the two bridges plus the `scene_info` assignment — what the handoff currently asks for — does not remove this. (The duplicate `player_turn_sent` bridge is also not a pure no-op: it gets a refused submit and pushes a warning per turn, though the pump survives because it re-checks `Director.is_busy()`.) Suggested fix, carried into P2.22's brief: guard the call (`if not bool(date.get("auto_start")): date.start_date()`), or make `start_date()` idempotent — which in turn requires `DateSceneTest.test_capture_screenshots_for_handoff` (re-entry at `DateSceneTest.gd:274` and `:285`) to host two Dates instead of starting one twice.

`production/handoffs/P2.22A.md:57` has `cd "/run/media/<user>/New Volume/lila-wt/P2.22A"`, against the protocol's definition of done ("no … absolute personal paths … in the diff") and the `<main tree>/…` / worktree-relative convention the recent handoffs use (P2.23, P2.25 and P2.26 carry none; I checked).
