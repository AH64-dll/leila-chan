### CODE-7 detail

- **title:** Preserve the deferred save_gone note across the Director reset
- **file_path:** `game/autoload/Telemetry.gd`
- **line_start / line_end:** 320–325
- **priority:** 2
- **confidence:** 0.9

The chain is unambiguous and fully inside this patch's new code:

1. `SaveSystem.delete_slot` reads the ended run's stage and posts the note: `SaveSystem.gd:284-291` → `_note_save_gone` (`:175-180`) → `Telemetry.note_player_action` → `_run_ended = _build_event(...)` (`Telemetry.gd:499-502`). `wipe_everything` takes the same road (`SaveSystem.gd:168`).
2. The only way to reach a spoken turn afterwards is a Date scene, and both ways into one reset the session first: Continue → `SaveSystem.load_latest` → `load_from_slot` (`SaveSystem.gd:238-256`) → `_apply` → `Director.reset()` (`SaveSystem.gd:397-398`); New Game → `NewGame.confirm_name` → `director.call("reset")` (`game/scenes/NewGame.gd:122`).
3. `Director.reset()` → `InputHook.reset_session(get_node_or_null("/root/Telemetry"))` (`game/autoload/Director.gd:158`) → `telemetry.call("reset_session")` (`game/llm/InputHook.gd:77-81`) → `Telemetry.reset_session()` → **`_run_ended = {}`** (`Telemetry.gd:323`).
4. The first turn's `take_turn_events` (`Telemetry.gd:516`) then finds `_deliver_run_ended()` empty (`:653-654`) and T19 never fires: no line ("the only copy of the sentence" is this event, the row's `line` is ""), no instability +4, no AWAKE +2.

The new test that claims to pin this, `test_t19_deleted_slot_survives_the_title_to_date_transition` (`game/tests/TriggersT16T23Test.gd:162-181`), calls `Telemetry.reset_session()` **before** `delete_slot` (`:166-167`), then `set_date_active(true)` (which only `_clear_pending`) and `take_turn_events(3)` (`:174`) — with no `Director.reset()` between the delete and the drain. That is not the title→date transition the test's name describes, so the test cannot fail on the defect. The handoff (`production/handoffs/P3.07.md:354`) states the note survives "`reset_session`-time reset", which line 323 contradicts.

Impact: docs/01 §5 T19's "Delete save" half is silently never delivered in the only flow that can reach a turn. It is latent today only because no screen calls `delete_slot`/`wipe_everything` yet; the moment P3.13 wires the buttons, the row's delete half stays dead and its test stays green.

Fix: make `_run_ended` the documented exception to the session reset (it is the one event that is *about* the transition), then run the test change so the test would have failed before the fix.
