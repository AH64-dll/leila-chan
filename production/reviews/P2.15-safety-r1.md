### SAF-1 detail (the reason for the verdict)
- Reachability: `flicker` was `"unimplemented"` on main (main `FX.gd:25-27,60-62`); P2.15 adds it to `IMPLEMENTED` (`FX.gd:31-43`) and the host draws it (`Character.gd:762-776`), gate 3, cooldown 3 turns.
- Pattern: 4 dips (`0.32`, `0.28`, `0.35`, `0.30`) each returning to `1.0`, all within 0.63 s. Each pair is a full-screen luminance change of ~65–72 % of maximum with the darker level below 0.8 — both WCAG general-flash thresholds are met, over the whole 384×688 window (including the UI text, because the pass is CanvasLayer 3). That is **4 flashes in a one-second period**, not the 3 the playbook allows, and it is what the suite currently pins (`FXStageHostTest.gd:158-160`).
- The accommodation is correct but inert: default `false` in three places (`FX.gd:59`, `Settings.gd:4`, `Date.gd:29`); the only writers are `Date.set_photosensitive` (called by tests/tools only) and `FX.set_photosensitive`; no scene can set it (`game/scenes/` = Title, NewGame, Date, Boot); `Boot` has no warning. So this is not "the mode is missing" — it is "the mode cannot be reached", which is the same hazard for the player.
- The stage-5 stack does not mitigate it: `darken` and the stage drain are *multiplicative* (`stage_fx.gdshader:85`), so a dimmed screen keeps the same 68 % per-step contrast; "it's already dark" is not a defence.
- Combining `flicker` + `vignette_red` in one turn (both gate 3, independent cooldowns) adds 1.4 pulses/s on top → ~5 opposing pairs in the same window.

## Summary
The FX work is well built — the single-pass composition, the data-owned gate/cooldown table and the photosensitive dim are all correct and tested. It cannot be approved, because it ships the first player-reachable full-screen strobe: four flashes in 0.63 s at stage 3+, with the only safe mode defaulting off and the Settings screen that would expose it still a later task (P3.13), so every player is currently exposed to a WCAG 2.3.1 failure. Cap the normal pattern at ≤3 flashes per second (and fix the test that currently asserts the opposite), or default the safe mode on until the toggle ships; either is a small, doc-compliant change. The remaining findings are minor: the bleed band crosses the input row, one stale doc line contradicts docs/02 §2.3, and calmer mode's stage cap needs confirming.
