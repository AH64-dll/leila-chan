| DES-3 | S3 | `game/scenes/ui/TextBox.gd:103-110` (`end_turn`'s new idle branch) | On an idle turn — the CODE-1 case, i.e. `begin_turn_wait` → `end_turn` with no (or zero-length) say text — the branch calls `_writer._maybe_advance_beat()` first, which fires `drained` → `_on_writer_drained` → `all_displayed`, then the branch condition `not has_pending_beats …` fires `all_displayed` again synchronously. Baseline probe (same SceneTree script at `97be4dd`) observed 0 emissions for exactly this sequence; at `1a8dd71` it is 2 per `end_turn` call, and the call is also re-entered per frame afterwards while `_process` keeps polling the drained writer (pre-existing per-frame emission, unchanged from baseline). Today the only consumer, `ChatUI._on_all_displayed` → `_maybe_close_turn`, is idempotent (+ `_turn_open` latched), so no player-visible defect — this is an S3 contract-hygiene finding, not an S2: the signal's doc contract "Every streamed beat so far is on screen" is state, not a rate, and a once-per-state-change emission is the shape future consumers (e.g. a P1.16 编剧 beat-tally, a P3.13 settings hook) will reasonably assume. | Emit the idle branch only when the writer has not already reported completion this call — e.g. guard with the writer's pending state instead of re-deriving it:

```gdscript
	if _writer != null and not _writer.is_complete():
		_writer._maybe_advance_beat()
	var has_pending_beats := not _writer.is_complete()
	if not has_pending_beats:
		hide_typing_indicator()
		all_displayed.emit()
```

(credit for the fix belongs to the same commit's own `is_complete()` semantics — `_writer.is_complete()` is true exactly when every queued beat was drained, so the second synchronous emission falls away and the once-per-frame re-emission from `_process` stays as the (unchanged, baseline-present) tail.
