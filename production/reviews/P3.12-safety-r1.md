### SAF-1 fix

```gdscript
	# A trailing "/" stops DirAccess.remove_absolute() from removing a child
	# built from that path, so normalize it — but never strip the scheme:
	# "user://" must stay "user://", or DirAccess.open() cannot resolve it and
	# the wipe silently deletes nothing.
	var root := dir_path
	while root.ends_with("/") and not root.ends_with("://"):
		root = root.trim_suffix("/")
	var dir := DirAccess.open(root)
	if dir == null:
		return
```

## Observations (not findings)

- The file sits in a hidden directory (`user://.leila/`), which is M08's specified path. Hidden is not
  secret: any process running as the same OS user can read it, as with save slots. The privacy claim is
  "documented and player-visible JSON", not "encrypted", and the docs say so.
- `user_root` is a public seam: if a future task ever set it from player input, `wipe_everything` would
  recurse outside `user://`, which docs/05 §0 rule 1 forbids. It is test-only today (the sole writer is
  `ShadowSaveTest`), so I did not file it — worth a guard if it ever gains a setter from data.
- Memory facts are herself-generated summaries, not displayed raw; when P3.09 makes her *say* one, that
  `say` goes through `Safety` like every other line.

## Summary

The data design is privacy-sound: the file holds a validated name, the names list, a capped run list
and at most three fact texts, never logs, transcripts, drafts, the OS username or telemetry — and I
confirmed by probe that the raw player `source` attached to a memory is not copied. The blocker is the
deletion control: with the default `user://` root the recursive wipe opens `user:/`, deletes nothing and
still reports success, so "Reset Everything" — the one mechanism the docs, the docblock and the task
promise for erasing this personal data — leaves it on disk; the new test masks it by replacing the root.
SAF-2 (uncapped `_heal`) and SAF-3 (a wrong doc citation) are smaller, but the privacy promise is not
something to leave to interpretation, hence CHANGES_REQUESTED.
