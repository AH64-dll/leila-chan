## Notes (not findings)

- **Label arrays are matched to values by index.** `_cfg_labels` rejects a wrong-*length* table but not a
  same-length *reorder*; e.g. putting "Not set (safest)" at index 2 would make that row write `full`. The
  shipped `ui.json`/`UiConfig.DEFAULTS` arrays are currently correct and identical (verified), and the
  value arrays stay in code, so nothing is wrong today. If writers will own these arrays, storing
  `{label, value}` pairs would close the gap. Not a round-2 defect.
- **`save_settings` (`Settings.gd:363-383`) writes `content_level_before_calmer = full` also when
  `content_level` is already `full`** (the `else` branch of `set_content_level` sets the memory). The key
  is redundant in that state but harmless: the loader maps it back to the same memory.
- The round-2 run's `WARNING: Settings: refusing non-finite …` lines come from the new corruption test
  exercising the refusal path (the designed behaviour), not from production code.
- The dose row is refreshed only in `_refresh_settings_rows`; the tree is paused while the settings page
  is open, so the stage cannot change behind it.
