### CODE-1 detail

Sequence in the real Director, not in the test:

1. Player: "here, I got you a music box" → model reads `gift` and writes `memory: "The player gave me a music box"`.
2. `_close_turn_success` calls `GameState.apply_turn_meters` (`Director.gd:749`), then `Memory.consider(...)` (`:762`) — accepted by `MemoryRules.reject_reason` rule 1 because it shares "music"/"box" with `last_player_inputs` (`game/llm/MemoryRules.gd:311-330`).
3. `turn_completed.emit` (`:791`) → `Triggers.close_turn` → `_context(false)` injects `_memory_facts()` = the live store (`Triggers.gd:322-326`), so the new fact is in it.
4. `_guard_matches` → `_memory_mention` → `MemoryRules.shared_fact` finds 2 shared words → T22 fires on the **first** gift.

`test_t22_repeated_gift_needs_the_memory` stores the fact *before* `begin_turn`, so it never exercises step 2→3 and cannot catch this. The snapshot fix also closes the same exposure for T13, which today could quote a fact the model invented about the same message.

### CODE-2 detail

`SaveSystem.begin_new_game` is the only reachable T19 trigger in this build (`delete_slot` has no UI caller; `wipe_everything` is reached from the not-yet-built settings screen). Its call order in `game/scenes/NewGame.gd:94-120` is: `begin_new_game` — records `save_gone`, Telemetry's `_record` hands it to `Triggers.handle_engine_event`, T19 fires at the old stage and its meters/path points land — then `GameState.reset()` (clears `pending_events`), then `Director.reset()` (clears Telemetry's pending queue and the trigger state). The row itself has `"line": ""` (`triggers.json:456`), so the only copy of the sentence is Telemetry's `_pending["save_gone"]`, which both resets drop. Net effect: the T19 count, the AWAKE +2 and the line are all discarded; the handoff's follow-up for P3.09 ("M08 … can now say the previous save is gone") is not true.
