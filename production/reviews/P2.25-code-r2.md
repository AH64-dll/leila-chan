## Findings

### CODE-6 — S2 — `tools/merge_check.py:289-294`

`pre_merge` now records `both-deleted` and `continue`s before the simulated merge's conflict evidence is used, and `report.conflicted` (`:284`) never reaches the verdict (`:341-350`: no status the both-deleted path can carry is in either condition). Because the changed-path listing disables rename detection (`:136`), a rename is just a deletion of the old path, so both rename shapes end up with no blob at the same path on either side and are reported as a merge that "loses nothing".

Impact: the documented meaning of exit 0 is "clean" (`production/MERGE_CHECK.md:57`), so a producer who follows the three-command habit gets `VERDICT: PASS` from the pre gate for a merge that git refuses, while the same report's header already says `3 conflicted path(s)` and no finding names the paths that must be reconciled. The printed sentence "both sides deleted this path; the merge deletes it too and loses nothing" is factually wrong for these shapes (the renamed copy has to survive, and in the rename/delete case taking the deletion drops the rename's added content), and `production/MERGE_CHECK.md:31` repeats the same generalisation. No test covers a both-deleted path that still conflicts.

Suggested fix (`tools/merge_check.py:343`, one line — a conflict the tool itself counted must not pass):

```python
    if any(f.status in ("delete-vs-edit", "auto-merge-drops", "auto-merge-deletes") for f in report.findings):
        report.verdict = "FAIL"
    elif report.conflicted or any(
        f.status in ("conflict", "non-blob", "binary")
        or f.lost_if_branch_taken
        or f.lost_if_target_kept
        for f in report.findings
    ):
        report.verdict = "REVIEW"
```

I validated the candidate on a copy in `tmp` (project files untouched): rename/rename and rename/delete both become `VERDICT: REVIEW`, exit 1; the pure delete/delete repository (`conflicted` is empty) still passes with exit 0; `--target main task/P2.25` still passes; the incident pre-check output is unchanged; and all 20 tests pass against the patched copy (`20 passed in 2.62s`). Add one case to `tests/test_merge_check.py` for the rename/delete shape, since `test_pre_passes_when_both_sides_delete_the_same_file` asserts only the clean one.
