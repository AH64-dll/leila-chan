### CODE-1 — `consider()` can evict the fact it just accepted (S2)

`consider()` appends the newcomer at `MemoryRules.new_importance()` (1.0) and *then* asks `eviction_index()` for the lowest-importance entry. Importance never decays, so after every stored fact has been quoted once (each `note_quotes()` turn adds +1) all 24 slots sit at ≥ 2.0 while the newcomer is 1.0 — strictly the lowest — and the victim is index 24, the fact just accepted. I reproduced it on a 24 × 2.0 store with a grounded candidate:

```text
accepted=true  evicted=has a sister called Yuki  size=24  stored_new=false  unchanged=true
```

The returned decision is `accepted: true`, `evicted: <the candidate text>`, so neither the Director nor the transcript can tell that she did not learn the fact. After that point the store is frozen for the rest of the run: every later grounded fact is appended and deleted in the same call, which voids docs/01's "she remembers facts you tell her" and is a regression — the pre-P2.11 code always kept the new fact and dropped the oldest (`memories.append(...); if size > 24: memories.pop_front()`).

The covering test does not reach this: `test_store_holds_24_slots_and_evicts_the_oldest_low_importance` (`:273`) keeps 23 slots at 1.0, so the newcomer never holds the minimum.

```gdscript
	var evicted := ""
	if entries.size() > capacity:
		# The newcomer is never its own victim: it is the newest, not the oldest.
		var victim := MemoryRules.eviction_index(entries.slice(0, entries.size() - 1))
		evicted = String(entries[victim][ENTRY_TEXT])
		entries.remove_at(victim)
```

### CODE-2 — the promise mutation is skipped for a whole class of facts (S2)

`corrupt()` tries the three kinds from a seeded offset and returns `{}` when none applies. Two kinds need a capitalised token (`name_swap`) or a number (`number_off_by_one`); the third is refused by `_append_promise()` whenever `fact + " — " + promise` is longer than `max_length`. That leaves every fact of 49–80 characters with no capitalised word and no number permanently corruption-proof:

```text
probe fact (61 chars) "she told me she used to live near the harbour with her sister"
  200 seeds -> {} (no mutation)
48-char control fact -> false_promise ; 49-char control fact -> {}
```

Selection is silent: `prompt_facts()` logs nothing and the roll is simply spent, so per-injection corruption for that class is 0 %, not 10–25 %. The schema limit being guarded (`TurnSchema.MEMORY_MAX_LENGTH`) applies to the model's own `memory` proposal; the corrupted string only ever lands in a prompt bullet, which has no such cap and whose budget is a soft `over_budget` report (`PromptBuilder._over_budget`, `game/autoload/PromptBuilder.gd:582-596`) — nothing breaks if the promise is appended. `test_corruption_chance_matches_the_documented_band` cannot see this because its filler facts are 16 chars.

```gdscript
	var budget := int(_table()["max_length"])
	if fact.length() + 3 + promise.length() <= budget:
		return "%s — %s" % [fact, promise]
	# Never skip the mutation: the limit guards the proposal field, not the
	# prompt bullet, so shorten the fact and keep the doc's promise phrase.
	var room := budget - 3 - promise.length()
	if room <= 0:
		return ""
	return "%s — %s" % [fact.substr(0, room).strip_edges(), promise]
```

### CODE-3 — the transcript's `memory` block is not this turn's (S3)

`prompt_facts()` clears only `last_corruptions`; `note_quotes()` clears only `last_quotes` and only when it runs; nothing clears `last_proposal`. `_log_turn_record()` is shared by four paths, and three of them never reach `_close_turn_success`:

- `_reject_unsafe_input()` (`:313`) builds no prompt, so `corruptions`, `quotes` and `proposal` all belong to the previous turn;
- `_on_llm_failed` (`:835`) and `_on_llm_cancelled` (`:842`) build a prompt but never quote or propose, so their `quotes`/`proposal` are the previous turn's;
- a normal completed turn whose model emitted `"memory": ""` (legal — the schema has no `minLength`) skips `consider()`, so `memory.proposal` shows an older decision.

`report()` is documented as "this turn's corruptions and this turn's quotes" (`game/autoload/Memory.gd:48-49`) and the handoff advertises `memory.proposal` as the audit of "why she just refused to remember"; for the `""` case (the common one) the field instead reports whatever happened last. The corruption half is sound because the prompt build clears it first.

```gdscript
## Start a turn's record: nothing from the previous turn leaks into it.
func begin_turn() -> void:
	last_corruptions.clear()
	last_quotes.clear()
	last_proposal = {}
```

Call it at the top of `Director._start_turn()` and at the top of `Director._reject_unsafe_input()` (before `_log_turn_record`), and route `Memory`'s facade to it.

### CODE-4 — an untrusted `capacity` defeats the slot invariant (S3)

`from_dict()` adopts `capacity` from the save (`maxi(1, int(data.get("capacity", …)))`) with no upper bound, then trims only to that number. Probed: `from_dict({"capacity": 500, "entries": [24 rows]})` yields `capacity == 500`, and 30 rows survive. docs/02 §6 fixes the store at 24 slots and the function's own contract is "anything malformed is dropped rather than trusted", so a hand-edited or half-written save (P2.20's input) can silently widen the store; the accompanying test asserts the 24-slot invariant only because its fixture omits `capacity`.

```gdscript
	capacity = clampi(
		int(data.get("capacity", MemoryRules.capacity())), 1, MemoryRules.capacity()
	)
```
