| CODE-1 | S3 | `game/llm/Endings.gd:261-265` | `force()` stamps `FLAG_ENDING` and clears `FLAG_RECORDED` *before* it computes `reached`. If `GameState.from_dict` does not keep everything `satisfying_state` wrote (the realistic case is a counter name `from_dict` drops because it is not in `PROFILE_COUNTERS`/`Paths`, the same class of typo as CODE-2), the live evaluator picks another id, `reached` is false, and the function returns `ok: false` — but the run's `ending_id` now names the row the evaluator did **not** choose. The overlay prints "Force … failed" while the run was silently stamped; the ending screen trusts that flag over a fresh evaluation (`Ending.gd:156-169`), so the next ending shows the phantom row. | Compute the verdict first and only mutate on success: `var reached := String(decision.get("id", "")) == String(row.get("id", ""))`; `if not reached: return {"ok": false, "error": "unsatisfiable", "ending": decision}`; then `GameState.set_flag(FLAG_ENDING, …)`, `GameState.clear_flag(FLAG_RECORDED)`, `return {"ok": true, "error": "", "ending": decision}`. |
| CODE-2 | S3 | `game/llm/Endings.gd:377-385` (`_bounds_problem`), `:510-518` (`_counters_hold`), `:502-508` (`_meters_hold`), `:597-605` (`_apply_meters`) | The load validator checks the *shape* of `meters`/`counters` but not the names. A typo'd meter is read as 0 (`_num(state.get(name))`), and a typo'd counter is read as 0 (`profile.get(name, 0)`), so a `max` clause on a misspelled name always holds — e.g. `"counters": {"broken_promises_typo": {"max": 0}}` makes the row match every run. That is exactly the "a typo must never make an ending easier to reach" invariant the class header claims (`Endings.gd:7-11`). `_apply_meters` already skips names not in `METER_RANGES`, proving the name check is understood; it is missing from the load path. The shipped data is fine and the Python pin checks only the outer keys (`tests/test_endings.py::test_every_condition_uses_the_vocabulary`). | Reject unknown names in `_bounds_problem`: for `meters`, require `GameState.METER_RANGES.has(StringName(key))`; for `counters`, require `GameState.PROFILE_COUNTERS.has(StringName(key)) or Paths.is_counter(StringName(key))`; return a problem string so the row drops like any other invalid clause. |
| CODE-3 | S3 | `game/scenes/Night.gd:345-349` (cause: `game/llm/NightLoop.gd:66-70`) | `_note_ending()` evaluates the `any_time` question after `NightLoop.resolve()` has already advanced the day and applied the +3 burn, so the state it sees is the *new* day. Consequence: a run that closes day 6 at Instability 98 gets day 7 and 100 from the burn, and E14's `day_max: 6` fails — "Instability 100 before Day 7" can never fire on the 6→7 boundary.
