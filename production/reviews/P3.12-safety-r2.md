| SAF-4 | S3 | `game/tests/ShadowSaveTest.gd:193-216` (`test_reset_wipes_under_the_shipped_default_root`); same issue as CODE-3 in the code report | The test wipes whatever `user://` resolves to, keeping only the files it saw at snapshot time. Anything another process writes between the snapshot and the wipe is deleted — including a running game's `user://.leila/shadow.json`, letters, diary and autosave, and another worktree's test fixture. Every worktree of this project resolves `user://` to the same `~/.local/share/godot/app_userdata/Leila-chan`, and that live tree currently holds other tasks' fixtures from the same hour. A safety review cares because the destroyed files are exactly the personal data this task exists to protect, and neither the player nor the agent asked for that wipe. | Make the live-root wipe opt-in (one guard, same fix as CODE-3), or drop it: the shipped value stays pinned by `test_wipe_root_preserves_the_shipped_scheme` (`:178`), which reproduces the old `user:/` failure without touching live data. |

Evidence: a separate process wrote `user://other_suite/f_N.json` every ~2.5 ms while the suite ran against
the same scratch user dir; afterwards the surviving indices were 1..11995 except `3711-3714` — exactly the
files that existed at the instant `wipe_everything` ran, and nothing written after it.

```gdscript
func test_reset_wipes_under_the_shipped_default_root() -> void:
	# Wipes the live user:// tree. Every worktree of this project shares
	# ~/.local/share/godot/app_userdata/Leila-chan, so this is opt-in only: a
	# concurrent suite or a running game would lose what it writes here.
	if OS.get_environment("LEILA_WIPE_LIVE_USER_DIR") != "1":
		return
	SaveSystem.user_root = SaveSystem.DEFAULT_USER_ROOT
```
