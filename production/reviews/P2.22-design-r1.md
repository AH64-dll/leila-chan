## Findings

### DES-1 (S2) — S4-1 is filed at the wrong severity and with arithmetic that the artifact does not support

**Location:** `production/playtests/P2/full_run_report.md:217-228` (S4-1), `:152` (the 97-instead-of-45
summary), `production/handoffs/P2.22.md:142-145` and `:180-181`, `production/playtests/P2/runs/awake.md:1403-1409`.

**What is right:** the code trace and the live proof are real. `TriggerEngine._fire` calls
`TriggerEffects.add_path(_path_scores, effects)` (`TriggerEngine.gd:404`), `TriggerEffects.add_path`
keeps a private ledger (`TriggerEffects.gd:70-76`), and `Triggers.path_scores()` returns it
(`Triggers.gd:168-170`); `GameState._evaluate_path()` calls
`Paths.select(Paths.scores(profile, meters), path_evidence)` (`GameState.gd:566-573`) and never reads
the ledger. No production caller of `Triggers.path_scores()` exists. That is a real missing fold, and
the AWAKE run shows the consequence.

**What is wrong:** the numbers treat the authored trigger points as if agreement scaling did not
exist. `game/data/triggers.json` has `strength.model = 0.5`, and `TriggerEffects.scale` rounds a model-
only firing (`TriggerEffects.gd:33-50`); the sidecar's own effect dictionaries show the scaled values
(T05 model-only = 2, keyword = 4). The eight T05 firings before the lock are 3 keyword ×4 + 5 model
×2 = 22, plus T06 6 = **28**, not 4×8+6 = 38. The folded lock is therefore **67**, not 77. By the
final night the AWAKE ledger is 9 T05 (3×4 + 6×2 = 24) + T06 6 + T07 10 = **40**, so the folded AWAKE
score is **85**, not 97; the other 3 points in the 43-point total belong to TSUN (2) and SPLIT (1) from
T14 and cannot be added to AWAKE. The stage-2 crossing already had 14–16 trigger points, so with the
fold the crossing would read AWAKE 29–31 vs ANCHOR 15 — AWAKE would win outright instead of the 15/15
tie the report describes. The "first live exercise of the tie-break" is therefore an artefact of the
missing fold, not a validation of the intended soft rule.

**Severity and what it breaks:** this is S2 by the playbook (a docs/01 §5 formula/effect number that
never reaches the game without a DCR), not a nit. It removes every trigger row's `effects.path`
contribution from `path_scores` and from the live scores that the prompt runner-up and the overlay
read; it makes the AWAKE trigger budget (T05/T06/T07) inert; it lets the model's `read` label alone
decide an AWAKE soft assignment; and it will distort P3.19's path-separation metric and P3.20's
"≥4/6 land on the intended path" gate for any path whose intended play style is expressed through a
trigger. The final AWAKE label in this one run happens to remain AWAKE, so the artifact's final `path`
is not wrong; the decision and the score are.

**Suggested correction (report and handoff):**

```text
S4-1 · Trigger path points never reach the path score (S2, not S4)
At the stage-3 lock AWAKE is 39 = 3 × 13 meta_curiosity while the trigger ledger already holds 28
points (3 keyword T05 ×4 + 5 model-only T05 ×2 + T06 6); folded, the lock is 67. By the final night
the AWAKE ledger is 40 (9 T05 = 24, T06 = 6, T07 = 10), so the night is 85, not 45. The stage-2
crossing held 14–16 points before the turn's profile bump, so a fold would have made AWAKE the
outright winner at the crossing instead of the 15/15 tie. The authored AWAKE trigger budget is inert
and the soft assignment is decided by the model's read label alone.
Proposed task: SYS, S — fold Triggers.path_scores() into GameState._evaluate_path() (and therefore
the night re-score) with an integration test where T05/T06/T07 alone win AWAKE.
```
