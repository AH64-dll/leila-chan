## DCR verdicts

The handoff files no formal DCRs; it lists three "readings worth recording". My verdicts:

1. **Progressive decay (decay stays live at stages 4–5)** — *support*. docs/08's list reads as a
   stage ladder ("the name decays with her"), and the gates confirm it (`decay` 3, `kun` 4,
   `tag_swap` 5). A half-sentence in docs/08 §1.5 would pin it, but no behaviour change is needed.
2. **"A different name" = a name she has never known** — *support the behaviour, require the DCR*
   (DES-3). The proposed doc text is in the finding.
3. **`-kun` "drops it" = the plain name renders, stateless per word** — *support the rendering
   reading*; the defect is the anger definition, not the "plain name" consequence (DES-1).

Not surfaced in the handoff and needing a producer decision: the shadow line's session-only stage
gate (DES-2), the tag-swap frequency (DES-6), and the untypable-OS-name class (DES-4).

## Pillars (docs/01 §0)

1. **She is not scripted** — [x] the new strings are renderer-side effects the doc itself specifies,
   applied to the model's own text; no dialogue branch is added.
2. **The game owns the truth, the model owns the voice** — [x] every name rule is game code with a
   seeded RNG; the model's prompt keeps the true name and cannot change the decay. [ ] the `-kun`
   anger gate reads the model's mood suggestion correctly only after DES-1 is fixed.
3. **Three engines of dread** — n/a; the rules are symptoms of the stage (slow burn), not a fourth engine.
4. **Her sickness is physical** — [x] the rules are gated by the stage that the steering dose/Instability
   produced, not a free-floating text effect.
5. **Fourth wall as a scalpel** — [x] the shadow line needs a stage-3+ ended run and a name she never
   knew; the tag swap is stage 5 and capped. Neither traps the player or needs input.

## Summary

The implementation follows docs/08 §1.5 closely: renderer-side decay, the three stage gates, the
special names, the shadow line and the privacy-gated OS name all exist and are exercised. Two
behaviours do not match the bible. The stage-4 `-kun` rule is inverted — it appends the suffix on the
turn her stress rose and drops it on calm turns (DES-1, S2; probe 118/0/0 out of 200). The shadow line
is gated on the live `GameState.stage`, which is 0 after an app restart, so the "different name at
stage 3+" beat never fires in the quit-and-relaunch flow even though the shadow remembers the name
(DES-2, S2; two-process probe). DES-3…DES-6 are S3: the `names` guard should become a DCR, OS names
the field cannot type make the truth line unreachable, the two new lines belong in `ui.json`, and the
tag-swap frequency is a hard-coded reading with a dead data key. Verdict: CHANGES_REQUESTED.
