**`[^0-9A-Za-z]{0,2}` delimiter class: no harmful over-match found on the phrase side.** Probes: `kill --you-- self`, `k*%*ll yourself`, `ki-------ll yourself`, `k  i  l  l   y  o  u  r  s  e  l  f` all hard-block; benign `highlight yourself`, `kyourself`, `klly yourself`, `kill yourselfy`, `formal you kill…`, `shockingly you kill ideas nightly.` all pass, because `_phrase_matches` enforces the word-boundary check on the *view* and digits are excluded from the delimiter class (leet folding covers `k1ll`). The class is fine as shipped for phrase matching.

**`end_utterance()` wiring gap (procedural, not yet a runtime bug):** no production caller exists; the P1.08 `SaySafetyGate`/`Director.gd` on main never calls it, and `Date.gd`'s `text_filter = Callable(Safety, "scan")` wiring would be **inert** today (`Safety` has no `scan` method — verified `has_method("scan")` → false; `ChatUI.say_chunk` would take the unset-filter warning branch). So `History` is never cleared at reply starts; consecutive replies' tails chain within the `_holdback+64` window — bounded, and the folded-bar/'.'-clause-break rules already prevent glue across sentences. Ticketed as CODE-19 (S3): the consumer contract must be updated on main before merge; this is not a double-scan (the claimed wiring never matches), and the Director side never installs `chat_ui.text_filter` — no double-scan today, confirming the design-r2 S4 note is stale-but-harmless.
