## Findings
| ID | Sev | Where (file:line) | Problem | Suggested fix |
|---|---|---|---|---|
| CODE-1 | S3 | `game/llm/IncrementalJson.gd:101` and `:424` | When a syntax error occurs inside an open `say` string and the error arrives in the same `feed()` chunk, `_fail()` appends the `error` event during the loop, then `_flush_say(out)` at `:101` appends the buffered partial `say_chunk` after it. With the same error split into a later chunk the partial text arrives first. The order therefore depends on transport chunking and contradicts the class docstring's "events ... in stream (schema) order" (`:7`); docs/02 §7's broken-JSON fallback wants the partial `say`, so a consumer that treats `error` as terminal can lose it. | Flush pending say before appending the error (call `_flush_say(out)` at the top of `_fail`, or flush before returning when `_s == ERR`), and add a test asserting a broken stream's partial `say_chunk` precedes the `error` event. |
| CODE-2 | S3 | `game/tests/IncrementalJsonTest.gd:39-40`; parser `:339-342` | The test oracle emits a zero-length `say_chunk` for `"say":""`; the parser emits none (only `beat_field(i,"say","")`). The corpus has no empty-say beat (105 recorded beats, min say length 18), so this is untested even though docs/02 §7 explicitly treats empty `say` as a real fallback case. A future recorded fixture with an empty `say` would make the whole/split equality tests fail falsely. | Align `_expected_events` with the documented convention (skip empty say chunks) and add an explicit empty-say case asserting `beat_field(i,"say","")`, no `say_chunk`, and the correct `get_value()`; or emit a zero-length chunk if that is the intended contract, and test that. |
| CODE-3 | S4 | `game/tests/IncrementalJsonTest.gd:392-409` | `test_corrupted_recorded_streams_error` accepts `p.has_error() or p.finish() != OK`, so a TRUNCATED result passes despite the comment "every one must error". All four mutants currently do set ERROR (offsets 7/270/153/21), so the looseness is latent. | Assert `p.has_error()` and `p.finish() == IJ.Status.ERROR` for each mutant. |
| CODE-4 | S4 | `game/tests/IncrementalJsonTest.gd:233-234`, `:260-261` | `test_event_order_contract` initialises `music_i` and `fx_i` to `-1` and only asserts they are less than `first_say[i]`; a parser that dropped both field events would still pass this test (the equality tests catch it elsewhere). | Assert `music_i >= 0` and `fx_i >= 0` before the ordering comparisons. |
| CODE-5 | S4 | `production/handoffs/P1.03.md:18` | The criterion-1 evidence says "6 recorded + 2 synthetic fixtures carry `\"`/`\\`/`\n` escapes". The manifest has 6 fixtures with escapes total: 4 recorded (`turn_028`, `turn_061`, `turn_070`, `turn_072`) and 2 synthetic (`synth_escapes`, `synth_mixed`). Coverage is real; the count is overstated. | Correct to "4 recorded + 2 synthetic". |
