### CODE-1 — T04 accuses a player who did confess

`game/data/triggers.json:103-106` writes `flags.love_confessed` only from the T03 row, and T03's guard is `day_lte: 2` (`:94-96`). T04 then fires whenever `day >= 10` **and** `flag_absent: love_confessed` (`:110-126`). A confession on Day 3–9 therefore sets nothing, and Day 10 fires "The player has never said they love you" plus SPLIT +5 — the probe above shows the flag still false after a Day 5 and a Day 6 confession, and the Day 10 event firing. The shipped test cannot see it because its last block forces the flag with `GameState.set_flag(&"love_confessed", true)` (`game/tests/TriggersT01T08Test.gd:90-94`) instead of making the player confess on Day 5+.

This is not a tuning number: docs/01 §5's trigger text is "Never say 'I love you' by Day 10", so the condition itself is wrong, and the false line is fed to the model as fact (Pillar 2: the game owns the truth). Fix: give the confession its own guard-free write — e.g. a marker row for T03's keyword patterns with `behavior: once`, `line: ""` and only `effects.flags.love_confessed` (keep the T03 row's `day_lte: 2` guard for the affection/instability reaction), or add a `flag_on_match` guard field — and assert the Day 5 confession stands T04 down, with no hand-set flag.

### CODE-2 — "I see you" is a goodbye

`game/data/triggers.json:67`'s `\bsee you\b` matches any occurrence of the two words, including the most natural thing a player says on a date ("I see you"). The probe shows the full reaction: the "player said goodbye" line, SPLIT +4, YANDERE +2. "See you later/soon/tomorrow" is the farewell the doc means, so narrowing the pattern to those continuations (or to end-of-sentence) keeps the trigger and drops the false positive. Add "I see you, Leila." as a negative case next to the existing `test_t02_goodbye_begs_you_to_stay`.

### CODE-3 — T13 calls an ordinary disagreement a lie

`MemoryRules.contradiction` (`game/llm/MemoryRules.gd:619-644`) returns the first stored fact that shares **one** content word with a message that contains **any** cue in the row's list (`game/data/triggers.json:309-326`, floor `1` at `:327`). The cue list includes `don't`, `do not`, `didn't`, `wasn't` — the negations of ordinary speech. "I don't like that music." against the memory "I like music" therefore fires (probe: trust −10, the line quoting "I like music" as something the player "said … word for word"). The row's consequence is heavy and it also writes a false statement into the prompt, so a plain disagreement is turned into evidence of a broken promise. A two-word floor plus denial-of-statement cues (`never said`, `i didn't say`, `that's a lie`, `you're wrong`) would keep the documented case (denying a stored fact) and lose the false one; the negative case belongs in `TriggersT09T15Test.test_t13_needs_a_denial_and_a_shared_fact`, which currently only covers "no shared fact" and "no denial".

### CODE-4 — a common word in T01's name list

`game/data/triggers.json:29` is a bare alternation of 40 names, one of which (`grace`) is an everyday noun; the probe fires T01 on a sentence that mentions no girl. Removing the homographs (or requiring a capitalised/possessive context) is a one-line data fix. The rest of the list is fine for round 1.

### CODE-5 — dead guard vocabulary

`game/llm/TriggerEngine.gd:52-65` declares `GUARD_KEYS` and `GUARD_CLOCK_KEYS`; `grep -n "GUARD_KEYS\|GUARD_CLOCK_KEYS" game/` finds only the declarations, and `_parse_guard` (`:831-857`) never consults them. Deleting them recovers the headroom the handoff itself says the class needs (`TriggerEngine.gd` is 999 lines against gdlint's 1000).

### CODE-6 — the data-driven gate is untested

The claim "`TriggerEngine.stage_min_of("T10")` is the single gate (data)" is the reason `MetaDirector` has no second copy of `3`, but no test reads it: `grep -n stage_min_of game/tests tests` is empty. `test_close_below_the_gate_closes_on_the_first_press` only exercises the shipped value. A catalogue with T10's `stage_min` moved (and a `close_gate()` + `-1`/fallback assertion) would make the seam load-bearing.

### CODE-7 — the Telemetry comment now states the opposite

`game/autoload/Telemetry.gd:384-389`: "Recorded only — auto_accept_quit is never touched, so closing still works in one press (docs/05 §0)." After this patch `auto_accept_quit` is false and the first press at stage ≥ 3 is held, so a future change reading this comment would reintroduce a bypass or an over-trust. The handler itself is still observation-only, which is the part worth keeping.

### CODE-8 — handoff inaccuracy

The Files changed line overstates the data: T10 ships `"effects": {}` on purpose (the intercept is the effect) and the E rows ship no `line`. Both are correct in the code; only the sentence is wrong.
