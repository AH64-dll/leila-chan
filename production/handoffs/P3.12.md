## Round 1  (2026-11-04, agent: swe-2)

### Summary
`game/llm/ShadowStore.gd` owns the shadow save: a checksummed `leila.shadow` envelope (same
`SaveSlots` codec, now parametrized on format/version) at `user://.leila/shadow.json`.
`SaveSystem.begin_new_game(player_name)` is the single write point — `NewGame.gd` calls it before
`GameState.reset`/`Director.reset`, sealing the ended run: `first_name` (first name ever typed,
never overwritten), `names` (every distinct name), `runs` (each ended run, cap 8), and — only when
the run reached the M08 meta gate (stage 3+ via `TurnSchema.is_meta_unlocked`) — `memories`: the
top-`memory.json→shadow.limit` (3) facts ranked by importance, newest winning a tie.
`Settings.reset_everything()` → `SaveSystem.wipe_everything([settings.cfg])` deletes ALL of
`user://` (slots, shadow, letters, diary, debug) except the settings file.

## Round 2  (2026-11-04, agent: swe-2)

### Summary
The round-1 blocker was one bug seen from three angles (CODE-1 / DES-1 / SAF-1): `_recurse_wipe`
normalized its root with `dir_path.trim_suffix("/")`, so the shipped `user_root = "user://"` became
`user:/`, `DirAccess.open` returned null and the recursion returned silently — `Settings.reset_everything()`
answered `{ok: true, removed: 0}` while the shadow save, the slots, the letters and the diary all survived.
The trim was also unnecessary: the recursion only ever hands `path_join`ed children to
`DirAccess.remove_absolute`, never the root. Normalization is now `SaveSystem.wipe_root()`, which drops
exactly one separator per pass and never the scheme, and a directory that cannot be opened is reported in
`errors` instead of a silent success. `ShadowStore._heal` re-applies both documented caps on read
(CODE-2/SAF-2); `wipe()`'s docblock is retargeted (DES-2); the `memories` sentence is corrected in code and
docs/07 §3.5 (DES-3); the OS-username citation now points at docs/05 M28 / docs/02 §8 (SAF-3).

The probe script (unchanged between the two runs):

```gdscript
extends SceneTree
## P3.12 round 2 probe: Settings.reset_everything() on the SHIPPED default root
## (user_root = "user://"), run with an isolated XDG_DATA_HOME so the real
## player tree is never touched.

const FILES := {
	"user://.leila/shadow.json": "{\"probe\":true}",
	"user://saves/slot_1.json": "{}",
	"user://saves/autosave.json": "{}",
	"user://letters/for_Ren.txt": "for you",
	"user://diary/day_07.txt": "day 7",
	"user://debug/turns_1.jsonl": "{}",
	"user://settings.cfg": "[accessibility]\n\nphotosensitive=true\n",
}


var _done := false


func _process(_delta: float) -> bool:
	if _done:
		return true
	_done = true
	var saves := get_root().get_node("SaveSystem")
	var settings := get_root().get_node("Settings")
	print("user_root=", saves.user_root)
	for path: String in FILES:
		DirAccess.make_dir_recursive_absolute(path.get_base_dir())
		var file := FileAccess.open(path, FileAccess.WRITE)
		file.store_string(FILES[path])
		file.close()
	print("before=", _paths("user://"))
	var result: Dictionary = settings.reset_everything()
	print("result=", result)
	print("after=", _paths("user://"))
	print("shadow_exists=", FileAccess.file_exists("user://.leila/shadow.json"))
	return true


func _paths(rel: String) -> Array:
	var out: Array = []
	var dir := DirAccess.open(rel)
	if dir == null:
		out.append("<cannot open %s>" % rel)
		return out
	dir.set_include_hidden(true)
	dir.list_dir_begin()
	var entry := dir.get_next()
	while not entry.is_empty():
		var child := rel.path_join(entry)
		var is_dir := dir.current_is_dir()
		out.append(child + ("/" if is_dir else ""))
		if is_dir:
			out.append_array(_paths(child))
		entry = dir.get_next()
	dir.list_dir_end()
	return out
```

### Deviations from the design bible
None added in round 2. **DCR (doc-only, for the producer):** `docs/09_PRODUCTION_PLAN.md:74` says "OS username
use is opt-out", while docs/02 §8 (hard-block row "Real-world personal data beyond what the player typed +
opt-in OS username") and docs/05 M28 ("or the OS username if opted in") say **opt-in**. The safety rule wins
(docs/02 §8; a change to it is docs/09 §4's user-only decision), so the code cites docs/05/02 and nothing
reads the OS username. Proposed fix: docs/09:74 → "OS username use is opt-in only". Impact: documentation
only; no code reads `OS` for the username today.
