# Handoff — P2.03: Stage-change server restart with `--control-vector-scaled`, hidden behind the transition glitch; vector files in game/data/steering

## Round 1  (2026-11-04, agent: deepseek)

### Summary
The prototype can now bind a new steering dose. `GameState.stage_transition` (P2.02) is the trigger: on the frame the
transition glitch starts, `LLM.apply_stage_steering(stage, window_ms)` resolves the docs/06 §3 dose through the new
`StageSteering` mapper (`game/data/steering/vectors.json` → the shipped `malice.gguf`, built from the tweet neurons) and
hands it to `LlamaServerBackend.apply_steering()`, which relaunches the llama-server on its own worker
(`LlamaServerProcess.restart_with_vectors`) and reports the measured ms back on the main thread. A turn and a relaunch
share one session lock, so a player line submitted during the window waits for the new server and then completes on it —
never dropped, never cut off. Everything that can go wrong (attached server, missing/invalid vector, launch failure)
keeps the previous dose and logs the reason; a vector set that fails validation is refused *before* anything is stopped.

### Files changed

  llama-server can open (extracts packed `res://` bytes to `user://steering/` for exported builds), validates GGUF

  serve healthy and unsteered). `path_mix` is reported as unbound, not invented.

  `5a61adff…cf9b5`, copied from the experiment artifact and renamed (no brand name in a shipped identifier).

### Deviations from the design bible
- **The relaunch refuses an attached server instead of restarting it.** docs/06 §4 says the prototype restarts the
  server at each stage change; it cannot restart one it did not launch without putting a second server on a busy port
  (P1.02's attach rule). Boot therefore stays attach-by-default and gains `LEILA_OWN_SERVER=1` to launch the pinned
  server, which is the configuration docs/06 §4 describes. Recorded in docs/06 §4.1 ("Ownership").
- **`path_mix` binds no file.** docs/06 §2's per-path vectors ship in P3.04; docs/06 §3 still schedules the weight, so
  the map declares it unbound and the payload omits it. No DCR: the doc already calls it interim.
- **A turn in flight wins over the glitch window.** A relaunch that would cut off a stream waits for it (bounded by
  15 s) and then gives up rather than kill the line, so a mid-turn crossing can bind late or not at all. Correctness
  (AC 2) outranks hiding the latency; the shipped stage machine only crosses at turn close, so this is the
  trigger/night-rollover path. Recorded in docs/06 §4.1 ("No lost input").
- **The mapped `--control-vector-scaled` FNAME is normalized in GDScript** (P1.23's open question), not by a shell
  helper: POSIX/relative paths pass, a Windows drive path is relativized against a declared `vector_cwd`, and
  `X:file`/`:`/`,` names are refused so the app keeps the old dose instead of launching a server that silently runs
  unsteered. No DCR: P1.23 explicitly assigned this to P2.03.
