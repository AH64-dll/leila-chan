### Round 1 continuation — what changed and why

1. **Both campaigns completed.** YANDERE ran to `campaign_over` (179 turns, 14 nights) and AWAKE to
   stage 4 (66 turns, 5 days). The AWAKE path was assigned live: the stage-2 crossing scored a 15/15
   AWAKE/ANCHOR tie (ANCHOR by tie-break), the same turn's close re-scored 18/15 and assigned AWAKE,
   and the stage-3 crossing locked it (39/16). The transcript's annotation section proves the path
   layer from the game's own logged system prompts: `path_AWAKE.md` and the scenario AWAKE twist in
   35/35 post-assignment prompts, 0 before stage 2, 0 runner-up lines.
2. **Findings updated for main.** S1-1…3 are fixed by `task/P2.22A` (`98fa28d`) and S2-1…2 by
   `task/P2.22B` (`43bcdee`); the report keeps the baseline measurements as the "before" evidence and
   says so. Round 1 also filed five S4 findings; the round-2 review corrected them: the trigger
   `effects.path` gap is **S2, not S4** (fixed on this branch — the AWAKE lock would have read 67,
   the night 85, and the stage-2 tie would have been an outright AWAKE win), the refused-input
   turn-spend was **already fixed** in main (`98fa28d`), the runner-up drop is recorded in
   `debug.missing` (no production caller reads it; the four missing modules are P3.05's), and the
   leak shortfall is stage-5-only — AWAKE is *above* its table. The resume-header duplication and
   the stage-5 leak rate stay open.
3. **The harness dropped its three wires** after Main merged `P2.22A`; the merged-tree smoke day
   above is the proof. If a future tree stops starting its Date (or reverting P2.22A), the driver
   will stall — that dependency is intentional: the harness now exercises production seams only.
4. **Host-pressure procedure** (recorded because it will recur): a killed segment leaves transport
   failures, which are not game turns. Remove them from the sidecar's `broken` array and the
   `### Broken turn`/`## Run summary` tail from the Markdown, then `--resume=1`; the per-turn
   autosave holds the resume point, and no recorded turn, night or trigger is touched. Days 9–14 of
   YANDERE were produced this way.

### Harness defects found and fixed during round 1 (so the next round starts clean)

1. Records were written a frame after the display boundary while the Date's deferred end check could
   already have burned a day — fixed by capturing the turn's whole state at the display boundary.
2. `Director.turn_completed` and `ChatUI.turn_displayed` can arrive in either order — the record now
   waits for both boundaries.
3. A submit into a locked `InputBox` looked like a phantom timeout — every submit is now guarded by
   `_ready_box()` and verified with `Director.is_busy()`.
4. Unsafe-input refusals were counted as broken turns — they are a safety pass (`refused[]`).
5. `--resume` used to start the summary at the resumed segment — it reloads the sidecar so the
   summary covers the whole campaign.
6. The driver's three wires are removed in this round (main ships them); the merged smoke proves the
   harness works without them.

### Deviations from the design bible

None in game code or data — no design file, scenario, trigger, prompt module or schema was changed.
The deviations are in the test method only, stated in report §6: attach-mode server (dose scheduled,
not bound), classifier tier off (fail-closed bars), raw model text in the dev transcript, and
mid-campaign server restarts caused by host memory pressure.
