# Handoff — P1.06: `PromptBuilder.gd` — layered assembly (persona, player, stage, scene, memories, events, rules + 12-exchange history as plain text)

## Round 1 (2026-11-03, agent: deepseek)

### Summary
`PromptBuilder` now turns a turn context (docs/02 §4 step 1) into the message array the LLM facade
sends, plus the per-layer token report the overlay, prompt lab and transcript logger need. The
eight layers of docs/08 §1 are assembled in exactly that order into the system message — persona,
player line, stage module, path module (stage ≥ 2 + one runner-up line), scene, memories (≤ 8),
events, rules + glosses (+ the dynamic enums offered this turn). The rest of the array is the
sliding history window (last 12 exchanges, pairs intact, assistant turns stored as the spoken text
only), the current player turn and an opt-in assistant prefill block. Two committed golden fixtures
pin the whole structure; 25 new gdUnit4 cases cover the four acceptance criteria and the failure
paths. `bash tools/test.sh` is green: 80/80 gdUnit4 cases, lint and format clean.

### Deviations from the design bible
docs/08 §1 is followed literally; the following are choices the docs leave open (each is covered by
a test and documented in the class docstring):
- **History trimming is budgeted, not just counted.** docs/08 §1 says "last ~12 exchanges"; the
  window also drops whole exchanges from the oldest end when the docs/07 §3.1 ~1500-token history
  budget would be exceeded. 12 alone can exceed the context at 8192 with long lines.
- **Missing prompt files are reported, never invented.** `debug.missing` names them and the layer
  stays empty; a stage ≥ 2 turn with no path adds `path_unassigned_at_stage_<n>` to
  `debug.warnings`. Stage 2–5 and path modules are P2.13, so today this is the honest behaviour
  instead of silently reusing a stage-1 voice.
- **The prefill block is opt-in** (`ctx.prefill`, default off). llama-server renders the
  non-thinking assistant header itself (`chat_template_kwargs.enable_thinking=false`, docs/02 §9,
  already sent by P1.02), so a trailing assistant message would change how the template ends the
  prompt. `PREFILL_NEWLINE` is exposed and tested for callers that want it.
- **Token counts are estimates** (`ceil(chars / 3.6)`) until a real counter is injected with
  `set_token_counter()`; `debug.token_counter` reports which is in use. Calibrated against P1.05's
  real llama-tokenize numbers (857 stage-0 / 873 stage-1 tokens at 3028/3146 chars) and asserted
  within 5% by `test_token_estimate_is_calibrated_against_the_real_tokenizer`. No llama tokenizer
  is reachable from GDScript, so the exact number needs the backend's `/tokenize` — a follow-up for
  the LLM role, not a silent approximation.
- **Memories keep the newest 8 facts** (docs/08 §1 caps the layer at 8; the doc does not say which).
- **Two suites instead of one.** gdlint caps a class at 20 public methods, so the history window
  lives in `test_prompt_builder_history.gd` (the GameState suite is split the same way).
- **Dynamic enums** (docs/08 §1 "rules.md + enum glosses (+ dynamic enums)") are injected from
  `ctx.offered` as one "Offered this turn — …" line; the builder never owns gate tables (P1.07).

No DCR: nothing here contradicts docs/01–docs/10; the open points above are implementation choices
inside doc-silent space.

- **P2.13 (stage 2–5 + path modules)** must land before stage 2 is playable: until then

  bias means the real number is near 1010. NAR trimming or a shorter scene line is the lever; this
  task reports the split rather than hiding it.
