### Deviations from the design bible

**DCR-1 — docs/06 §1's hardened recipe conflicts with docs/02 §3 and §9**

- **Docs/sections:** `docs/06_STEERING.md` §1 ("Hardened decoding (`maxLength` on strings, `repeat_penalty 1.15`,
  `temperature 0.7`) keeps 100% valid JSON up to scale 12") versus `docs/02_DIRECTOR_PROTOCOL.md` §3 (schema
  `say` `maxLength` 200, `inner` 90) and §9 (stage temperatures 0.75–0.95, stage 5 = 0.95).
- **The conflict:** the measured recipe — `experiments/RESULTS.md:45` ("Hardened = maxLength 90 on `inner`, **160**
  on `say`, `repeat_penalty` 1.15, temperature 0.7") and `experiments/windows/report.md` §3 ("maxLength 90/160,
  repeat_penalty 1.15, temp 0.7") — is not the shipping configuration on two legs: `say` ships 200 (docs/02 §3)
  and every stage runs hotter than 0.7 (docs/02 §9). docs/06 §1 currently reads as if the *shipped* schema and
  table were the validated ones.
- **Proposed text (docs/06 §1, replacing the bullet):** "Hardened decoding (`maxLength` on strings,
  `repeat_penalty` 1.15, `temperature` 0.7) kept **100% valid JSON up to scale 12** — measured with `say` capped
  at **160** (`experiments/RESULTS.md`, `experiments/windows/report.md` §3). The shipping schema uses `say` 200
  (docs/02 §3) and the docs/02 §9 temperature ladder (0.75–0.95), so the claim is measured for this recipe, not
  for the shipped numbers; P2.21 re-measures the shipped configuration."
- **Why:** the bible must not present an unmeasured configuration as the validated one. Keeping the two number
  sets distinct makes the residual risk explicit: stage 5 ships 0.95/200 and is exactly the stage in the 8–12
  risk band.
- **Impact:** docs-only, no code or data change; the table stays docs/02 §9's (this task's row mandates those
  numbers). Enforced and gated is the subset that both docs agree on — the string limits (docs/02 §3) and the
  `repeat_penalty` floor for every stage that can reach the band. `sampling.json` → `hardened.measured` keeps the
  measured legs (160/0.7) so they cannot be mistaken for adopted values, and the suite pins them. P2.21 must
  validate the shipped 0.95/200 configuration; if it does not hold at scale 12, lowering stage-5 temperature
  and/or `say` toward the measured recipe is a P2.02/P2.21 decision, not this task's.

No other deviations: the data file keeps the docs/02 §9 rows exactly, and no runtime clamps were added — the file
stays authoritative.
