# Handoff — P2.05: Sampling per stage (temperature, top_p, repeat_penalty) + hardened schema limits

## Round 1 (2026-11-04, agent: commandcode)

### Summary
The docs/02 §9 per-stage table is now provably data-driven end to end: `game/data/sampling.json` (v2) carries the six stage rows plus a `hardened` envelope from docs/06 §1, `TurnContext.parse_sampling()` resolves it (current shape **and** the legacy stage-agnostic flat-row shape, keeping backward compatibility), and `Director` no longer keeps a copy of the numbers or their defaults — it asks `TurnContext.request_sampling(stage)`. A new suite drives every stage 0–5 through the Director into a `TurnRequest` and then through `LlamaServerBackend._build_body()` into the JSON payload, asserting the exact stage values and the hardened `maxLength` limits. `TurnSchema` now has one named constant per limit (`INNER_MAX_LENGTH` 90, `SAY_MAX_LENGTH` 200, `MEMORY_MAX_LENGTH` 80) shared by the grammar and `validate_turn`, so the two cannot drift.

Note for the producer: the brief's "extend sampling.json with per-stage entries" was already true at branch point — the file has been per-stage since P1.08 (`git log -- game/data/sampling.json` → `4a46b3d`). This round extends it with the docs/06 §1 hardening envelope and the backward-compatible loader, and adds the missing proof.
