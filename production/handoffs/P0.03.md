## Round 1  (2026-11-02, agent: swe2)

### Summary
The Windows CUDA 13.4 build of llama.cpp **b12024** (`llama-b12024-bin-win-cuda-13.4-x64.zip` +
`cudart-llama-bin-win-cuda-13.4-x64.zip`, extracted as a pair into `tools/llama/llama-b12024/`, gitignored,
732 MB) now serves the model on this machine — the E: copy was Linux `.so` only. `tools/llm/serve.ps1`
and `serve.sh` launch `llama-server` with `--jinja`, `-ngl 99`, `-c 8192`, `-np 1`, port 8089 and an
optional `--control-vector-scaled file:scale`. `tools/llm/fetch_llama.*` re-download the pinned build;
`tools/llm/smoke.py` runs one B4 schema-constrained Turn and prints validity, tokens/s and VRAM;
`tools/llm/README.md` documents fetch → serve → verify. Verified live on the RTX 4050: health ok,
valid Turn JSON at ~51 t/s, 3251 MiB VRAM, and the scale-4 malice vector produces the documented
dark-inner effect while JSON stays valid.

### Files changed
- `tools/llm/serve.ps1` — start llama-server (Windows). Params `-Model/-Bin/-Port/-CtxSize/-GpuLayers/-Vector/-VectorScale`; env `LEILA_MODEL`/`LEILA_LLAMA_BIN`; prepends bin dir to PATH for backend DLLs.
- `tools/llm/serve.sh` — same for Git Bash / Linux (LD_LIBRARY_PATH on Linux).
- `tools/llm/fetch_llama.ps1`, `tools/llm/fetch_llama.sh` — download + extract the pinned release pair (`-Variant cuda-13.4|cuda-12.4|vulkan|cpu`, `--variant` for sh).
- `tools/llm/smoke.py` — health + one real Turn via the imported `tool_test_v3.schema`; exit non-zero unless valid.
- `tools/llm/README.md` — fetch/serve/verify docs, manual download commands, control-vector restart note.
- `tools/llama/llama-b12024/` — binaries (gitignored, not in the diff).

### Deviations from the design bible
None. Notes: ctx is `-c 8192` (docs/07 §3.1) rather than the 4096 used in the quick experiments — fits VRAM
with room. Port defaults to 8089 so `experiments/tool_test*.py` work unchanged (steer_sweep.py manages its
own server on 8090).

### Open questions / follow-ups
- `smoke.py` imports `tool_test_v3.schema` via sys.path — fine for the prototype; P1.02 builds the real backend.
- PowerShell 5.1 parses `.ps1` files as ANSI when they lack a BOM — keep `tools/llm/*.ps1` pure ASCII
  (an em dash byte sequence broke a string literal in round 1).
- CUDA 13.4 chosen (driver 610.47 supports it); `fetch_llama.ps1 -Variant cuda-12.4|vulkan` are the
  documented fallbacks per the P0 risk table.
- P0.04 (QA) can run `tool_test_v3.py` / `steer_sweep.py` against this server directly.
