# Handoff — P1.23: P0 gate C1: document and verify Windows drive-colon handling for control-vector launch paths

## Round 1 (2026-11-03, agent: swe2)

### Summary
`--control-vector-scaled FNAME:SCALE` is parsed by llama.cpp splitting on `:` and `,` — a FNAME
containing `:` can never be passed, so every `X:\...` Windows absolute path failed (the P0 gate C1
carry-over). Both launchers (`serve.sh`, `serve.ps1`) now normalize vector paths through a single
shared helper, `tools/llm/cvec_path.py`: drive-rooted paths become same-drive relative paths against
the server working directory, `X:file` drive-relative syntax and `:`/`,` filenames are rejected with
clear messages, and scale strings are validated. The contract is documented in both script headers,
their `--help` output, and `tools/llm/README.md`; `experiments/steer_sweep.py` now imports the same
helper instead of its inline copy. Verified live: the real b12024 binary rejects `a:b:c`, and
`serve.sh` launched a healthy server with the real malice vector at scale 4.
