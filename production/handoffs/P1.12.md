### Deviations from the design bible
- **"8 stage-0 cues"** = docs/02 §2.1 rows with gate 0: `none`, `giggle`, `laugh_soft`,
  `gasp`, `sigh`, `hum`, `sniffle`, `heartbeat` = 8. `none` is an accepted no-op; `hum` and
  `sniffle` are documented `gap` pools and deny cleanly without burning budget.
- **Cue budget semantics**: "1 cue per 2 turns" is implemented as a token bucket
  (per-turn accrual 0.5, cap 1.0 at stage 0–1; band table in data). First turn starts at cap
  so the very first cue is never starved. Same long-run rate the docs describe.
- **Music hold-vs-request**: over-early requests are *queued* and applied on the first legal
  turn (pending state observable via `pending_music()`/`music_deferred`), rather than
  silently dropped — the doc says "requests" without specifying deferral; queueing matches
  Director-per-turn semantics. `silence` still must clear the hold like other states; it cuts
  instantly once it wins the slot (0 s crossfade, per docs/04 §2 table).
- **Stage-DSP on the Music bus (docs/04 §1/§2 drift effects) not implemented** — the audio_rules
  bus map and MusicA/B pair are built so effects can be added, but pitch drift/low-pass per stage
  is P2.16 "stage layers" scope, not listed in this task's criteria.
- **Loudness is single-pass ffmpeg loudnorm** (~−16/−18 LUFS), not two-pass; fine for v1,
  P5.10 owns the final measured mix.
- **System keys imported so far**: only `voice_blip.stage0_2` (needed by the Voice bus routing
  test + META's blip playback); other system pools stay unimported until their consumers land.
