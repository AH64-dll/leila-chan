# Handoff — P2.07: Inner-voice leak from stage 2 (safety-filtered inner text surfacing)

## Round 1  (2026-11-04, agent: deepseek)

### Summary
The docs/03 §5 inner-voice leak (docs/05 M41) now exists end to end. `InnerLeak` owns the docs
frequency/style table (stage 2 → 5 %, stage 3 → 15 %, stage 4–5 → 30 %, red, word by word), the
closed stage gate (2+) and per-turn cap, the docs-fixed stage→style mapping and the seeded per-turn
roll; `InnerLeakLabel` draws the leaked thought as a ghost line pinned to the dialogue box's top edge
(behind the box, its bottom `behind_overlap` px occluded by the panel); `ChatUI.leak_inner()` is the
only path from model `inner` text to the screen and runs every line through the **Safety autoload
first, failing closed to bars**; `Date` forwards each finished turn's `inner` from the Director's
public `turn_completed`; the F3 overlay shows the plan and leaks the data's sample line on `F4`.

### Deviations from the design bible
- **"Behind the text box" had to be given a drawable meaning.** docs/03 §5 says the ghost appears
  *behind the text box*. The shipped panels are opaque (`ChatLog` 0.75, `TextBox` 0.92 alpha), so a
  literal z-behind-everything draw renders the thought as near-black (verified: the first render pass
  measured ~30 % of the intended colour). Implemented as: the leak is drawn at **z −1, behind the
  TextBox panel**, with the ChatLog panel moved to **z −2** — so the line sits over the log panel but
  under the dialogue box, and its bottom `behind_overlap` px are genuinely occluded by the box's top
  border (screenshots 01/03). The alternative (in front of the box) was rejected because it loses the
  "surface from behind the panel" effect. **DCR candidate** for docs/03 §5: "the game shows it as a
  ghost line at the top edge of the text box, drawn behind the box so its lower edge is clipped by the
  panel". Impact: visual only; no pillar/safety rule involved.
- **Alignment and overlap are data, not the docs** (docs are silent): stage 2–3's ghost is
  right-aligned and tucked 2 px under the border; stage 4–5's red line is left-aligned and sits fully
  in the gap. Both live in `game/data/inner_leak.json→styles.*.align/behind_overlap` and can be
  retuned without code.
- **Red-line timing is data tuning**: docs give "1 s" only for the stage-2 ghost; the red line's
  0.22 s/word and 1.6 s hold are our numbers (docs-silent), in the data file.
- **The leak fires at `turn_completed`, not when the `inner` field closes mid-stream.** The leak is
  decided per turn; the Director already publishes `turn_completed(turn_index, turn_data)`, and it
  sits at gdlint's 1000-line cap, so the scene subscribes there instead of adding a second
  Director → UI seam for one field. Practically the leak still lands while her beats are typing out
  (the 35–45 chars/s read-out lags the stream). If design wants it strictly *before* the first beat
  (the docs' "earliest warning" framing), that is a Director-side one-line hook in P3.08.
- **The leaked line is not run through the corruption filter.** docs/07 §3.4 places Corruption on the
  *say* pipeline; docs/03 §5 defines the leak's look only (grey italic / red word-by-word). Keeping the
  earliest warning readable is the point, so no hesitation/strike/zalgo is applied. If the design
  reviewer wants it, `CorruptionSession.transform_beat()` is a three-line drop-in (P2.06's note).
- **The stage→style mapping is code, not data** (`STAGE_STYLE`): data tunes each style's look and the
  per-stage chance, but cannot move the gate, exceed one leak per turn, restyle a stage, or set a hold
  so short the leak is invisible (the hold is floored at 0.1 s). Pinned by
  `InnerLeakTest::test_data_cannot_restyle_a_stage_or_exceed_one`.
- **Calmer mode** reuses `Corruption.effective_stage`, so `content_level = calmer` makes stage 4–5 leak
  the stage-3 ghost at 15 % (docs/02 §8's "calmer caps stage at 3", one rule for both text systems).
