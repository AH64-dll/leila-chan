### Open questions / follow-ups
- `llama-server --version` writes to **stderr** (b12024). `serve.sh` merges `2>&1`; `serve.ps1`
  relaxes `ErrorActionPreference` around the call because PS5.1 promotes native stderr to a
  terminating error under `Stop`. Worth remembering for any future script that shells out.
- `check_turn` hand-mirrors `tool_test_v3.schema()`. If `jsonschema` ever becomes a project
  dependency, swap it for `jsonschema.validate(turn, schema(stage))` for strictness; the manual
  check already covers every constraint the schema encodes.
- The Git Bash `PATH="$BIN:$PATH"` prepend splits on the `D:` colon (`D` + `/lila/...`); harmless
  because Windows DLL resolution finds the backend DLLs in the exe's own directory, and `exec "$EXE"`
  doesn't use PATH. Left as-is — flag if a future .sh relies on the bin dir actually being on PATH.
- Worktrees have no `tools/llama/` or `models/` — live verification needs
  `LEILA_LLAMA_BIN`/`LEILA_MODEL` pointing at `D:/lila` (as in the verify block).
