### Deviations from the design bible
- **DCR-1 — docs/01 §5 T13 and T15 are marked M, but docs/02 §1.2's `read` enum has no label for them.**
  The 17 labels cannot say "that was a lie" (T13) or "you ignored my question" (T15). Implemented as
  **guard-only rows**: the game decides (`MemoryRules.contradiction()` for T13; this turn's
  `ignored_questions` bump for T15 — the counter P2.12's keyword rule already sets, per its handoff
  convention) and the row fires at full strength. Proposed doc text: *"A trigger may also declare a
  game-side `guard` instead of a detector when the evidence is a fact the game computes itself (T13's
  contradiction with a stored memory, T15's ignored question); a guard row fires at full strength,
  because the evidence is deterministic and not the model's guess."* Why: without a label the M letter is
  unimplementable, and halving a deterministic check would make T13's documented Trust −10 unreachable.
  Impact: docs only; `tests/test_triggers.py::test_guard_only_rows_are_the_game_checks` pins the shape.
- **DCR-2 — docs/01 §5 T03's Detect column is K, but "before Day 3" is a clock condition.** Taking it as
  a C detector would make the row K+C, which the doc's column does not allow; putting the day into the
  line only would leave the trigger firing on day 9. Implemented as a `guard` (`day_lte: 2`), which is
  not a detection letter. Proposed doc text: *"T03: K (plus the clock guard `day_lte 2`)"*, and a
  sentence in docs/02 §1.2 that a guard is a precondition, not evidence. Impact: docs only;
  `test_t03_love_before_day_3` proves day 2 fires and day 3 does not.
- **DCR-3 — the data-contract additions** (`docs/07 §2`'s row vocabulary, and docs/05 §2 for the
  sentence): (a) row field `guard` with `day_gte|day_lte|day_eq|turn_gte|hour_from|hour_to|`
  `absence_hours_gte|flag_set|flag_absent` plus `counter_gte` and `contradicts_memory`;
  (b) `{fact}` as a line token; (c) `effects.flags.flash_sprite` for docs/01 §5's "sprite 29 / sprite 17
  flash"; (d) `gates.opportunities.<action>` in `stage_gates.json` for the docs/05 §2 offer sentence.
  Why: (a)+(b) let P2.10 author T03/T13/T15 without inventing detection letters, (c) is the only channel
  P2.08's effects vocabulary offers for a sprite request, (d) keeps prompt content in data (the
  OPPORTUNITY sentence was hard-coded in docs/05 §2 and would otherwise sit in a `.gd`). Impact: docs
  only; the loader heals unknown guard keys by ignoring the row, and `tests/test_triggers.py` rejects an
  unknown guard key, counter or empty cue.
- **T01 "…until answered" (docs/01 §5).** There is no resolution detector to clear it (the read enum has
  no "answered"), so the row is `repeatable` with `cooldown_turns: 1`: she asks again every time the
  player brings the girl up, and stops when they stop. A `clear_on` field would need a signal the design
  does not define; flagged for the producer rather than invented.
- **Numbers the bible does not state** ("SPLIT/YANDERE spike", "Affection +", "HOLLOW/SPLIT +", "TSUN/SPLIT
  spike") are data choices in `triggers.json`, chosen so each path's own formula (docs/01 §4) moves and no
  row alone can lock a path: T02 SPLIT 4/YANDERE 2, T03 affection 3, T09 SPLIT 2, T11 HOLLOW 2, T12
  apathy 1, T14 TSUN 4/SPLIT 2, T15 HOLLOW 2/SPLIT 2, T08 instability 2, and T06/T14's sprite flashes.
- **T05 "first time … third time"** is a three-entry `line` array on a `repeatable` row (the last entry
  repeats), not an `escalating` row: docs/01 §5 gives T05 a flat "AWAKE +4" and only the *speech*
  escalates.
- **docs/05 §2 "your reply is the last thing they hear before the game decides"** is honoured as the
  second press (docs/05 §1.1 M01's own rule), not as a self-quit after her line: the self-quit is M02
  "she closes the game" (St 4), a separate event outside this task. `execute_after_text("refuse_exit")`
  consumes the offer and records the refusal.
- **T04 fires on the first submit on/after Day 10.** The pipeline is turn-driven, so a night roll-over
  that nobody follows with a message does not fire it; P2.19's night loop should call the clock entry
  point (follow-up below).
