# Handoff — P1.30: Windows Godot launcher: native stderr warnings must not terminate passing test runs

## Round 1  (2026-11-02, agent: claude)

### Summary

`tools/godot.ps1` now relaxes `$ErrorActionPreference` to `Continue` for the native invocation
only (`& $Exe @Arguments`) and restores it immediately afterwards. Windows PowerShell 5.1 turns
any native stderr line into an ErrorRecord; the launcher's script-scoped `Stop` turned that into
a terminating `NativeCommandError` even when Godot exited 0, which is why an expected
`WARNING: GameState.from_dict: ...` aborted a passing gate. The new `Invoke-Godot` helper keeps
the child's real exit code, leaves stderr on the error stream (so the `2>&1 | ForEach-Object`
transcript in `tools/test.ps1` still captures every `WARNING:` line), and fails closed if the
process never starts. The optional `git worktree` probe got the same narrow treatment: a copy
outside a git repository produced the identical abort before binary resolution even began.

A Windows-only regression test compiles a stub native executable at run time and covers
warning-plus-exit-0 and stderr-plus-exit-7 for both `LEILA_GODOT` and the resolved-binary path,
plus missing-binary fail-closed cases. I reproduced the exact P1.04 integration failure by
temporarily reversing the revert in this worktree: the pre-fix launcher exits 1 at
`WARNING: GameState.from_dict: stored stage 5 outside the peak band`, while the fixed launcher
completes 37/37 gdUnit4 cases and exits 0 through both `tools/test.ps1` and `tools/test.sh`.
The temporary P1.04 reapplication was discarded; this branch contains only the launcher fix and
its test. The zero-suite and stale-report guards were re-run and still fail red.

Provenance: SWE-2 started this task and stopped on a rate limit before editing anything; the
only worktree difference was the producer's untracked brief.

### Files changed

- `tools/godot.ps1` — new `Invoke-Godot` helper (`:16-32`) that relaxes `$ErrorActionPreference`
  around the native call, captures and propagates the real exit code, and errors on a process
  that never started; both invocation branches use it (`:34-40`, `:63-70`). The optional
  `git worktree` probe is wrapped the same way (`:46-61`) because its expected failure outside a
  repo was also a terminating native-stderr error.
- `tests/test_godot_launcher.py` — Windows-only pytest wrapper; skips on other platforms and
  asserts all six probe cases and `PROBE: OK`.
- `tests/launcher/godot_launcher_probe.ps1` — compiles a stub `.exe` at run time, builds a fake
  pinned-binary repo, and exercises warning+0 / stderr+7 for both resolution paths plus two
  fail-closed cases.
- `tests/launcher/run_case.ps1` — runs one launcher case in a fresh Windows PowerShell process
  with the same `2>&1 | ForEach-Object` shape as `tools/test.ps1`, and reports the launcher's
  exit code without masking a terminating failure.

### Open questions / follow-ups

- **Producer:** P1.04 is still reverted on `main`. After this fix merges, reverse `38ea118` and
  re-run both gates; the evidence above shows P1.04 completes 37/37 through both runners with
  the launcher fix. Do not merge the temporary reapplication from this worktree — it was reset.
- **CI:** the new pytest test skips outside Windows (`sys.platform != "win32"`); the current CI
  runner is Linux, so this regression is covered on Windows dev machines only until a Windows
  runner is added.
- **Probe dependency:** `tests/launcher/godot_launcher_probe.ps1` compiles its stub with
  `Add-Type -OutputType ConsoleApplication` (Windows PowerShell 5.1 / .NET Framework). If a
  future runner lacks the compiler, the probe fails loudly rather than silently skipping.
- **Do not weaken** the zero-suite wipe/freshness checks or the native stderr handling; the
  `NativeCommandError` label will still appear in PowerShell 5.1 transcripts even when the
  stream is correctly non-terminating.
