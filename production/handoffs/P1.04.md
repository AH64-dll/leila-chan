### Design interpretations (docs were silent — flagged for the design reviewer)
These are readings of the bible, not changes to it; each is one line to flip if the reviewer disagrees.
- **Stage is monotonic** (`_refresh_stage` only moves up). docs/01 §2 lets Instability dip to
  `peak − 15` ("good days"); §3 stage transitions are one-way diegetic events and the path locks at
  stage 3. I read stage as never regressing — it also prevents band-edge flapping when instability
  hovers at 15/30/50/70/90. The dip itself is still visible in Instability/dose inputs later.
- **`read` → counter mapping** is not written down in docs/01 §2 (it only says the harness "tags
  messages into counters"). It lives in `profile_map.json`: direct-name mappings where a counter
  exists (tease→teasing, leaving→leaving_talk, …), compliment→flattery (keeping warmth scarcer so
  ANCHOR stays "the hardest path"), insult/cold/leaving → coldness. `control`, `apathy` and
  `flattery_rejected`-style signals are bumped by the keyword classifier via `bump_profile()` — no
  `read` label carries them.
- **All meters start at 0** (docs give ranges, not starting values). If design wants a warm start
  (e.g. affection > 0 at first meeting), that's a one-line change in `reset()` or scenario data.
- **`inconsistency`** is computed from a warm↔cold tone map in the same data file; a neutral `read`
  between them does not break the swing. `leaving` counts as cold-toned (warmth then "gtg" is a swing).

### Deviations from the design bible
None for formulas/rules. Scope notes: `turn`, `player_name`, `path`/`path_locked` are in the snapshot
because docs/07 §2 lists them as GameState contents and P1.06/P1.08/P1.14 need them;
`advance_day()` applies the +3 daily burn (docs/01 §2) — P2.01 owns slow-burn tuning on top.
