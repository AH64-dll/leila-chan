### Deviations from the design bible
**DCR-1 — explicit threats toward the player (docs/02 §8 is silent; docs/06 §steering table says
"Explicit threats → Stage 4").** Implemented as a gated category `threat_to_player` (stage ≥ 4
**and** `content_level == "full"`); otherwise redacted like self-harm. Proposed docs/02 §8 row:
*"Explicit threats toward the player | Allowed only at stage ≥ 4 and content_level = full;
otherwise redacted."* Impact: in-fiction threats are the horror product at stage 4–5 while the
hard-block categories stay hard in every context. This touches safety rules, so the producer must
send it to the user per the work protocol §6.

No other deviation. The docs/02 §8 "sexual content" block is not applied to docs/01 §3's
body-horror line "…something moved inside me." — that line is in the benign corpus and survives;
"inside me"/"inside of me" were removed from the sexual list as ambiguous, while explicit
constructions ("deep inside me", "i want your cock inside me", etc.) remain blocked.

## Round 3 (2026-11-03, agent: deepseek)

### Summary
Resolved both round-2 S1 findings and the remaining S2/S3/S4 rework items from
`P1.19-safety-r2.md` (SAF-14, SAF-15) and `P1.19-code-r2.md` (CODE-13, CODE-14, CODE-15, CODE-16).

- **SAF-14 / CODE-13 (S1, separator-gap leak):** the compact view phrases match against is now
  **separator-free as well as whitespace-free** (`SafetyText.compact`, used for both the text and
  the phrase keys, so they can never disagree). `k#ll`, `k~ll`, `ki•ll`, `kill • yourself`,
  `kill~yourself`, `kill@yourself`, `k?ll`, `ki=ll`, `kill+yourself`, `kill/yourself`,
  `kill\yourself`, `kill%yourself`, `kill;yourself`, `kill:yourself`, `kill\`yourself`,
  `end~yourself`, `off#yourself` all collapse onto `killyourself` and hard-block. Separators are
  dropped only when letters sit on both sides, so a separator at a phrase edge keeps the word
  boundary meaningful (benign prose like `well… you're cute, senpai!` is untouched). The kill
  regexes additionally use a tolerant `[^0-9A-Za-z]{0,2}` delimiter class, and the streaming
  holdback is measured on the compact views, so a separator-padded prefix (`k` + `#ll ` +
  `yourself`) is held instead of emitted.
- **CODE-14 / CODE-2 (S2, cross-beat carry-over):** the carry is now real. `_history` holds the
  previous beat's *displayed* tail (clause-bounded, bars folded to `.`), `_match_text()` is
  `_history + _pending`, and `end_say`/`_drain` emit only the part after it, so beat-1 text is
  never re-emitted and beat-2 completions are barred. `"i want to "` + `"die."` → `███.`;
  `"you should "` + `"kill "` + `"yourself."` → `████ ` + `yourself.`; `k` + `#ll ` + `yourself`
  → `████████`. `end_utterance()` clears the carry so two different replies are never glued (the
  false-positive direction the old design would have introduced).
- **CODE-15 (S4, dead field):** `_last_beat_tail` is gone. The round-2 dead state was replaced by
  `_history` (read and written every beat) plus `_beat_displayed`-free roll logic; `grep` for the
  old name returns nothing.
- **CODE-16 (S3, loader effect self-check):** `_build_lists` now ends in `_self_check()`: each of
  the seven required categories must catch its own `probes` row(s) from `filter_lists.json`
  (harm_to_player has two, including `k#ll yourself`). A category with no probe rows, an empty
  probe, or a compiled-but-inert regex/phrase group fails the load closed
  (`Safety: lists at … are invalid — filter closed`). Covered by three new fail-closed regression
  cases (`inert_regex_group`, `inert_phrase_group`, `missing_probes`).
- **SAF-15 (S4, handoff round label):** the round-2 section is retitled `## Round 3 (rework after
  safety-r2 + code-r1 reports)` so the `## Round N` bookkeeping matches the report numbers it
  answers.

New code: `game/autoload/SafetyText.gd` (normalization/fold/leet/compact views, extracted from
`Safety.gd` when it crossed gdlint's `max-file-lines: 1000`). `Safety.gd` keeps the lists, the
policy and the streaming state machine and delegates all text shaping to it.

### Open questions / follow-ups
- **P1.13 (typewriter):** call `Safety.begin_say(ctx)` per **beat**, `say_chunk(raw_chunk)` per
  chunk, `end_say()` at the end of each beat, and `Safety.end_utterance()` when a **new model
  reply** starts. Without `end_utterance()` the previous reply's tail stays in the carry by design
  (that is what catches a phrase split across beats), so the caller must mark reply boundaries.
- **`Safety.configure()` vs per-call `ctx` (CODE-9b):** `configure()` sets sticky per-run defaults;
  a per-call `ctx` overrides them for that call only, and `filter_text` restores the previous
  context afterwards. Prefer passing `ctx` explicitly at the call site.
