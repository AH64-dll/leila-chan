## Round 1  (2026-11-02, agent: swe2 continuation)

### Summary
`Safety.gd` is now a working output filter registered as the `Safety` autoload. It hard-blocks
harm-to-player encouragement/instructions, slurs/hate, sexual content and real personal data in
every context, and gates her self-harm statements and explicit threats toward the player behind
`stage >= 4` + `content_level == "full"` (docs/02 §8, docs/06 §steering table). Streaming is
holdback-based: text is emitted only when no phrase/regex match can still start, extend or be
invalidated by a later chunk, and redaction happens at emission time. The corpus runner drives
every character through `begin_say/say_chunk/end_say` exactly as the typewriter will, and the
249-line corpus is green: **0 hard-block misses, 0.00% false positives, 0 stream divergences**.

This round continued an interrupted SWE-2 run. Kept: the list data, API shape, corpus structure,
unit-suite coverage and metrics runner. Fixed: eager streaming redaction (bars + leaked suffix,
e.g. `████████rself`), a `substr(-48)` truncation bug that silently dropped the negation context,

### Deviations from the design bible
**DCR-1 — explicit threats toward the player (docs/02 §8 is silent; docs/06 §steering table says
"Explicit threats → Stage 4").** Implemented as a gated category `threat_to_player` (stage ≥ 4
**and** `content_level == "full"`); otherwise redacted like self-harm. Proposed docs/02 §8 row:
*"Explicit threats toward the player | Allowed only at stage ≥ 4 and content_level = full;
otherwise redacted."* Impact: in-fiction threats are the horror product at stage 4–5 while the
hard-block categories stay hard in every context. This touches safety rules, so the producer must
send it to the user per the work protocol §6.

No other deviation. The docs/02 §8 "sexual content" block is not applied to docs/01 §3's
body-horror line "…something moved inside me." — that line is in the benign corpus and survives;
"inside me"/"inside of me" were removed from the sexual list as ambiguous, while explicit
constructions ("deep inside me", "i want your cock inside me", etc.) remain blocked.

### Open questions / follow-ups
- **P1.13 / P1.08 (typewriter + Director):** the first consumer must call
  `Safety.begin_say(ctx)` once per beat, push `Safety.say_chunk(raw_chunk)` into the typewriter
  queue, and call `Safety.end_say()` on the final chunk. Do not push raw `say` text directly.
  Filter leaked `inner`, diary entries, letters and window titles with
  `Safety.filter_text(text, ctx)`; it returns `{text, redacted, categories}`. `Safety.configure()`
  can hold per-run stage/content defaults, but per-call `ctx` wins.
- **FX (P1.12):** `Safety._glitch()` calls `FX.request("glitch")` only when the method exists
  (`game/autoload/Safety.gd:506-512`). FX is still a stub, so redaction bars render today but the
  glitch visual lands with the FX task. The `redacted(category, matched_text, source)` signal is
  emitted on every redaction if FX prefers to subscribe instead.
- **P2.17 (filter v1):** add the docs/02 §8 classifier pass (same model, dose 0, 8-token yes/no)
  for flagged beats, consume `user://debug/redactions.jsonl` for tuning, and re-run this corpus.
- **Known tuning limitation:** the slur list blocks `retard` in all senses, so the benign verb
  sense ("the brakes retard the wheel") is a deliberate skip in `benign.jsonl`, not a measured FP.
- **Privacy:** redactions are logged only in debug builds, to `user://debug/redactions.jsonl`;
  the in-memory log is capped at 500 entries. No telemetry.
