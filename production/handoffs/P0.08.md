# Handoff — P0.08: Asset/data bridge: deterministic script `tools/bridge/export_to_godot.py` copying art/leila/x2 + palette, data/casting.json, assets/audio/cue_map.json into game/ with Godot import settings (nearest filter, no mipmaps)

## Round 1  (2026-11-02, agent: swe2)

### Summary
`tools/bridge/export_to_godot.py` now copies the 31 Leila x2 sprites + `palette.json` into
`game/assets/sprites/leila/`, and `data/casting.json` + `assets/audio/cue_map.json` into `game/data/`.
Each sprite gets a `.png.import` written **byte-for-byte the way the editor writes it** (lossless,
`mipmaps/generate=false`) including a `uid://` produced by a Python port of Godot's own
`ResourceUID::create_id_for_path` (DJB2 `hash64` over project name × res path × file md5 → PCG32 →
base-34 `id_to_text`), so `godot --import` finds nothing to change — every output byte is a pure
function of the inputs. `game/tests/test_bridge.gd` (a `SceneTree --script` smoke test, no framework
needed yet) verifies casting resolution `joy/T0/i1 → 01`, sweeps all 264 feeling×tier×intensity
cells + every path override/flagged sprite id, and checks all 31 sprites load as
`CompressedTexture2D` with mipmaps off. Nearest filtering is the project default
(`default_texture_filter=0`, already set by P0.05 — Godot 4 has no per-import 2D filter).

### Deviations from the design bible
None contradicting docs; clarifications where docs/brief are silent:

1. **"Nearest filter" mechanism** — Godot 4 has *no* texture-import filter option for 2D; filtering is a
   render-time property. It is satisfied by `rendering/textures/canvas_textures/default_texture_filter=0`
   (Nearest), already set by P0.05 and asserted in the test. `.import` files carry
   `mipmaps/generate=false` + lossless `compress/mode=0` (pixel-art correct: no filtering artifacts, no
   VRAM compression smearing).
2. **File placement** — docs/07 §2 sketches granular `data/{feelings,sprites,resolver,cues}.json`
   (owned by P1 tasks). The consolidated `casting.json` lands at `game/data/casting.json` and
   `cue_map.json` at `game/data/cue_map.json`; P1 tasks can keep reading them or split data from them.
   `palette.json` sits next to the sprites it describes (`game/assets/sprites/leila/`).
3. **x2, not px** — the brief names `art/leila/x2`; casting.json `art.display` agrees (768×1376 display
   set). With the provisional 384×688 viewport + integer ×2 window (P0.05), an x2 sprite at node scale
   0.5 renders 1:1 texel:pixel. The px/ set stays repo-only (casting keeps both paths).
4. **`leila.gpl` not copied** — GIMP authoring palette, not runtime data.
5. **Python side has no pytest** — no Python test infra exists yet (P0.06/P0.11 own it); `--check`
   mode is the harness until then.
