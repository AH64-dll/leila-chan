### Summary

The human round now has a **runnable kit**: three participant-facing documents (consent, survey,
observer sheet) plus an operator log template; `tools/playtest/session.sh`, which launches the game
on an isolated `user://` profile and tails its own transcript into
`production/playtests/P2/human/<session>/telemetry.jsonl`; `tools/playtest/collect.sh`, which

### Files changed

- `production/playtests/P2/human/RUNBOOK.md` — **new**: the operator manual. Recruiting rules
  (three strangers, 18+, no team, nobody who read the runbook), preflight (backend, build, kit dry
  run, room), the consent script, the verbatim opening and closing lines, an explicit
  what-NOT-to-say table, the 10-minute stop rule, the stuck-turn script and the safety/withdrawal
  procedure, then collect/scoring and the definition of done.
- `production/playtests/P2/human/consent.md` — **new**: participant information + signature block.
  Discloses the AI-generated replies, the horror tone, flashing effects, exactly what is recorded
  (text transcript, survey, timing notes; never audio/video/real name), withdrawal within 14 days,
  and the offline paper copy. Version `consent-v1`.
- `production/playtests/P2/human/survey.md` — **new** template: five 1–5 ratings (Face, Sound,
  Charm, Creepiness, Play again) + `## What felt alive?` / `## What felt off?` / optional
  `## Anything else?`. The table shape is the machine-readable contract for `score.py`.
- `production/playtests/P2/human/obs_sheet.md` — **new** template: timing definitions and a
  required summary table (first-beat latency, longest/total dead air, laughs, discomfort peak, quit
  threat, broken turns, played seconds), an optional per-turn log, verbatim reactions and a
  broken-turn description.
- `production/playtests/P2/human/session_log_template.md` — **new** template: session id,
  participant code, consent + version, date, start/end, build, scenario, facilitator, withdrawal;
  what happened, runbook deviations, teardown checklist.
- `production/playtests/P2/human/.gitignore` — **new**: `**/_userdata/` (the per-session Godot user
  directory: settings, saves, the live transcript the tail reads — machine state, not evidence).
- `tools/playtest/session.sh` — **new**: resolves the build (`$LEILA_PLAYTEST_BUILD` →
  `build/…` → `game/build/…` → `dist/…` → `export/…` → dev run), checks `/health` (skipped when
  `LEILA_OWN_SERVER` is set), creates the bundle, seeds the three templates, exports
  `LEILA_PLAYTEST_SESSION`/`LEILA_PLAYTEST_BUNDLE`, points `XDG_DATA_HOME` at
  `<bundle>/_userdata/`, launches the game, tails the newest `turns_*.jsonl` into `telemetry.jsonl`
  while the game runs, copies `raw/*.jsonl`, finalizes `session.meta.json` on every exit path
  (`ended` / `aborted`), and prints the next three steps. `--check` is the no-launch preflight.
- `tools/playtest/collect.sh` — **new**: seeds missing templates, copies `_userdata` transcripts to
  `raw/`, merges them into `telemetry.jsonl` (dedupe by session/type/turn/event/seq), renders
  `transcript.md`, writes `manifest.json` (bytes + sha256, `complete`, missing list), validates and
  exits 2 naming every incomplete field. Idempotent; `--all` for the whole round.
- `tools/playtest/score.py` — **new**: the single source of truth for the gate. Parses the
  `| Field | value |` tables (normalized keys, exact and all-words lookup), validates every bundle
  (meta ended, ≥1 turn, single transcript session, five ratings in 1–5, two required free-text
  answers, every observer number, consent + consent version + distinct participant code), computes
  pooled Face+Sound mean and broken turns (worst of observer vs telemetry), and writes `RESULT.md`
  with per-session scores, timing, verbatim quotes and `VERDICT: PASS|FAIL`. Incomplete → exit 2 and
  no verdict file; synthetic → refused without `--allow-synthetic`; short/dirty round → exit 2.
  Helper modes `--merge`, `--render`, `--manifest`, `--validate` are what `collect.sh` calls.
- `tools/playtest/tests/test_score.py` — **new**: 14 pytest cases. The three the brief names are
  `test_incomplete_bundle_fails_loudly` (exit 2, no RESULT.md, field named), `test_four_of_five_passes`
  (exit 0, `VERDICT: PASS`), `test_three_of_five_fails` (exit 1, `VERDICT: FAIL`); the rest pin a
  broken turn, missing consent, empty telemetry, the synthetic flag, a duplicate participant code,
  a short round, an empty round, `_dryrun` exclusion, transcript rendering, the committed fixture,
  and the blank-rating lookup regression below.
- `production/playtests/P2/human/_dryrun/` — **new, SYNTHETIC**: `session_1/` (meta with
  `"synthetic": true`, 5-turn telemetry, raw transcript with 2 extra turns so the merge is
  exercised, filled survey/observer/log), generated `transcript.md`, `manifest.json`, `RESULT.md`,
  and `NOT_EVIDENCE.txt`.

### What the project owner must do (the three sessions)

1. **Before the day** — start the backend (`tools/llm/serve.sh`) and confirm
   `curl -s http://127.0.0.1:8089/health` says `{"status":"ok"}`; then run
   `tools/playtest/session.sh --check` (build + server + bundle path) and the kit dry run in
   RUNBOOK §0.4. No export exists in the repo; the dev run is the supported path.
2. **Recruit three strangers** per RUNBOOK §1 (18+, never seen the project, nobody who read the
   runbook), one session each.
3. **Per session**: read `consent.md`, get the signature, run
   `tools/playtest/session.sh --name "<their character name>"`, say the RUNBOOK §4.1 opening
   verbatim, stay quiet (the what-NOT-to-say list is §4.2), stop at 10:00 or the in-game end, then
   say the §4.4 closing and hand them `survey.md`.
4. **After they leave** — fill `obs_sheet.md` and `session_log.md` in the bundle from memory, then
   `tools/playtest/collect.sh <session-id>` and fix whatever it names until it prints `OK`.
5. **Repeat twice.** Then `python3 tools/playtest/score.py`: it writes
   `production/playtests/P2/human/RESULT.md` and exits 0 only on PASS. Commit the three bundles and
   `RESULT.md` together.
6. Read the free text before quoting the number; report a FAIL as the result if that is what the
   three strangers gave — do not re-run a participant to move the mean.

### Deviations from the design bible

- **None.** The gate text is quoted from docs/09 §1 "M1 — Vertical slice" (the brief and the phase
  row cite "§4", which in docs/09 is the decisions list; the criterion itself lives in §1 and that
  is the text implemented). Worth correcting the reference in the task row, not a design change.
- The runbook does **not** promise Esc-pause: the Esc hook exists (`ChatUI.pause_requested`) but
  nothing in the Date/Settings listens to it yet, so the honest instruction is "close the window".
  Consent and runbook say exactly that.
- The scorer's gate is the pooled Face+Sound mean (six values), matching the P1 round-0 survey's
  own arithmetic (`4.92 + 3.95 → 4.44 ≥ 4.0`), plus zero broken turns (worst of observer count and
  telemetry statuses). The rule is printed in every `RESULT.md`.

### Review findings addressed

None — first round. One self-found defect was fixed before handoff and pinned by a test: `lookup()`
treated a bare-string needle as a sequence of characters, so a blank **Charm** row could be
silently filled with the **Face** score (validated as complete). It now normalizes a string to a
one-element needle, and `test_blank_charm_row_is_not_masked_by_the_face_row` fails if it regresses.
