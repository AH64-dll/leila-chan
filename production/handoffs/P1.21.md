### Analysis of Misses & Proposed Follow-Up Tasks

1. **Miss 1: First Beat Latency (< 1.0 s budget vs ~1.85 s CUDA / ~7.52 s host CPU)**
   - **Root Cause (P0 carry-over C8):**
     In the canonical turn schema (docs/02 §3), the JSON object requires the fields in order:
     `{"read": ..., "inner": ..., "music": ..., "fx": ..., "beats": [{"feeling": ..., "intensity": ..., "cue": ..., "say": ...}]}`.
     The first `say` string token is emitted only after ~85 tokens have been generated by the model (the entire `read`, `inner` thought, `music`, `fx`, and initial `beat` metadata). Even at a blazing 42 tokens/sec on RTX 4050 CUDA, generating 85 tokens takes $\approx 2.0$ seconds. Therefore, TTFT alone (~94–391 ms) hits the token stream quickly, but the player sees nothing until `say` starts streaming.
   - **Proposed Fix (Task: P2.xx or P1-refine: Streamed Turn Schema Reordering / Compact Inner):**
     - Option A: Reorder the JSON schema so that `say` or the first `beat` appears before `inner`, or split `inner` into a separate post-turn chain or compact 2-token abbreviation.
     - Option B: If `inner` and `feeling` must precede speech for character sprite and tone selection, permit displaying typing indicator animations during the pre-say window and adjust the design bible first-beat latency budget to distinguish TTFT (< 500 ms) from first spoken phoneme (< 1.8 s).
     - Option C: Restrict `inner` max length from 90 chars down to 30 chars or 5 words during early stages.

2. **Miss 2: Full Turn Latency on CPU Fallback (14.5 s median vs 2–3.5 s target)**
   - **Root Cause:**
     The background process on Linux host runs without complete CUDA offload, generating at ~11 tok/s across 130–190 tokens.
   - **Proposed Fix:**
     - Deploy the CPU "Fast mode" defined in docs/07 §4 (line 175: "offer 'Fast mode' — shorter replies, 1 beat"). Limiting max tokens to 80 tokens on CPU fallback keeps full turns under 4.0 seconds.
