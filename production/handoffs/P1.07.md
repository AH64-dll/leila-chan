# Handoff — P1.07: Turn schema builder with stage gates for cues, music, fx and offered actions (stage 0–1 values for now)

## Round 1 (2026-11-03, agent: gemini-3.8-flash)

### Summary
Built the dynamic Turn schema builder and validator in `game/llm/TurnSchema.gd` (with autoload shim `game/autoload/TurnSchema.gd`) backed by data-driven gate tables in `game/data/stage_gates.json` and canonical feelings in `game/data/casting.json`. The builder compiles the per-turn JSON schema for `llama-server` `json_schema`, enforcing the canonical property order (`read`, `inner`, `beats`, `mood`, `memory`, `action`, `music`, `fx`, `meta`), stage gates across stages 0–5 (with explicit tests for stages 0 and 1), `meta` gated as `null` at stages 0–2 vs unlocked at stage 3+, all 22 canonical feelings, 17 player-intent labels, and C9 non-empty `inner` and `say` constraints. A semantic validation helper (`TurnSchema.validate_turn()`) is provided for the Director pipeline and test suites. 15 gdUnit4 test cases in `game/tests/TurnSchemaTest.gd` verify schema structure, enums, gates, limits, and validations. `bash tools/test.sh` is 100% green (70/70 gdUnit4 tests, 0 failures, lint/format clean).

### Deviations from the design bible
- **Canonical property order and `meta` field:** The brief and task assignment explicitly specified the canonical property order `("read", "inner", "beats", "mood", "memory", "action", "music", "fx", "meta")` with `meta` gated as `{"type": "null"}` at stages 0–2 and unlocked as `{"type": ["object", "null"]}` at stage 3+. `TurnSchema.build_turn_schema` supports this order as default while also allowing `include_meta: false` or custom `property_order` arrays for callers needing the 8-property subset.
- **C9 Non-empty constraints:** Per carry-over C9 from P0 / P1.02 handoff, `inner` and `say` enforce `minLength: 1` in both the compiled JSON schema and `validate_turn()`.
