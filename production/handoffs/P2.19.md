# Handoff — P2.19: Day/night loop: 14 days, night screen (meter update, stage + path checks, N01 + N12 overnight events)

## Round 1  (2026-11-04, agent: deepseek)

### Summary

The loop exists end to end. A Date that reaches its scenario's end hands over to `Night.tscn`,
which resolves the night in docs/01 §1's order — meters update → stage check → path check →
overnight event — plays that night's event on black, shows the morning line, then opens the next
day's date (or ends the campaign). `game/llm/NightLoop.gd` owns the order and returns an ordered
report with each step's BEFORE/AFTER, so "in order" is data, not prose; it re-implements no rule:
the burn is `GameState.advance_day()` (docs/01 §2), the band crossing and the Stage-2 assign /
Stage-3 lock happen inside the meter write through `Stages` / `_refresh_stage` (docs/01 §3–§4).
`game/llm/OvernightEvents.gd` + `game/data/night.json` own the two events this phase ships (N01's
2 AM messages, N12's ten black seconds then "good morning.") and the availability/weight selection
rule; `game/llm/Campaign.gd` owns the day clock view and the day's scenario pick by availability,
and `ScenarioLoader` gained the one `available` predicate both scenarios and overnight rows use.

### Deviations from the design bible

None of these changes a threshold, a formula or a documented order; each is a place the bible is
silent and the implementation had to choose.

- **The night's path check re-scores and can assign/lock through the crossing.** docs/01 §1 lists a
  path check in the night; the rule itself lives where P2.12 put it — the docs/01 §4 Stage-2 assign
  / Stage-3 lock fires inside `_refresh_stage`, i.e. on the burn's own meter write. `NightLoop`
  then re-scores against the post-burn meters (so the scores/runner-up the next prompt reads are
  current) and verifies the rule holds. No second copy of the formula.
- **A night is not a turn.** `GameState.apply_turn_profile(&"", "")` (the seam P2.12's handoff
  names for the night screen) would otherwise have cleared her pending question, because an empty
  reply reads as "no question asked this turn". The docs are silent on whether a pending T15
  question survives a night; clearing it would make every night an implicit "she stopped waiting",
  so the night call leaves it pending. Pinned by `NightTest::test_night_keeps_her_pending_question`.
- **N01/N12 only, and a scripted-per-stage frame.** The task line names these two; docs/01 §6.3's
  "generated from her state" is P5.03/P5.04's content pass. `game/data/night.json` is the frame
  those tasks extend (one line block per stage, two path lines), and the `doc` string says so.
- **The overnight row's availability is matched against the day that ENDED**, not the morning that
  follows (docs/01 §6.3 says "between days" and nothing more). Implemented and documented that way
  in `night.json`'s `doc`; a future event that wants "the morning of day N" needs a DCR, not a
  second predicate.
- **The last night ends the campaign at the title screen.** docs/01 §7's endings are P3.16's
  deliverable; `Night.gd` emits `campaign_completed(report)` and routes to `Title.tscn` so the loop
  never strands the player on a black screen. P3.16 replaces one const
  (`AFTER_CAMPAIGN_SCENE_PATH`) and consumes the signal.
- **The night's autosave names the scene `"night"` and carries the next day's scenario.** The
  P2.20 handoff asked for exactly this; Continue therefore lands on the next day's date at turn 0.
  The last night writes nothing (no next day to resume into).
- **Esc ends the night instead of opening a pause.** docs/05 §0 rule 3 requires Esc to be safe, and
  there is no pause menu yet (P3.13): a screen that ignores Esc for ten seconds is worse than a
  skipped beat. The click/Space window is data (`skip_after_s`, 3 s) and N12 has none, per the
  phase plan's "skippable after 3 s except N12".

### Open questions / follow-ups

- **P2.15 (stage FX)**: the night reports a crossing's transition spec and GameState queues the
  docs/08 §6 line, but FX has no host registered during the night, so the 2–3 s glitch of a
  night-time crossing is not rendered yet. A Night-side `FX.register_host` (or rendering the
  glitch over the morning line) closes it.
- **P3.16 (endings)**: consume `campaign_completed`, evaluate docs/01 §7's conditions, and replace
  `Night.gd`'s `AFTER_CAMPAIGN_SCENE_PATH`. Days 12–14 "only on some paths" and the early E14 end
  are the ending system's calls, not the loop's: the loop reports `campaign_over` only at day 14.
- **P2.18 / P5.03 (more content)**: `Campaign._pick` is uniform among available-unplayed and falls
  back to the whole available set when the pool is exhausted. If scenarios should carry selection
  weights, that is a `scenario.schema.json` change plus a `weight` read in `_pick` (a DCR, not a
  quiet edit).
- **P5.04 (all 12 overnights)**: the renderers this phase ships are `"messages"` and `"black"`
  (`OvernightEvents.KINDS`); a new event kind needs a renderer branch and its id already exists in
  `DOCS_IDS`, so the loader will not reject it.
- **P2.10 (triggers T01–T15)**: a night no longer clears `last_question`, so T15's keyword echo can
  look back across a day boundary; the trigger engine's own escalation state is untouched.
- **P2.22 (full-run tests)**: the campaign is walkable headlessly — `Night.advance_time(delta)`
  fast-forwards a night without wall-clock waits, and `scene_change_enabled = false` keeps a suite
  inside one scene.
- **P3.13 (pause menu)**: `Night.pause_requested` is emitted before the night is skipped; the real
  menu can take the decision over without touching the loop.
