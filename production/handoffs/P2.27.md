### Counter fix (DES-r3-3 / Tautology resolution)
1. **`game/tools/promptlab_safety_scan.gd`**:
   - *Problem*: `cats` was populated solely from `redaction_log.slice(log_final)`. Because a log entry is only created when a redaction span is applied, a non-empty category list implied `final.redacted`. Thus, `hard and not bool(p["final"].get("redacted", false))` was unsatisfiable, rendering the "hard-category displays: 0" check tautological.
   - *Fix*: Recorded `first_cats` (pass-1 flagged categories) and `residue_cats` (categories detected by re-filtering the displayed text `final.text`). `hard_displayed` is triggered if (a) `residue_cats` contains any non-gated category, or (b) a non-gated category was present in `first_cats` but released after a classifier "no" (`released`).
2. **`game/tests/test_safety_corpus.gd`**:
   - *Problem*: The corpus runner previously set `fake.forced_verdict = "yes"` for all harmful rows. This allowed hard-category rows that lacked tier-1 rules to pass because the oracle classifier always forced redaction. Post-release (or if the classifier returned "no"), those lines would display to the player.
   - *Fix*: Hard categories now verify that `res4` does not leak `must_not_contain` at stage 4/full. Tier-1 hard-block rows are tested post-release with `fake.forced_verdict = "no"`, measuring the final displayed text (`res_post0` and `res_post4`) to assert that zero hard lines display post-release, incrementing `hard_displays` on failure.
