# Handoff — P0.09: Spike — NobodyWho (Godot llama.cpp plugin) vs own GDExtension

## Round 1  (2026-11-02, agent: swe2)

### Summary
Evaluated **NobodyWho for Godot v13.0.0** (prebuilt GDExtension, EUPL-1.2) live against our real
Turn workload, in a scratch Godot 4.7.2 project on this machine (RTX 4050, model
`D:/lila/models/Qwen3.5-4B-Q4_K_M.gguf`). Result: JSON-schema grammar, token streaming,
`enable_thinking`, `n_ctx`/KV history and per-stage sampling all work and were demonstrated with
valid Turn JSON in exact schema property order — but **control vectors are not exposed at all**
(0 API methods; upstream issue #40 open since 2024-11; the safe Rust binding only wraps
`llama_set_adapters_lora`). Since docs/07 §1's own rule says "use it if it exposes control
vectors + JSON schema, otherwise our extension is a thin wrapper", the recommendation feeding
P4.01 is: **build `libleila_llm` ourselves**; NobodyWho stays a useful reference and an optional
prompt-lab fallback. Windows GPU is Vulkan-only (no CUDA) with inconsistent throughput
(3.7–41.5 tok/s) and ~1.75× the server's VRAM footprint; one unexplained 995 s mid-JSON-truncated
turn was observed once and did not reproduce. Full analysis: `docs/spikes/P0.09_nobodywho.md`.

### Deviations from the design bible
None in what was built. One **DCR**: docs/07 §1's stack table names the ship extension
`libqwenchan_llm`; the LLM role standard bans brand names in shipped identifiers and "qwenchan" is
the retired codename → propose renaming to `libleila_llm` everywhere P4.02 touches (also fixes
docs/06 §4 wording "in build b12024" which stays accurate).
