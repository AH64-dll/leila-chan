# Handoff — P1.29: P1.04 round-2 state hardening: landed mood budget and strict snapshot/flag invariants

## Round 2  (2026-11-03, agent: deepseek)

### Summary

`GameState.gd` now enforces every round-2 review edge instead of documenting it. The per-turn mood
budget charges *landed* movement rather than the signed suggestion, so unlanded suggestions at a
meter boundary cannot free budget in the opposite direction; `version` alone can no longer reset a
save; `instability_peak` is bounded on direct writes; flag validation rejects non-finite floats and
cyclic/over-deep containers without recursing to a stack overflow; a load sets the final stage
before the meters so no intermediate stage transition is emitted; and a successful load's single
`state_reset` is now asserted. Two additional choke points found by my own adversarial probing were
closed on the way: non-finite floats can no longer enter any meter (through a snapshot or a mood
dictionary), and a mid-turn ratchet lift is never billed to the model's per-turn allowance.

### Adversarial probe (scratchpad, not committed)

400 randomised trials mixing `apply_mood()`, game-side `adjust_meter()` spikes, raw
`instability_peak` writes + meter writes and `apply_slow_burn()` — 6 steps each, one turn:

```text
$ ./tools/godot.sh --headless --path game --script <scratchpad>/probe4.gd
finite=0 floor=0 range=0 budget=0 move=0 json=0
```

Every counter is a violation count: no non-finite meter or peak, no instability below the ratchet
floor after a meter write, no meter outside its range, no budget above the ±cap, no model-only
affection movement above ±5 in one turn, and every snapshot round-trips through `JSON.stringify` +
`JSON.parse_string`. An earlier revision of the same probe (which poked `instability_peak` without
a following meter write) reported 268 "floor" hits; that is the documented semantics — a raw peak
write is a high-water-mark raise, and the floor is enforced on the next meter write, exactly as
`from_dict()` and `adjust_meter()` do. The probe was corrected to assert the invariant on real write
paths, not to change the rule.

### Deviations from the design bible

None. The round-2 work is defensive hardening of paths the bible does not specify (corrupt saves,
non-finite input, direct field writes). The docs/01 §2 formulas and the docs/01 §3 stage bands are
untouched: `test_apply_mood_scales_and_clamps`, `test_slow_burn_turn_and_daily` and
`test_stage_bands_monotonic_and_signal` still pin them.

Two judgement calls, both flagged in the journal:

- **Non-finite writes are dropped, not clamped.** `INF` would "clamp" to a range bound the caller
  never asked for, and `NAN` has no meaningful bound at all (`clampf()` passes it through, which is
  how a NAN could reach a meter before this round). Dropping keeps the meter's last finite value and
  pushes a warning. Flag values are still rejected outright, per docs/07 §3.5's JSON-safe contract.
- **The per-turn budget charges only model-caused movement.** A game-side correction (the ratchet
  floor after a mid-turn peak write) is not the model's move, so it is not billed to the docs/01 §2
  allowance. Without this, a peak write mid-turn could drain the allowance and let a later
  same-sign suggestion drag instability backwards.

### Open questions / follow-ups

- **P2.12 (paths):** `assign_path()`/`lock_path()` still do not enforce the docs/01 §4 stage-2/stage-3
  gates (DES-6 from the P1.04 design review, S4, caller-owned). The state API keeps the caller's
  authority; P2.12 must gate on `stage`.
- **P2.20 (saves):** `from_dict()` is instance-independent and rejects non-snapshot input; a save
  file that has been truncated to metadata only is now rejected rather than silently resetting.
  `state_reset` fires exactly once per successful load.
- **P2.01/P2.02 (tuning):** `STAGE_BANDS`, `RATCHET_DROP`, `SLOW_BURN_*` and the two suggestion caps
  are still code constants; moving them into `game/data/` remains the natural P2.02 step.
- **P1.17 (overlay):** connect `state_reset` for the wholesale resync; a load now emits a single
  `stage_changed`, so a transition animation will not flash an intermediate stage.
- **P1.08 (Director):** `apply_mood()` may be called more than once per turn, but the budget is
  shared per turn and `advance_turn()` resets it — the documented call order
  (`advance_turn()` → `apply_slow_burn()` → `apply_mood()` → `apply_read()`) stays the safe one.
