### Deviations from the design bible
None. The formulas, the scales, the caps, the ranges and the daily burn are the doc numbers; no value
was retuned.

Design interpretations (docs are silent; each is one line to flip if a reviewer disagrees):
- **The formula values are data with a doc-pinned test.** The SYS playbook wants tunables in data and
  the same playbook wants the formula as written, so `meters.json` holds the numbers and both
  `MetersTest.test_data_table_matches_docs` and `tests/test_meters.py` fail if they stop matching
  docs/01 §2 / docs/02 §1.1. Changing one is a DCR + a test update, never a quiet edit.
- **A peak write now lifts Instability to the floor.** docs/01 §2 defines the floor; it does not say
  what a direct peak write does. Before, `instability_peak = 90` on a live meter of 20 left
  instability (20) below its new floor (75) until the next meter write. The peak setter now lifts the
  meter, so the invariant holds after every write, not just the next one. Lowering the peak never
  lowers the meter.
- **`apply_mood()` returns the landed deltas and `advance_day()` returns the landed burn** (previously
  `void`). Additive for every existing caller; the values feed the ledger and the night screen.
- **`TurnContext.meters()` gained three keys** (`instability_peak`, `instability_floor`, `slow_burn`).
  Additive; the five doc meters keep their names.
- **Stage bands stay in `GameState.STAGE_BANDS`.** P2.02 owns "thresholds from data"; moving them now
  would collide with that task. `Meters` deliberately covers only the P2.01 formula.
- **The simulation's player model is scenario input, not a game rule.** Fixation/Lucidity drift and
  the read/mood mix live in `game/tools/meters_sim.gd` constants; P2.08/P2.12 will own the real
  drivers. The CSV records the real state, ledger and daily burn.
- **`meters_curve.csv` column `instability_pre`** exists so `tests/test_meters.py` can prove the burn
  equals the formula clipped by the ceiling at the time it ran.

### Open questions / follow-ups
- **P2.02** should move `STAGE_BANDS` into `data/stages.json` and keep using
  `GameState.apply_turn_meters()` as the only per-turn entry point.
- **P2.19** night screen: `advance_day()` now returns the landed burn (0 at the day cap) for display;
  `Director.last_meter_ledger` has the last turn's slow burn + mood deltas.
- **P2.08** triggers keep using `adjust_meter(&"instability", spike)` — spikes stack on the slow burn
  exactly as before, and the ratchet applies to them too.
- If design wants non-zero starting meters (all start at 0), that is still a one-line `reset()` change
  (unchanged from P1.04).
