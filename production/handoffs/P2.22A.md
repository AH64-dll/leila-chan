# Handoff — P2.22A: wire the three seams the P2.22 playtest found dead (S1-1/S1-2/S1-3)

## Round 1 (2026-11-04, agent: commandcode)

### Summary
The shipped Boot → Title → NewGame/Continue → Date flow now drives the date itself. `Date.auto_start`
defaults to **true**, so the scene that a real entry builds starts its own date: greeting beats, the
music request, the scene-entry autosave, the turn counter restored from a save, and the `end` rule that
finally fires. `Date._on_player_turn_sent` now calls `Director.submit_player_input`, so a typed line opens
a turn instead of only moving a counter — and the date's counter now follows the Director's, so a
Safety-refused line spends neither a date turn nor an `events[].at_turn` (docs/02 §4 step 0). The Date
also installs `Director.scene_info` before each submit with `ScenarioLoader.resolve_scene(...)` — the
loaded scenario's goal, prompt, stage/path variant and the turn's scheduled `events` line — clearing it
when the date ends or the scene leaves; the Director's hard-coded café sentence is gone.

All three wires were previously installed by the P2.22 playtest driver (`game/tools/full_run_driver.gd`,
branch `task/P2.22`), which is exactly why the gap survived a milestone. `game/tests/DateFlowWiringTest.gd`
(new, 5 cases) now proves each seam from the production scene, and the suites that host a Date by hand say
`auto_start = false` out loud. The duplicate bridges in `DirectorFallbackTest` and `SaveFlowTest` were
deleted (clean cutover: one submit point, one scene layer writer).

### Deviations from the design bible
None. Two decisions worth a reviewer's attention, neither a DCR:

1. **`Director.scene_info` defaults to `{}` now.** docs/08 §1 defines `[scene]` as
   "scenario.prompt + current event" (with §7 adding `goal` and the stage/path variant), i.e. the layer is
   owned by the scenario. The old constructor value was a café sentence no document describes; leaving it
   as a fallback would let a turn outside a date roleplay a place the game is not in. Empty renders no
   scene layer (`PromptBuilder._scene_layer` returns `""` for an empty dict), and there is no shipped turn
   outside a Date, so nothing the player can reach loses the layer. `Director.reset()` also clears it, so a
   New Game cannot inherit the date a session ended in.
2. **The Date starts itself in `_ready`, as `Night.gd` already does** (`start_night()` in `_ready`, with a
   `_started` guard). docs/07 §2 describes the Date as the scene that "integrates ScenarioLoader", and every
   real entry uses `change_scene_to_file`, which cannot pass an export — so "started by a caller" is
   unreachable by construction. `auto_start` survives as the tools/suites opt-out; it is now set **before**
   the node enters the tree, which is the only moment it can take effect.
3. **The date's turn counter now advances only when the Director accepts the line.** It used to increment
   on every submit. docs/02 §4 step 0 says a Safety-refused line "never opens a turn", and the Director
   keeps its own history and `GameState.turn` untouched for it — the Date disagreeing meant a refusal spent
   a date turn, and with the new `at_turn` binding it would also have spent a scheduled event and walked
   `max_turns` down. `DateFlowWiringTest` case 4 pins both halves. No doc change: this is the Director's
   documented rule applied to the counter that names its turns.

### Open questions / follow-ups
1. **`Date.start_date()` is deliberately not idempotent.** `DateSceneTest.test_capture_screenshots_for_handoff`
   calls it twice (stage 0 then stage 1) to capture both baselines, so a `_started` guard like
   `Night.start_night()`'s would delete that P1.16 evidence. Consequence for tool authors: a host of a
   self-starting Date must **not** call `start_date()` again (double greeting; `_current_turn` resets to
   `_saved_turn`, which is 0 after the first start). If a later task wants the guard, it must first replace
   that screenshot test's re-entry with two scenes.
2. **The P2.22 driver still carries its own copies** (`game/tools/full_run_driver.gd` on `task/P2.22`). Its
   owner reports them inert after this branch: `start_date()` is called only when `auto_start` is false, and
   `_submit_to_director` returns while `Director.is_busy()` (true because the Date submits first), so the
   remaining `player_turn_sent` bridge and `Director.scene_info` assignment are no-ops. They should still be
   **deleted** when `task/P2.22` lands — a second copy of a production seam is what caused this ticket. No
   change made here (that worktree/branch belongs to P2.22).
3. Not in this ticket (same report, still open): S2-1 Fixation/Lucidity writers and E12, S2-2 the slow burn's
   speed, S3-1 stage-dose binding, S3-2 the model never using an offered action, S3-3 turn latency. Each has a
   proposed role in the report; S2-1 and S3-1 are SYS-sized tickets of their own.
4. `_exit_tree` clears the scene layer unconditionally. With two Date scenes alive at once (a test-only
   state) the leaving one clears what the other may have set. The shipped game has one live Date at a time
   and the field is prompt input, not shared state, so no identity guard was added — unlike the ChatUI
   registration, a stale value here cannot crash anything.
