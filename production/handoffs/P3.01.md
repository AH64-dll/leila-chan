# Handoff — P3.01: Residual-dump tool (llama.cpp eval callback, option b): per-layer activations for a prompt set → .npy

## Round 1  (2026-11-04, agent: swe-2)

### Summary
`tools/steering/` now holds the residual-dump toolchain. `dump_residuals.cpp` builds
`llama-dump-residuals`, which runs a chat-templated prompt set through the pinned
Qwen3.5-4B GGUF and captures every per-layer residual output (`l_out-<il>`, the tensor
*after* the control vector is applied at that layer) via the public
`llama_context_params.cb_eval` hook — no llama.cpp patch, no weights download
(docs/06 §2 option b). Output is `prompt_NNN.npy`, float32
`(n_layers, n_tokens, n_embd)`, row 0 = `--layers` low bound. `check_malice.py`
verifies the dumps against the known malice direction by projecting onto
`direction.13/14` of `evil_qwen_unit.gguf` and comparing base vs steered runs.

The llama.cpp source at b12024 (commit `ddf48f85c`) was fetched into the main tree's
`tools/llama/llama.cpp` (gitignored local artifact, same class as `llama-b12024/`).
This machine is Linux, so the tool was **built and run on Linux**; the same cmake
commands work on Windows/MSVC (note in acceptance table).

### Files changed
- `tools/steering/dump_residuals.cpp` — the tool: jinja chat template via
  `common_chat_templates_apply` (thinking off, same as `llama-server --jinja`
  `enable_thinking=false`), one user prompt per line, KV cleared per prompt,
  `cb_eval` copies `l_out-<il>` after each graph compute (accumulates ubatches
  >512 tokens), `.npy` v1.0 writer, optional `--cvec F:SCALE` through
  `common_control_vector_load` + `llama_set_adapter_cvec` (same path the server uses).
- `tools/steering/CMakeLists.txt` — `add_subdirectory(llama.cpp)` build;
  `-DLLAMA_DIR=` override (defaults to `<repo>/tools/llama/llama.cpp`).
- `tools/steering/check_malice.py` — sanity checker (finite/degenerate per layer,
  projection onto each `direction.*`, optional steered-vs-base dose-shift check).
- `tools/steering/prompts/probe_v1.txt` — 10-prompt probe set (game register:
  affection, jealousy, rejection, fear, neutral probes).
- `tools/steering/prompts/persona_stage0.txt` — stage-0 persona system prompt.
- `tools/steering/README.md`, `tools/steering/.gitignore` — build/run docs; build dir ignored.
- `experiments/steering/2026-11-04_dump_p301.json` — experiment record (model+cvec
  sha256, config, results; method standard).
- `.gitignore` — ignore `experiments/steering/dumps_*/` (~204 MB of .npy, regenerable).

### How to verify (copy-paste)
```bash
# needs: main tree at ../lila with tools/llama/llama.cpp (b12024 source) and
# models/Qwen3.5-4B-Q4_K_M.gguf; pip install -r requirements-experiments.txt
MAIN="/run/media/amrhares/New Volume/lila"   # adjust to your main tree
cmake -S tools/steering -B tools/steering/build -DCMAKE_BUILD_TYPE=Release \
      -DLLAMA_DIR="$MAIN/tools/llama/llama.cpp"
cmake --build tools/steering/build -j

LD_LIBRARY_PATH=tools/steering/build/bin ./tools/steering/build/llama-dump-residuals \
    -m "$MAIN/models/Qwen3.5-4B-Q4_K_M.gguf" \
    --prompts tools/steering/prompts/probe_v1.txt \
    --system tools/steering/prompts/persona_stage0.txt \
    --out-dir experiments/steering/dumps_p301/base --layers 10-20 --threads 8
# same again with: --out-dir .../malice8 --cvec "$MAIN/experiments/steering/evil_qwen_unit.gguf:8"
python3 tools/steering/check_malice.py experiments/steering/dumps_p301/base \
    experiments/steering/dumps_p301/malice8 \
    --cvec "$MAIN/experiments/steering/evil_qwen_unit.gguf" --scale 8
```

### Deviations from the design bible
None. Layer-note worth recording (not a deviation): `direction.N` in the cvec file
applies to `l_out-N` directly — 0-indexed block N, matching `steer_build.py`.
The dump captures `l_out` *after* the cvec add, which is what the dose-shift check
exploits. For mean-activation-difference vectors (P3.03) that is the same residual
the path vectors will steer, so no post-hoc correction is needed.
