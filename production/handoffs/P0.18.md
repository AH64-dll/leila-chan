# Handoff — P0.18: P0.15 review carry-overs: streamed gdUnit4 transcript, JUnit-based zero-suite guard, handoff excerpt label

## Round 1  (2026-11-02, agent: swe2)

### Summary
All three P0.15 code-review carry-overs are resolved. The gdUnit4 stage no longer buffers the
whole transcript in a variable: both runners now `tee`-stream it — live to the console **and**
into `game/reports/gdunit_console.log`, so a hung suite leaves its partial transcript behind
(demonstrated below with a real `while true` suite killed at 90 s: 2432 bytes, including the
`STARTED` line). The zero-suite guard no longer greps gdUnit4's console text at all: it asserts
on the JUnit artifact — `game/reports` is wiped before the run, and the run must produce a
`report_*/results.xml` whose `<testsuites tests="N">` is >0. This is strictly decoupled from
message wording *and* fails red (never green) if a future gdUnit4 stops writing the report —
the zero-case path in `GdUnitTestCIRunner.gd:393-397` quits before any session/report exists.
Finally, the P0.15 handoff's `excerpt, otherwise verbatim` label now names the elided blocks.

Design note: **streaming chosen over a timeout** (the finding said "a timeout *or* streaming").
Streaming restores the pre-P0.15 behavior — and exceeds it, since the transcript also lands in
a durable gitignored file that CI already uploads (`Upload gdUnit4 reports on failure` in
`.github/workflows/ci.yml` picks up `game/reports/`). A wall-clock limit stays CI's job.

One PS-specific refinement while implementing: `Tee-Object -FilePath` in Windows PowerShell
5.1 writes **UTF-16LE** (verified — the file read as `S c a n n i n g` under byte tools), so the
ps1 runner tees through an auto-flushing `System.IO.StreamWriter` instead → UTF-8 log, same as
bash, still streaming live and flushed per line even on a kill.
