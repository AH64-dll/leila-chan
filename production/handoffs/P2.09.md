# Handoff — P2.09: Input & window telemetry: deleted drafts, focus loss during her line, close request, idle 60 s, resize, screenshot key, repeated message

## Round 1  (2026-11-04, agent: commandcode)

### Summary
`Telemetry.gd` (new autoload) is the docs/01 §5 "E" seam: seven detectors (deleted draft, focus
loss during her line, close request, idle 60 s, resize, screenshot key, repeated message) normalize
to one engine-event shape `{trigger, event, stage_min, line, data, seq, ts}` and hand it to `Triggers`
in real time, while queueing the docs/08 §6 `EVENT:` line for the next turn. The Director drains that
queue at docs/02 §4 step 0 through the new `InputHook` helper, so the line reaches `ctx["events"]` →
PromptBuilder. The catalogue lives in `game/data/telemetry.json` (docs fallback in code). ChatUI
forwards the InputBox draft signals and her turn-open state, Date scopes detection to an active date,
and the F3 overlay gained a TELEMETRY section with one test button per event.

Two P1.08 bugs surfaced and are fixed: `submit_player_input()` cleared `_turn_events` *after* the
step-0 hooks, so no telemetry/trigger line had ever reached a prompt; and the deleted draft was
written into a text-valued `t08_deleted_draft` GameState flag, i.e. into every save snapshot. The
draft now lives only in Telemetry memory, is quoted once at the docs/05 M21 stage (≥ 3), then
cleared; the dev transcript is scrubbed with the exact words before it is written.

### Deviations from the design bible
- **Interpretation (docs/01 §5 vs docs/05 §1.3 gates):** the T-rows list no stage gates while the
  M-rows do (M19/M20/M30 = St 2/1/2, M21 = St 1, M01 = St 3). Detection is deliberately ungated so
  the trigger engine can count every fact (P2.08 owns caps/escalation); `stage_min` in
  `data/telemetry.json` gates only when she may *react*, using the docs/05 gate. No bible conflict —
  but the two tables should be read together. No doc change requested.
- **DCR (docs/07 §2): the autoload ring is now 15.** The layout/section says "the 14 autoloads
  register in the doc order above". This task adds a session-wide engine-event seam, which belongs
  with the other services rather than inside `Date`, so `Telemetry` registers last (it is a leaf
  observer; nothing at boot depends on it). Proposed doc text: add `│  ├─ Telemetry.gd        # input &
  window engine events (docs/01 §5 E, docs/05 §1.3)` after `Settings.gd`, change "14 autoloads" to
  "15 autoloads", and list `llm/InputHook.gd` plus `data/telemetry.json` in the tree. Impact: the
  doc tree only; `Boot.EXPECTED_AUTOLOADS` and `AutoloadRingTest` are updated in this branch.
- **Deleted-draft privacy vs the dev transcript (docs/07 §5):** the M21 quote is player text inside
  the prompt, and the P1.18 dev transcript persists prompts. To keep docs/05 §0's "memory only"
  literal, `Director._log_turn_record()` scrubs the exact draft words out of the record copy before
  the logger writes it (`Director.gd:913-919`, `InputHook.scrub`). The transcript keeps
  `[deleted draft]`. The local model still receives the real words once — that is how she quotes
  them — but nothing on disk does.

### Role playbook checklist (docs/05 §0, one line each)
- **Window and `user://` only:** no OS calls, no files; the only write is the pre-existing
  `user://debug` transcript, and the draft is scrubbed from it.
- **Closing always works:** `auto_accept_quit` is never touched (asserted in
  `test_screenshot_key_and_window_signals_are_wired`); only the request is observed, P2.10's M01
  intercept owns the once-per-session behaviour.
- **Esc → safe pause:** `Telemetry._input` never calls `set_input_as_handled`; UI tests still pass.
- **Fake dialogs / deep OS tricks:** none added.
- **Deleted draft memory-only:** proven by the two privacy tests above.
- **Safety before display:** this task displays no model text. The dry run's only text surfaces are
  authored data (`telemetry.json`) and the deleted draft inside a prompt; the draft quote is inside
  the system message, never a `say`.
- **Photosensitive / reduced motion:** no visual effect is added (events only; the F3 panel is a dev
  overlay). Nothing to honour yet.
- **F3 triggerable + caps:** every catalogue row has an overlay button (`test_f3_overlay_fires_every_event`);
  prompt caps are one pending line per event kind per turn, idle is once per stretch, resize one per
  cooldown, screenshot one per cooldown.
