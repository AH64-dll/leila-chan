# Handoff — P1.24: P0 gate C3: bound CI job runtime

## Round 1  (2026-11-02, agent: swe2)

### Summary
Every CI job now carries an explicit `timeout-minutes`: the single `checks` job in
`.github/workflows/ci.yml` is bounded at 15 minutes (P0.07 CODE-3's suggested value; observed
end-to-end run is ~15–30 s including the ~50 MB Godot download, so ~30x headroom against a
stalled `curl`/`godot --import` without any flaky-trip risk). A new pytest policy test,
`tests/test_ci_workflow.py`, parses every workflow YAML and asserts each job has a sane
`timeout-minutes` (int, 1..360 — 360 being GitHub's own hard cap), so the gate criterion is
mechanically enforced and re-verifiable. `PyYAML==6.0.3` is now declared in
`requirements-dev.txt` (previously only a transitive gdtoolkit dep).

### Files changed
- `.github/workflows/ci.yml` — `timeout-minutes: 15` on the `checks` job + a comment recording the bound's rationale (C3) and the observed-runtime basis.
- `tests/test_ci_workflow.py` — new: parses every `.github/workflows/*.yml`; asserts each job's `timeout-minutes` exists, is an int (bool rejected), and is within 1..360. Written as the scaffold P1.25 (gate C4) extends for `persist-credentials: false`.
