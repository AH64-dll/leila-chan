# Handoff — P3.16: Endings system: condition evaluation, ending scene, ending log, Extras unlocks

## Round 1  (2026-11-04, agent: deepseek)

### Summary

The endings system exists end to end. `game/data/endings.json` is docs/01 §7's fourteen rows
plus the secret as a data table (id, name, path, a declarative condition, a selection priority,
when it may fire, and the per-path fallback the bible is silent about); `game/llm/Endings.gd`
evaluates it purely from a GameState snapshot and never from live instance state, so a replayed
run cannot drift; `game/llm/EndingLog.gd` keeps `user://endings.json`, the cross-run record and
the Extras unlock store, beside the saves. `Ending.tscn` renders the run's ending (name from the
data, path/day/stage from the run, the row's `frame` slot, the visit's place in the log), writes
the log exactly once per run, stamps `ending_id` in GameState.flags (so a save carries it) and
autosaves itself as scene `ending` (so Continue returns to the ending, not to a date that is
over). `Extras.tscn` is the after-a-run gallery: every ending, names hidden until reached, and
the secret row whose "play all six paths" rule is its own data. The loop hands over to it from
the campaign's last night, from any night an `any_time` ending is due, and from a Date turn close
(E14's early burnout). The F3 overlay gained an ENDINGS section with one button per row; each
click runs `Endings.force()`, which builds a state that *satisfies* the row and lets the evaluator
pick it, then opens the ending screen — the button demonstrates the rule rather than bypassing it.

### Files changed

- `game/data/endings.json` — NEW: docs/01 §7's 14 rows + `SECRET` ("Weights"), the condition
  vocabulary, the per-path fallbacks, and a `doc` string that records every encoding decision.
  `frame` is absent on purpose: it is P3.17's content slot (the screen renders it when present).
- `game/llm/Endings.gd` — NEW: table load/validate (invalid rows drop with a problem), the
  condition evaluator, the priority selection (`priority` ascending, file order on ties), the
  phase model (`campaign_end` vs `any_time`), the per-path fallback, `secret_available()`,
  `describe()`, `satisfying_state()` and the dev-tool `force()`.
- `game/llm/EndingLog.gd` — NEW: `user://endings.json` (versioned, atomic write, tolerant read,
  unknown ids preserved), per-ending count/first/last seen/run day+stage/path, `seen_paths()`,
  `any_seen()`, `wipe()`, injectable path and clock. Privacy (docs/05 §0 rule 5): the file holds
  an ending id, its path, the run's day/stage and two wall-clock timestamps — no player text, no
  name, no OS data — and it never leaves `user://`. `wipe()` is the "Reset Everything" hook.
- `game/scenes/Ending.gd`, `game/scenes/Ending.tscn` — NEW: the ending screen. Data-driven
  reveal (`advance_time`, `line_interval_s`, `skip_after_s`), one log write per run, the ending
  autosave, Esc → Title (docs/05 §0 rule 3).
- `game/scenes/Extras.gd`, `game/scenes/Extras.tscn` — NEW: the Extras gallery; locked rows hide
  names, progress line, secret row gated by the log's path history; Back/Esc → Title.
- `game/autoload/SaveSystem.gd` — `SCENE_ENDING` ("ending").
- `game/scenes/Night.gd` — the last night (and any night an `any_time` ending is due) reports the
  decision in the night report, suppresses the morning line and the next-day queue, and routes to
  `Ending.tscn` instead of `Title.tscn` (the P2.19 seam).
- `game/scenes/Date.gd` — `ending_reached` + `_check_ending()`: E14's early burnout ends the run
  at the turn close, before the night (runs before the scenario-end check; `_date_over` makes the
  two mutually exclusive).
- `game/scenes/Title.gd`, `game/scenes/Title.tscn` — the Extras row (greyed until the log has an
  ending, docs/05 §3), and Continue routes by the loaded save's scene id so an ending save
  resumes on the ending screen.
- `game/scenes/debug/DebugOverlay.gd` — the ENDINGS section (one button per row, reached/log/paths
  line) and the `Endings.force()` click path.
- `game/data/ui.json`, `game/scenes/ui/UiConfig.gd` — `title.btn_extras` and the `ending` /
  `extras` string blocks (reveal timing included), mirrored in `DEFAULTS` as `UITest` requires.
- `game/tests/EndingsTest.gd`, `EndingLogTest.gd`, `EndingSceneTest.gd`, `ExtrasSceneTest.gd` —
  NEW suites (39 cases); `NightSceneTest.gd` +1 (the last night carries the ending),
  `DateSceneTest.gd` +1 (the early burnout ends the date).
- `tests/test_endings.py` — NEW: the data pin (docs table, numbers, vocabulary, fallbacks, secret,
  sensitivity/brand scan, UI strings).

### Deviations from the design bible

docs/01 §7 is the source. Two kinds of deviation, both implemented as **data** so retuning is an
edit, and both DCR'd for the producer:

1. **Per-path fallbacks (docs/01 §7 is silent).** The table gives every ending a condition but no
   row for the run that satisfies none of them, and a campaign must still end. `defaults` names one
   fallback per path (YANDERE→E01, SPLIT→E04, TSUN→E06, HOLLOW→E08, AWAKE→E10, ANCHOR→E12) plus
   `any`→E14 for a pathless state, and the decision's `reason` says `"default"` so it is visible to
   the overlay and the log. Proposed doc text for §7: *"Each path names one fallback ending
   (E01/E04/E06/E08/E10/E12); it is chosen only when no condition matches."*
2. **Numbers the bible does not state.** E01's 80, E12's 70@Day 14 and E14's 100-before-7 are the
   doc's and pinned. The rest needed one game-vocabulary proxy each, recorded in `endings.json`:
   E02 `leaving_talk ≥ 1`; E03 `boundaries ≥ 3` and `day ≥ 10` ("late"); E04 `instability ≥ 95`
   plus `broken_promises ≥ 1` (the complement of E05's "kept every promise", so SPLIT's two rows
   partition); E07 `lucidity ≥ 70` at stage ≥ 4 ("at Collapse"); E09 `ignored_questions ≥ 3`;
   E11 `flags.agreed_to_delete` (set by the P5.06 Terminal set-piece; unreachable until then, and
   forceable from F3 today); E13 `leaving_talk ≥ 1`. Proposed doc text: the table gains a
   "Condition (data)" column with these clauses; the *prose* stays as it is, this is the encoding.
3. **`at` (when a row may fire).** docs/01 §7 mixes "at Terminal", "at Collapse" and "at Day 14"
   with E14's "before Day 7". Implemented as `campaign_end` (the last night) vs `any_time`
   (checked at every turn close and every night); E14 is the only `any_time` row and the lowest
   priority, so it outranks a path row when both could match. No doc change needed; this is the
   reading of §7's two kinds of condition.
4. **Save layout.** docs/07 §3.5 lists the `user://` files; the log adds `user://endings.json`.
   Proposed addition to §3.5's list, and a note that Settings → "Reset Everything" deletes it like
   the rest of `user://` except `settings.cfg` (P3.12 owns the wipe; `EndingLog.wipe()` is the
   hook).

Nothing weakens a safety rule, the content warning or "closing always works": the ending screen
never intercepts a close, Esc leaves it for the Title (the P2.19 night precedent, docs/05 §0 rule 3),
and the only prose it shows is data.

### Open questions / follow-ups

- **P3.17 (NAR)** fills the `frame` slot per row; `Ending.gd` already renders it
  (`EndingSceneTest::test_a_row_frame_renders_when_the_data_has_one` proves it needs no code).
- **P5.06 (SYS)** must set `flags.agreed_to_delete` at the AWAKE Terminal set-piece for E11, and
  P5.08 owns the secret's in-run trigger (the 7th New Game). P3.16 gates the secret's *Extras*
  unlock only (`requires.paths`).
- **P3.12 (SYS)** should call `EndingLog.wipe()` (or sweep `user://` minus `settings.cfg`);
  `EndingLogTest::test_wipe_removes_the_file_and_the_cache` covers the seam.
- **P3.09–P3.11 (META)**: docs/05 §3 also puts the meta-event list in Extras; the screen is the
  host for that section once the event log exists.
- **P5.19 (SYS) balance**: the invented thresholds above are playable but untuned; they are data,
  and `tests/test_endings.py` pins only the doc's own numbers, so retuning the rest does not touch
  a test.
- **Campaign length**: docs/01 §1 says days 12–14 "only exist on some paths"; the loop ends every
  run at day 14 (P2.19's model). The ending table does not depend on a shortened run, but the
  "eight endings reachable" acceptance (P5.07) may add day limits per path.
