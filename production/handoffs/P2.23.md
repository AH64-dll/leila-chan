# Handoff — P2.23: F1 controller wiring — `Director.chat_ui_node` registration

## Round 1  (2026-11-04, agent: commandcode)

### Summary

The shipped Date scene now registers its ChatUI with the Director:
`Date._ready()` calls `Director.register_chat_ui(chat_ui)` beside the rest of its ChatUI wiring, and
`Date._exit_tree()` clears the registration (its own node, or a registration that already points at a
freed node) so the autoload never holds a freed scene node. P1.31's rejection release is therefore live in
the real scene, not only in tests.

The P1.31 regression tests now take their ChatUI from `Date.tscn` instead of registering a bare
`ChatUI.tscn` themselves: they drive the shipped Director→ChatUI path, and assert the registration is the
scene's before the rejection. Removing the one call in `Date.gd` turns both tests red (mutation run below),
so the tests no longer pass over a silently skipped `has_method` guard.

Scene-owned, not an autoload hookup: `Date.tscn` is the only scene that instantiates `ChatUI.tscn`
(`game/scenes/Date.tscn:45`); an autoload-side group lookup would add a second wiring path and a
frame-order dependency for one call in the node that already owns the instance. `register_chat_ui` still
installs no `text_filter` — the P1.19 CODE-1 single-scan seam is unchanged.

### Open questions / follow-ups

- **F1 is only half-closed.** The shipped Date scene still never calls `Director.submit_player_input`:
  `Date._on_player_turn_sent` (`game/scenes/Date.gd:328-330`) counts the submission and re-emits, so a
  player line can still not start a model turn. Propose a SYS task: "F1 controller: connect
  `ChatUI.player_turn_sent` → `Director.submit_player_input`, drive the scene's turn counter from
  `turn_completed`". The registration this task adds is now in place for it.
- `Date._current_turn` still counts submissions rather than completed turns (P1.31 handoff note); move it
  onto `turn_completed` (or `GameState.turn`) with the controller task so scenario `max_turns` is not spent
  on refusals.
- No `push_warning` was added for the no-UI rejection path (P1.31 CODE-4 offered that as the "at minimum"
  variant). `DirectorTest.test_step_0_input_safety_rejection` deliberately rejects a line with no UI
  registered, so a warning there would be a new headless warning for an intended path; with the scene
  registration and the re-pointed rejection tests, a missing registration is a red test instead.
