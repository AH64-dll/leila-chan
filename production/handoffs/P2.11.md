### Deviations from the design bible

No rule was changed; three implementation readings, each in the direction the doc's own wording points:

1. **Rule 1's "content word" excludes stop words.** Before this task the rule was a "longer than 2
   characters" floor, which let a shared `the`/`is` ground a wholly invented fact. docs/02 §6 says
   *content* word, so the stop list (in `memory.json`) is the faithful reading of the same sentence.
   Guarded by `test_rule1_does_not_ground_on_a_stop_word`; the benign few-shot fact
   (`gave me a music box`, P1.05 CON-2) still stores.
2. **Corruption is applied per prompt *injection*, not stored.** docs/02 §6 says "when memories are
   injected into the prompt, 10–25% are subtly altered", so the true fact stays in the store and is read
   accurately on one turn and wrongly on the next. A retry (`docs/02 §7`) is a new injection and may show
   a different variant.
3. **Eviction tie-break is age.** "oldest low-importance evicted" is read as (lowest importance, then
   oldest), so a frequently-quoted fact survives a wave of new ones — `test_store_holds_24_slots…` pins
   both halves.

### Open questions / follow-ups

- **P2.20 (saves)** must persist `Memory.to_dict()` — it carries `seed` **and** the rng `state`; restoring
  only the facts would resume corruption from a different point in the stream. The seed is fixed at 0
  today so transcripts replay exactly; a per-run seed belongs in the save schema with P2.20.
- `docs/08 §1`'s "≤ 8 facts (some corrupted at stage ≥ 3)" is pinned by
  `test_store_limits_are_the_documented_ones` against `PromptBuilder.MEMORY_LIMIT` and
  `TurnSchema.MEMORY_MAX_LENGTH`, so a retune of either constant fails loudly.
- The transcript now carries `memory.proposal` (accepted / rejected + reason). If the F3 overlay wants
  "why she just refused to remember", that field is already there — no new plumbing needed.
