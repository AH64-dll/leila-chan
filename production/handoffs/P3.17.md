## Round 1  (2026-11-04, agent: deepseek)

### Summary

The six path endings now have content. `game/data/endings.json` carries, per row, the scripted
`frame` (the game's narration of the last scene), `direction` (the director's note her last line is
generated from) and `final` (that line, written by hand and reviewed, which stands whenever the model
cannot deliver). `game/llm/EndingLine.gd` is the pure half of the live line: prompt assembly (persona
+ the run's stage module + its path module when that module exists + `prompts/ending.md`), the
`{"line": string}` schema, parsing, cleaning, the shipped Safety scan and the fallback. `Ending.tscn`
now renders frame → her line → the log line, plans the reviewed `final` up front, and gives the live
answer a slot that is held open until the stream's terminal signal or `ui.json`'s `ending.final_hold_s`
(4 s), so a slow or hung model costs a short pause and never an empty last beat. Every one of the six
is reached in a scripted test from a run state the game actually stores — never from `Endings.force`.

### Deviations from the design bible

docs/01 §7 gives conditions and one-line premises; it says nothing about how an ending is *staged*.
Four decisions had to be made, all as data:

1. **The frame's voice and shape (docs/01 §7 is silent).** `frame` is the game's narration: second
   person to the player, third person about her, three sentences, no first person, no asterisks, no
   quotation marks — the ending screen has no scene art in this build, so the prose does the staging.
   Proposed doc text for §7: *"Each ending shows a short scripted frame (the game's narration of the
   last scene) before her final line."* Pinned by `test_the_frames_are_the_games_narration`.
2. **The live last line (docs/08 §1 describes a turn, not an ending).** One request, no history:
   persona + the run's stage module + its path module when present + `prompts/ending.md`, with the
   row's frame and direction in the user turn, constrained to `{"line": string}`. Proposed doc text
   for docs/08 §7: *"An ending's last line is generated once, from the persona, the run's stage and
   path modules and `ending.md`, and is not a Turn."*
3. **A refused line falls back instead of showing bars (docs/02 §8 says the filter runs on every say
   chunk).** The filter still runs; but a redaction or a filter error means *no live line at all*, and
   the reviewed `final` stands. The rule's intent — no unsafe model text is ever displayed — holds and
   is tested; showing `██████` where the game's farewell belongs would replace the ending with noise.
   **This is the one policy call for SAFE to confirm.** Proposed doc note under §8: *"Where a filter
   redaction would replace a single authored beat (the ending's last line), the reviewed fallback is
   shown instead of bars."*
4. **E06's fake delete and E10's empty title.** docs/01 §7 says E06 "deletes your save in triumph
   (fake)" — nothing is deleted; the ending's own autosave is written and
   `::test_e06s_deleted_save_is_a_bluff` proves the file still loads. E10's "the title screen is now
   empty" is a Title-state feature this task does not own, so the frame deliberately does not claim
   it ("the space where she was keeps her shape for one more second"). Follow-up below.

No safety rule, the content warning or "closing always works" is weakened: the live line is filtered
(fail-closed), the screen never intercepts a close, and Esc still leaves for the Title.
