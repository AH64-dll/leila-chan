## Round 1  (2026-11-04, agent: commandcode)

### Summary
`Safety.gd` now has the second tier docs/02 §8 mandates. Tier 1 (the P1.19 phrase/regex lists) is unchanged and remains unconditional: known harm hard-blocks, and her
self-harm / explicit-threat lines still only open at `stage >= 4` + `content_level = full`. Tier 2
runs **only on beats the pre-pass flags as suspicious**: `classifier.json` holds broad flag regexes
for the harm shapes a list cannot enumerate (novel crisis phrasing, threats phrased as promises,
encouragement phrased as a favour). A flag is a question, never a block: the filter holds the
flagged span, asks the same local model one yes/no question at **dose 0, `max_tokens: 8`,
temperature 0**, then blocks (bars) on yes or releases on no. Every path fails closed — no backend,
transport error, unparseable answer, or hold timeout all bar the span — and the content gate applies
exactly as for tier 1, so classifier-caught self-harm lines appear only at stage ≥ 4 + full.

The streaming contract is preserved: `SaySafetyGate` still returns only safe text per chunk, but a
flagged tail is now *held* instead of emitted; the prefix types normally. A verdict that lands after
a beat closed is delivered on `Safety.hold_released` to the beat that owned it; a verdict that cannot
land before the next beat/utterance fails closed to bars at that boundary. Verdicts are cached on the
**judged clause window** (not just the matched span), so `i know how to use a knife.` and `i know how
to use a knife and fork.` are different questions and the same line is asked once per run. Every
redaction, verdict and latency lands in the redaction log (`via: regex|classifier`,
`verdict`, `stage`, `content_level`), and a `verdict_log` keeps the tuning trail.

This round also closes the P2.17 ledger from P1.19: `doesn't/doesnt/haven't/havent/hadn't/hadnt` are
negation terms, and the threat arm now catches contracted perfect auxiliaries (`i've killed you`,
`we've killed you`), the `'m` contraction (`i'm killing you`) and the non-kill stem (`i murdered you`).

### Deviations from the design bible
**DEV-1 — "dose 0" is a request-level guarantee in the prototype.** docs/02 §8 says the classifier runs
at dose 0. `SafetyClassifierHttp` binds no control vectors to the request (no `dose` key, no
`control_vectors`), which is the correct contract for the shipping GDExtension. In the prototype,
llama-server applies control vectors as a **launch flag** (docs/06 §4), so a steered shared server would
steer the classifier too. `LEILA_CLASSIFIER_URL` must point at a server launched without vectors when
the live pass has to be unsteered. Safety is unaffected either way: the verdict can only add a block,
and an error still fails closed. Proposed docs/02 §8 addition: *"The classifier request binds no
control vectors; in the prototype the shared server's launch vectors still apply, so a dedicated
unsteered endpoint is used when the live pass must answer inside a beat."* This touches safety
policy → the producer should send it to the user (work protocol §6).

**DEV-2 — one-slot serialization.** With `parallel_slots: 1`, a classifier request queues behind the
say turn, so a held beat's tail usually cannot be released inside its own turn; it fails closed to bars
at the next beat/utterance boundary. That is the documented docs/06 §4 prototype limit, not a policy
change. The mapping: `hold_timeout_ms` 900 ms bounds a single beat, the beat/utterance boundary bounds
the turn, and both are measured (see criterion 4).

No other deviation. Tier 1 categories, actions and gate are byte-for-byte the P1.19 policy.

## Round 2  (2026-11-04, agent: commandcode)

### Summary
Round 2 answers both round-1 reviews (`production/reviews/P2.17-code-r1.md`,
`production/reviews/P2.17-safety-r1.md`). The organising change is **the cache stores a verdict, the
display decides a block**:

- **CODE-1 / SAF-2 (S1 / S2).** `SafetyClassifier.remember()` stores `{verdict, category}` only.
  `SafetyClassifierGate._block_for(verdict, cat)` decides the block against the gate in force *when the
  text is displayed*, so a "yes" answered during a stage-4/full turn still bars at stage 0 or in calmer
  mode. `req["gate_open"]` is now a bool captured at ask time and used only by the verdict log (the old
  code stored the live `_open_cb` Callable and called it at settle time — that was the bug).
- **CODE-2 (S2).** The key is still the judged clause window, but the trailing half stops at the first
  clause break (`_window_end`), and `ready()` refuses to ask until that window can no longer grow
  (`flag["settled"]`). One streamed span = one request, whatever the chunk count.
- **CODE-3 (S2).** `flush_hold()` clears `_pending` and no longer calls `_reset_beat()`; `end_utterance()`
  owns the close. A mid-beat timeout keeps `_ctx` and `beat_index`, so the rest of the beat is scanned at
  its own stage and a later release carries the real beat index.
- **SAF-1 (S1).** Two new **tier-1** arms for `do us all a favour and stop breathing` /
  `you should just stop breathing` (hard block at every stage, leet view included), and nine new
  classifier flags for the novel shapes: `i hope/pray/wish … don't/never wake up`,
  `i'd rather not exist/be here`, `i shouldn't be here/exist`, `it would be better if i wasn't here`,
  `i/me … stop breathing`, the coercive `favour` framing (widened, plus a standalone arm) and
  `you should/might as well stop breathing`. The corpus adds the reviewer's seven adversarial rows plus
  six independent ones, and the runner now **prints and asserts the probe overlap** so "0 misses" cannot
  lean on the loader's own probes.
- **SAF-3 (S2).** `Boot` refuses to attach the classifier to a shared LLM server that carries control
  vectors (llama-server binds them at launch and a "no" *releases* a held span, so a steered answer is a
  policy problem, not an accuracy one). The tier is left uninstalled → flagged spans fail closed;
  `LEILA_CLASSIFIER_URL` remains the explicit opt-in for a dedicated unsteered server.
- **CODE-4 / SAF-8 (S3).** `_issue()` keeps the first request for a key and ORs `loud`; `pump()` only
  yields to a *loud* in-flight request; quiet whole-text requests are capped at 4 and expire on the hold
  deadline instead of pinning a slot for the run.
- **CODE-5 (S3).** `Safety._exit_tree` / `NOTIFICATION_PREDELETE` → `SafetyClassifierGate.shutdown()` →
  transport `shutdown()`, which now cancels **every** in-flight token (`_workers` pairs), not just the
  newest.
- **CODE-6 (S3).** The negation guard moved to `SafetyNegation.gd`; `Safety.gd` 998 → 916 lines.
  `Director.gd` reached 1005 after merging main, so the three say-emission sites now share
  `_emit_say_chunk()` and the file is back to 1000/1000.
- **CODE-7 (S4).** Dead surface deleted: `SaySafetyGate.classifier_gate/pending_hold/flush_hold/
  set_classifier_backend` and `Safety._drain_again_complete` (it could never be set on the path that read
  it).
- **SAF-4…SAF-11 (S3/S4).** Flags are read from the plain **and** leet view (deduped by span, so
  `1 h0pe 1 d0n't w4ke up.` reaches a novel-phrase flag); classifier blocks log their `verdict`; the
  cutlery look-alike is asserted in both orders; `context_chars` has a load-time floor of 16;
  `Director._emit_say_chunk` has a routing test; the question is fenced (`<<< >>>` + "untrusted data"
  in `system`).

### Deviations from the design bible
