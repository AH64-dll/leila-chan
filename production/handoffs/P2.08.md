## Round 1  (2026-11-04, agent: deepseek)

### Summary
`game/llm/TriggerEngine.gd` is the docs/01 §5 trigger engine: four detectors (**K** keyword/regex,
**M** the Turn's `read` label, **E** the P2.09 engine event, **C** the clock/OS), three behaviours
(once / repeatable / escalating), per-trigger cooldowns, stage gates, and the docs/02 §1.2 agreement
rule as **data** (`strength.agreement` vs `strength.model`) — every weight, threshold, effect and line
lives in `game/data/triggers.json`, so adding a trigger is a data row.

`game/autoload/Triggers.gd` (P2.09's sink) is now the GameState/prompt seam: `begin_turn()` runs K+C at
docs/02 §4 step 0, `handle_engine_event()` runs E in real time, and `close_turn()` runs M when
`Director.turn_completed` fires. Effects land on GameState (meters, profile counters, flags);
path points are kept in `path_scores()` for P2.12; the fired row's docs/08 §6 line rides the turn where
its evidence completed (step-0 lines this turn, close lines the next prompt).

`data/triggers.json` ships the engine tables plus the seven **E rows** `data/telemetry.json` already
detects (T08, T09, T10, T11, T12, T31, T32) — real, cross-checked content that makes the cooldown and
behaviour caps live today. T01–T15's K/M rows and their effects are P2.10's data edit.

### Deviations from the design bible
- **Interpretation (docs/02 §1.2):** the bible says "when both agree, the trigger fires with full
  strength; model-only → half strength". It does not say what a **keyword-only** hit is worth, and
  docs/01 §5 has K-only rows (T02, T03, T06, T07, T24, T25, T27) that could never reach full strength
  if keyword-only were halved. So `strength.keyword` ships at 1.0 and the whole table is data
  (`game/data/triggers.json:4-10`): if playtests show keyword false positives, the fix is
  `"keyword": 0.5`, no code. No doc change requested; flag it if the design wants the opposite default.
- **`requires` (new data field, default `"any"`):** the bible's sentence implies agreement must be
  *possible* but not that every K+M row *needs* both. A row with `"requires": "all"` fires only when
  every declared detector matches (full strength); `"any"` fires on the first match and halves a
  model-only firing. P2.10 picks per trigger; `tests/test_triggers.py` refuses `"all"` rows with one
  detector (the agreement rule would be dead).
- **Where an M-only row reacts:** the `read` label only exists once the Turn is finished, so a
  model-detected trigger's line is told to the model on the *next* prompt (`Triggers.close_turn()` →
  `GameState.queue_event()`); K/E/C lines ride the turn where their evidence exists. Inherent to
  docs/02 §1.2, documented in both files.
- **`Director.gd` untouched (0 lines added):** the M detector subscribes to
  `Director.turn_completed` (`game/autoload/Triggers.gd:38-46`) instead of adding a pipeline call,
  because the file sits at gdlint's 1000-line cap. The pipeline's observable order is unchanged: the
  `read` is applied, then the trigger engine sees the finished turn.
- **E rows duplicate the docs/05 stage gate on purpose:** `data/telemetry.json` gates the EVENT *line*,
  `data/triggers.json` gates her *reaction*; both must be the same number, and
  `tests/test_triggers.py::test_event_rows_agree_with_the_telemetry_catalogue` fails if they drift.
  E rows leave `line` empty so the two files cannot double the same prompt line (pinned by
  `::test_e_rows_leave_the_line_to_telemetry`).
- **Trigger path points vs P2.12:** docs/01 §5's effects include path spikes ("YANDERE +3", "AWAKE +4"),
  and P2.12 owns the path score formulas. The engine accumulates them into `Triggers.path_scores()`
  (`game/llm/TriggerEngine.gd:222-226`) instead of writing `GameState.path`; P2.12 folds them in. Only
  T11's documented "HOLLOW +" ships today (`data/triggers.json`, +2).
- **DCR (docs/07 §2 tree):** the layout already lists `data/… triggers.json` and
  `autoload/Triggers.gd # keyword/engine/clock triggers (docs/01 §5)`. The split-out class needs a
  line, mirroring `llm/Meters.gd` / `llm/Stages.gd`: add
  `│  ├─ TriggerEngine.gd                # docs/01 §5 trigger matching, caps, effects, data loader`.
  Impact: the doc tree only. No other doc change.

### Role playbook checklist (SYS standards)
- **Rules as written:** docs/01 §5 states no numbers beyond "once / repeatable / escalating … and a
  cooldown"; the only strength rule is docs/02 §1.2's agreement sentence, and it ships as the data
  table `strength` (pinned by `tests/test_triggers.py::test_shape_and_strength_are_the_agreement_rule`).
- **Everything tunable is data:** weights, defaults, stage gates, cooldowns, escalation, effects and
  lines are `data/triggers.json`; code holds only the vocabulary. `tests/test_triggers.py` validates any
  row a reviewer or P2.10 edits.
- **Determinism:** one injected snapshot (`Triggers._context()`: turn, day, stage, hour, absence, flags)
  plus an injectable clock (`set_clock`); `test_replay_is_deterministic` and the seeded 200-turn
  `test_invariants_over_a_long_session` pin it.
- **Clamping:** the only untrusted input is the schema-constrained `read` enum; every meter write goes
  through `GameState.adjust_meter` (range clamp + ratchet), and the loader keeps only scalar flag values.
- **docs/05 §0 hard rules:** this task adds no window or input handling — T10 is a data row with `once`
  behaviour that records and queues a line, and P2.09's `auto_accept_quit` observation is untouched
  (`TelemetryTest::test_screenshot_key_and_window_signals_are_wired` still passes). The close intercept
  and its speech are P2.10's; closing stays one press.
- **Safety:** the engine emits authored data strings (docs/08 §6 style) into the system prompt, never
  model text, and displays nothing itself. The shipped rows name no disorder (docs/01 §4 rule).
- **Save/load:** `Triggers.to_dict()/from_dict()` with `test_to_dict_from_dict_round_trip`; P2.20 has to
  call them (follow-ups below).
