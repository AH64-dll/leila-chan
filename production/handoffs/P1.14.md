# Handoff — P1.14: TranscriptLogger (per-session JSONL turn transcripts + replay loader)

## Round 1  (2026-11-03, agent: swe2)

### Summary
`game/llm/TranscriptLogger.gd` is the P1.18 transcript logger (docs/07 §5): a RefCounted dev tool that
writes one canonical JSONL line per turn — prompt, schema, raw model output, applied events and backend
metrics — into `user://debug/turns_s<unix>-<seq>_p<NNN>.jsonl`, bracketed by session start/end marker
lines. Every line passes an injected safety redactor before it touches disk (records are *held*, never
dropped, while the hook is not ready), files rotate on a UTF-8 byte budget with a bounded file-count cap,
each line is flushed immediately, and a static replay loader parses transcripts tolerantly for re-feeding.
Disabled in release builds (`OS.has_feature("release")` gate) per the plan. NOTE: brief P1.14-r1.md on
disk describes the META Boot→Title→NameEntry flow, but the dispatched assignment for this worktree was the
TranscriptLogger implementation (SYS/L-LM scope, the P1.18 plan row). Implemented per assignment.

### Deviations from the design bible
- docs/07 §5 is one bullet ("every turn's prompt, schema, raw output, applied events → user://debug, dev
  builds only"). Conventions chosen (doc silent), all documented in the class docstring: JSONL file naming
  `turns_s<unix>-<seq>_p<NNN>.jsonl`; session start/end marker lines (`type:"session"`) coexisting with
  turn lines (`type:"turn"`, record format `"v":1`); rotation knobs `max_file_bytes`/`max_files`;
  `redact_ready()` gate so a Safety hook that attaches late (P1.19 is still a stub autoload) causes
  `log_turn()` to *hold* the record (returns false) rather than write unredacted data — Director wiring
  will need this contract.
- DCR (candidate): docs/07 §5 could spell out the record schema + redactor contract so the P1.19 Safety
  filter knows the hook signature `func(record: Dictionary) -> Dictionary` expected of it.
