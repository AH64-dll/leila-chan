### Review findings addressed

**CODE-1 (S2) — safety bound to the real filter, one scan, injection point free.**
Removed both local phrase lists and both `has_method("check_input")`/
`("filter_output")` guards. `SaySafetyGate` drives the P1.19 streaming API
(`begin_say`/`say_chunk`/`end_say`) itself, one beat boundary per streamed beat;
`register_chat_ui` no longer installs `chat_ui.text_filter`, so ChatUI's
docs/07 §3.4 seam stays free and nothing scans a chunk twice.
`DirectorRoutingTest.test_say_chunks_are_scanned_once_and_safety_drives_beat_boundaries`
proves one beat scan, the redaction, the surviving surrounding text, and that
`ChatUI.text_filter` stays invalid. Fail-closed: with no filter the gate returns
bars (`test_absent_filter_fails_closed_to_redaction_bars`), and the transcript
redactor bars too rather than writing raw text. The input check delegates to the
filter (`check_input`, else its own text scan) — no local list.

**CODE-2 (S2) — AudioDirector told the stage.** `Director._ready()` connects
`GameState.stage_changed` and syncs once at reset; `test_stage_change_tells_audio_director`
crosses a band and asserts `AudioDirector.get_stage()` follows.

**CODE-3 (S2) — schema in docs/02 order.** `_start_turn` passes
`ctx["property_order"] = TurnSchema.DOCS_02_PROPERTY_ORDER`, so the compiled
grammar emits `music`/`fx` before `beats` as docs/02 §1/§3 and all 75 fixtures do.

**CODE-4 (S2) — one resolver pass per beat, flags threaded.** `_maybe_route_sprite`
resolves once, emits `beat_resolved`, notes the sprite on `AudioDirector`, and
hands the finished packet to the new `Character.apply_beat(packet)`;
`Character.set_feeling` now delegates to it. `GameState.flags` reaches the
resolver. `test_sprite_resolves_once_per_beat_with_flags` asserts one resolver
packet, zero `set_feeling` calls, and that the character applied exactly the
packet the Director emitted.

**CODE-5 (S2) — AC-1 signal/routing tests exist.** New suite
`game/tests/DirectorRoutingTest.gd` (7 cases) with fake character, fake ChatUI,
fake safety filter, and AudioDirector/FX spies. It subscribes to every signal
(`turn_started`, `beat_started`, `beat_resolved`, `beat_say_chunk`,
`beat_cue_requested`, `beat_ended`, `turn_completed`) and asserts the routed
subsystem calls.

**CODE-6 (S3)** `validate_turn(turn_data, stage, last_offered_actions)` — the
offered actions now reach the validator.

**CODE-7 (S3)** Documented rather than silently changed: the `{"base": dose}`
fallback stays, because the merged P1.09 retry contract pins it
(`DirectorFallbackTest` asserts stage-1 base 2.5 + (−2.0) reaches the request) and
`LlamaServerBackend` ignores `request.dose` (control vectors are a server launch
flag, docs/06 §4). The transmission gap is named in the code comment as
P1.02/P2.02 work; the offset now scales whichever dose source wins instead of
assuming a `base` key.

**CODE-8 (S3)** `TurnContext.build` adds `offered` (the docs/08 §5 enums from the
stage gates), `meters`, and real `events` — `_handle_input_telemetry` now keeps
the trigger layer's returned lines and passes them as `ctx["events"]`.

**CODE-9 (S3)** `_teardown_turn()` is the single exit path for failed, cancelled
and completed turns: clears `_active_stream`, `_parser`, `_current_*`, closes the
safety beat. The player's unanswered line stays in `history`/`last_player_inputs`
by explicit decision (the player did type it; rewinding the §6 rule-1 window
would be wrong), and AudioDirector/FX keep the counters the opened turn accrued,
since rewinding them would let a retry loop mint cue tokens. Both choices are
documented on the function.

**CODE-10 (S4)** `MemoryRules` adds `meta`/`other` (a) and the full intent-label
set, makes rule 1 fail-closed when the player window is empty (b), and documents
the `> 2` content-word floor with its rationale (c) — grounding on a stop word
would be worse than missing a two-letter noun.

**CODE-11 (S4)** Auto-fill uses the new `AudioDirector.play_engine_cue` (engine
path, not the model's token bucket) and only resets the streak when the cue or fx
actually landed; `DirectorRoutingTest`/`DirectorTest` assert the streak behaviour.

**CODE-12 (S4)** `_close_turn_success` now runs `advance_turn()` →
`apply_slow_burn()` → `apply_mood()` → `apply_read()`, the P1.04/P1.29 handoff
order, so the per-turn mood budget lands under the index it is keyed on.

**DES-1 (S2) — parse status routed to failure.** `_on_llm_completed` reads
`_parser.finish()`; `ERROR` and `TRUNCATED` (and any `error` event) route to the
docs/02 §7 broken-stream fallback, never to `turn_completed`. P1.09's `turn_failed`
path and retry handling sit on top of that branch unchanged.

**DES-2 (S3)** Covered by CODE-12: the mood/read application block sits after
`advance_turn()`, so state is applied under the index the budget is keyed on.

**DES-3 (S3)** `_handle_auto_fill` only contributes `typeof(...) == TYPE_INT`
intensities to the max.

**DES-4 (S3)** The docs/02 §9 table moved to `game/data/sampling.json`
(`TurnContext.SAMPLING_PATH`), loaded with the same in-code fallback for a
missing/partial file.

**DES-5 (S3)** `DirectorRoutingTest` spies AudioDirector and FX; `DirectorTest`
auto-fill and the routing suite assert the fill path rather than only the counter.

**DES-6 (S3)** Flags are threaded to the resolver (see CODE-4), and
`DirectorRoutingTest.test_sprite_change_is_noted_for_rare_reveals` asserts the
resolved sprite reached `AudioDirector._sprites_seen`.

**DES-7 (S3)** The local safety phrase arrays are gone; the seam is
`SaySafetyGate`, which delegates every decision to the filter.

**DES-10 (S4)** The docs/02 §6 rule-2 list moved to `MemoryRules.META_WORDS` with
the source and the CON-2 sync note inline.
