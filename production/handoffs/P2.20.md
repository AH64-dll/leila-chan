## Round 1  (2026-11-04, agent: deepseek)

### Summary

Saves exist. `game/llm/SaveSlots.gd` owns the bytes — one file per slot under `user://saves`
(`slot_1.json`…`slot_3.json`, plus `autosave.json` for the per-scene autosave) — and the
`SaveSystem` autoload owns the game side: it captures the docs/07 §3.5 triple
(`state`, `memories`, `log`), applies it, and is the single autosave entry point. The Date scene
writes that autosave when it becomes live and after every completed turn; the Title screen's
`Continue` loads the newest readable save and enters the Date, which restores the saved scenario and
turn counter and does not replay the date's greeting. A corrupted save is a returned
`{ok, error, message}` value: the envelope is checksummed and version-gated, the payload is
section-checked, and `GameState.from_dict()` refuses before mutating, so a failed load leaves the live
run untouched and never ends the script.

### Deviations from the design bible

No rule changed. docs/07 §3.5 names the save files and their three parts and is silent on the rest; these
are the readings this implementation makes, each disclosed:

1. **The autosave is a fourth file, `user://saves/autosave.json`, with slot id `auto`.** docs/07 §3.5
   only spells `slot_N.json`; the autosave is not a player slot and must not collide with one.
   **DCR (docs/07 §3.5)**: add the sentence *"The per-scene autosave is `user://saves/autosave.json`
   (slot id `auto`); v1 exposes three manual slots (`slot_1`–`slot_3`), and the P3.x save menu owns the
   final slot count."*
2. **Autosave writes on scene entry and after every completed turn.** The plan says "autosave per scene";
   a single date is many turns, and a quit mid-date would otherwise lose the whole date. Both writes are
   the same `auto` slot.
3. **`log` is the displayed scroll-back (`ChatLog` entries), and the prompt history is rebuilt from it**
   (docs/08 §1 keeps the assistant side as spoken text). The Director's raw turn JSON is deliberately not
   written to a save: a save file would otherwise carry model text that the safety filter held back.
4. **The memory rng `seed` and `state` cross the file as decimal strings.** Both are 64-bit and a JSON
   number is a double; as numbers they would lose their low bits and the corruption stream would resume
   from a different point (P2.11's replay requirement). `_memory_data` parses them back.
5. **Autosave is off in a headless run** (`DisplayServer.get_name() == "headless"`): a headless build has
   no player. Tests that exercise the writer set `SaveSystem.autosave_enabled = true` and a scratch
   `save_dir`. Consequence: an editor playtest does not autosave until a task flips the flag.
6. **`MemoryStore.from_dict()`'s guard was made total** (P2.11 follow-on): its doc promised malformed
   slots were dropped, but `String(7)` from a corrupt slot aborted the script — exactly the "corrupted
   save → no crash" criterion. The change is type guards only; P2.11's tests still pass.

### Open questions / follow-ups

- **P2.19 (day/night)**: the Night scene should call `SaveSystem.autosave("night", {"scenario": …,
  "turn": …})` on entry/advance. Everything the day loop owns (day, turn, meters, stage, path, profile,
  flags) is already carried by `GameState.to_dict()` in the save.
- **P3.x save menu**: `save_to_slot`/`load_from_slot`/`list_slots`/`delete_slot`/`wipe` are the API;
  `list_slots()` returns `{slot, ok, error, saved_at, day, stage, scene, player_name, path}` per row, so a
  slot screen needs no new plumbing. M33's "names she writes" can ride in the payload later.
- **An in-game load must re-enter the scene**: `Date._ready` consumes the pending scene, so a future
  pause-menu "Load" should call `SaveSystem.load_from_slot(...)` and then `change_scene_to_file(Date.tscn)`
  (the Title path does exactly this). Loading while a Date is already live leaves its `_current_turn`
  untouched.
- **P3.12 shadow save** is `user://.leila/shadow.json`, deliberately outside these slots — `wipe()` only
  removes `slot_*.json` + `autosave.json` and must keep it that way.
- GameState `flags` still cross as JSON numbers (a 64-bit flag would round, as the memory rng would have).
  No current flag approaches 2^53; a future 64-bit counter needs the same string trick as `_memory_snapshot`.
- `Date` still replays the *current* scenario's opening beats on a fresh (non-resumed) date, unchanged;
  a resumed one skips them (see round 2, CODE-2: "skips" now means "the saved log contains them").

(`_autosave_scene.call_deferred("after turn")`), so it runs after `Director._turn_in_flight` is cleared
