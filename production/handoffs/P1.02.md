# Handoff — P1.02: `LlamaServerBackend.gd` — start/attach llama-server, HTTP + SSE streaming, json_schema per request, sampling params, timeouts, restart

## Round 1  (2026-11-02, agent: commandcode)

### Summary
`LlamaServerBackend` is now the real prototype transport. It implements the P1.01 `LLMBackend`
contract on the facade's worker thread: raw HTTP/1.1 + SSE over `StreamPeerTCP` (Godot's
`HTTPRequest` is a Node and main-thread only), the request's own `json_schema` in
`response_format`, whitelisted sampling + `max_tokens`, `enable_thinking=false`, prompt caching,
and a JSON probe for the first usable `say`. It can attach to a `serve.ps1` server or start and
own the pinned llama.cpp b12024 build (with control-vector launch flags); a watchdog restarts a
dead owned process, and a pre-token transport failure is retried once. Every wait is bounded and
polls the cancel token. Per-turn metrics are logged on one line and kept in `last_metrics()`.

### Deviations from the design bible
The docs are silent on these; none contradicts docs/07 §3.1, docs/02 §3/§9 or docs/06 §4:
- **A non-empty `TurnRequest.schema` is required.** An empty schema fails with `invalid_request`
  instead of sending an unconstrained turn (the B4 method depends on the grammar; a schema is
  always built by SYS). `LlamaServerBackend.gd:272`.
- **Sampling keys are a whitelist** (`temperature, top_p, top_k, min_p, repeat_penalty,
  repeat_last_n, seed, presence_penalty, frequency_penalty, stop`); unknown keys are ignored so a
  Director typo cannot break the transport. Missing keys get the hardened defaults
  `0.8/0.9/1.15` (repeat_penalty ≥ 1.15 from the role facts); the request always wins.
- **Prompt caching is on by default** (`cache_prompt: true`). docs/07 §3.1 asks for KV reuse;
  measured `cache_n=293`, `prompt_n=18–19` on turns 2+.
- **Attach never kills.** A healthy server on `base_url` is adopted and never supervised or
  restarted; an occupied-but-unhealthy port fails with `port_in_use`. This protects another
  task's server.
- **Supervision is automatic** for a process the backend started (`watchdog=true`, default
  1000 ms). `shutdown()` stops it; the LLM autoload calls that after joining the worker.
- **`first_say` is a transport-level probe** (a small JSON string scanner) until P1.03's
  `IncrementalJson` becomes the authority. It records the first character of the first non-empty
  `say`, measured from the POST like TTFT; an empty `say` is reported as `n/a`, not as zero.
- **A mid-stream crash is not retried** once any token was delivered (duplicates would corrupt
  the Turn); it returns `stream_truncated` with the partial text. The watchdog heals the server for
  the next turn. Retry-once applies only before the first token.
- **A verification Turn schema lives in the demo/test**, not in the backend; SYS still owns the
  real schema (P1.07).

### Open questions / follow-ups
- **P1.03**: `game/tests/fixtures/sse/` is a literal-byte corpus (SSE framing + content deltas,
  provenance/timings); use it instead of re-serialized Turn objects. Replace the backend's
  `FirstSayProbe` with `IncrementalJson` events when it lands.
- **P1.07 (C9)**: the schema currently permits `"say": ""`; one of the 20-turn runs returned it.
  Add the non-empty constraints and re-measure `first_say` availability.
- **P1.08**: map `stream_truncated` / `http_error` / `timeout` to docs/02 §7 fallbacks; the
  backend never retries after tokens and never invents a Turn.
- **P1.18**: `last_metrics()` and `last_log_line()` are the transcript hooks; `TurnRequest.to_dict()`
  already exists.
- **P2.03**: `request.dose` is not mapped to server launch flags here. `control_vectors` config is
  in place; mapping dose names → vector files and restarting at a stage change is P2.03.
- **P1.21 (C8)**: first usable `say` is **median ~1.85 s, p95 ~2.42 s** on the RTX 4050, so the
  <1.0 s first-beat gate is **missed** and this task does not claim it. TTFT is ~94–102 ms median;
  the model spends the gap on `inner/music/fx` before the first `say`. Report honestly in the
  performance pass.
- **P1.23**: control-vector paths are passed as a single argv element
  (`--control-vector-scaled`, `path:scale`), so drive-colon strings are not shell-parsed here;
  the launcher-side handling remains P1.23's.
