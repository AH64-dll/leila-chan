### Deviations from the design bible
- **DCR-1 — the P3.07 row vocabulary** (docs/07 §2's trigger row fields, docs/02 §1.2's detector
  letters). Five additions, all spelled out in `game/data/triggers.json`'s `doc` string:
  (a) `guard.mentions_memory` — T22's message repeats a stored fact; the evidence is the memory store,
  not a gift-word list. (b) `guard.name_mention` — T26's capture pattern + the endearment/command
  excludes; the capture becomes `GameState.player_name`. (c) `guard.text_match` — a pattern
  precondition for T28 (thanks/apology) and T30 (her past), which keeps the broad `read` labels
  (`affection`, `question`) honest. (d) `detect.clock.absence_hours_lt` — T17's reunion window must end
  where T18's 168 h begins, and 168 h itself belongs to T18. (e) `{"from_event": "<key>"}` flag values —
  T21's mute/unmute share one row and the flag follows `data.muted`. **Why:** docs/01 §5 marks T22,
  T23, T26, T28, T29 and T30 as M-only, but the 17-label `read` enum has no "gift she already got",
  "my real name" or "about her past" label; a guard is a precondition, not evidence, so the detection
  column stays M and `tests/test_triggers.py::test_rows_match_the_bible_detection_column` still holds.
  **Impact:** docs only; the loader heals unknown guard keys and the Python contract rejects them.
- **T25's stage-gated tone** ("Stage 0 she's scared; Stage 4 she's interested") is a single line that
  states the rule, not an `escalating` row: the data contract reserves `escalate.axis: stage` for the
  rows whose doc text says "escalates with stage" (T08), and the prompt's stage layer already supplies
  the stage. A step-axis line array would have given the Stage-4 tone at Stage 0 on the second mention.
- **T17/T18's path-specific reunion** is carried by the line ("the shape it takes is the current
  path's"), not by a path channel: docs/01 §5 gives the clock rows no path condition and
  `Triggers._context` has no path field; the prompt's path layer tells her which shape she is.
- **T20's live setter** is `Settings.set_photosensitive` only, because P3.13's settings screen is the
  task that adds text speed/volume/content level. The sink takes any setting name, so those call
  sites are one line each.
- **T21's caps condition is stored, not re-injected per turn.** The EVENT line carries docs/08 §6's
  instruction for the turn it lands on and `GameState.flags.audio_muted` holds "until unmuted", but no
  prompt layer reads that flag every turn yet (see follow-ups).
- **Model-only rows author double the intended effect** (T22/T23/T26/T28/T29/T30), because
  docs/02 §1.2 halves a model-only firing — the convention P2.10 used for T14. The docstrings say so.
- **The engine/file split and the Telemetry API consolidation** are structural, not design changes:
  `TriggerEngine` hit gdlint's 1000-line cap (P2.10 flagged it) and Telemetry its 20-public-method cap.
  `catalog_kinds()` was a thin `catalog().keys()` alias and `note_screenshot()` is now private; both
  call sites and the tests were updated.

### Open questions / follow-ups
- **P3.13 (META):** the Settings screen should call `Telemetry.note_player_action("settings_changed",
  {"setting": <name>})` for text speed/volume/content level, and a prompt layer should turn
  `GameState.flags.audio_muted` into the ALL-CAPS condition for every turn until the unmute
  (docs/01 §5 T21 says "until unmuted", and today only the event turn hears it).
- **P3.09 (META):** M08's "New Game, same her" can now say the previous save is gone (T19 fires from
  `SaveSystem.begin_new_game`/`delete_slot`/`wipe_everything` at stage 3+); the F3 overlay already
  fires `save_gone`/`settings_changed`/`audio_mute`/`audio_unmuted` as buttons.
- **P3.14 (META):** `GameState.flags.name_confirmed` (T26's `observe`) is the marker that a run's name
  was typed in chat; P3.14's name rules may want it to skip the OS-username offer.
- **T26's exclude list** is data and deliberately conservative; if playtests show a real name being
  rejected (a one-word name that collides with a stop word), extend `guard.name_mention.exclude`
  rather than touching the pattern.
- **`TriggerEngine` sits at 731/1000 lines** after the split; the next vocabulary round should keep
  growing `TriggerTable`, not the engine.
