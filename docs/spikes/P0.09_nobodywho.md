# Spike P0.09 — NobodyWho vs own GDExtension (feeds P4.01)

**Date:** 2026-11-02 (round 2: same day, review fixes) · **Agent:** LLM (swe2) · **Task:** evaluate
the NobodyWho Godot plugin against our four runtime requirements and feed a recommendation to
P4.01 (runtime decision) / P4.02 (GDExtension build).

**Candidate evaluated:** NobodyWho for Godot **v13.0.0** (released 2026-10-29), the prebuilt
GDExtension from `nobodywho-godot-v13.0.0.zip` (362 MB, 1.2 GB unpacked — one fat binary per
platform bundling llama.cpp + ONNX-Runtime speech stack). Rust core over a nobodywho fork of
`llama-cpp-rs`; licence **EUPL-1.2**. Requires Godot ≥ 4.6 — our pin is 4.7.2, OK.

**Design rule being tested** (docs/07 §1): *"if it exposes control vectors + JSON schema, use it;
otherwise our extension is a thin (~800 lines) wrapper."*

## Tested minimal example

The minimal project's sources are committed at `docs/spikes/p0.09_nobodywho_test/`
(`project.godot`, `main.tscn`, `main.gd`). The whole backend is ~10 lines:
`NobodyWhoSamplerBuilder.new().json_schema(schema).penalties(...).temperature(0.8).dist()`,
`NobodyWhoChat.create(model_path, cfg)`, `chat.complete(msgs)` → `stream.next_token()`.
Round 2 extended the harness: it now enumerates every `NobodyWho*` class via
`ClassDB.get_class_list()`, times `ttft` / first `feeling` / first `say` key / first `say`
content separately, validates schema constraints on every turn, and adds a boundary turn
(≥400-char `say` demand + a requested stray `secret` key).

```bash

# 1) copy docs/spikes/p0.09_nobodywho_test/ to a scratch dir OUTSIDE the repo
#    (Godot writes .godot/ inside the project — never run it in-tree)
```

## Verdict — for P4.01

**Build our own GDExtension (`libleila_llm`), keep llama-server for the prototype/prompt-lab.**
This matches the design's own decision rule: NobodyWho has the JSON-schema half but not the
control-vector half, and control vectors are the load-bearing feature — the dose schedule,
path-vector mixing and trigger spikes (docs/06 §3/§4) all need `llama_set_adapter_cvec` called
per turn on one long-lived context.

Secondary factors, same direction:

- Vulkan-only Windows GPU showed 8–25× run-to-run variance and ~1.75× the server's VRAM on our
  exact target GPU; docs/07 §6 already plans CUDA **and** Vulkan per platform — we'd ship CUDA
  ourselves regardless.
- Even at the best observed Vulkan throughput (42–44.6 tok/s), the first `say` content lands
  ~2.1 s in — the model pretty-prints the JSON, so ~85 tokens precede it (docs/02 §4 assumed
  ≈30). The < 1 s first-beat budget needs either faster prompt eval + generation than Vulkan
  shows here, or a compact-output turn (shorter `inner`, no pretty-printing) — flagged as a
  P1.x measurement task, not as a NobodyWho defect.
- EUPL-1.2 copyleft on a commercial Steam release needs legal review; a fork carrying a cvec
  patch inherits EUPL and removes the licence escape hatch.
- 143 MB bundled runtime carries STT/TTS/ONNX we never use; a thin wrapper is ~800 lines and
  keeps llama.cpp pinned/upgradeable.

What NobodyWho *would* be good for here: a drop-in **prototype/prompt-lab** backend if
llama-server ever became painful — the grammar/streaming/template-variable surface proved it
can drive a full Turn end-to-end. It is also a working reference implementation of
Godot↔llama.cpp async plumbing worth cribbing for P4.02.

## Open questions / follow-ups for P4.01–P4.02

- Own extension wraps llama.cpp directly in C++ (gdext), pinned commit, CUDA+Vulkan on Windows,
  Metal on macOS per docs/07 §6. Expose `set_dose(vectors)` → per-turn `set_adapter_cvec`
  (upstream llama.cpp PR #20381 fixed graph reset on cvec change, merged 2026-03 — take a
  build at/after that fix).
- **First-beat budget needs a P1.x re-measurement** (P1.02 server backend): observed ~85
  tokens before first `say` vs docs/02 §4's ≈30 estimate. Options to test then: tighter
  `inner` cap, compact-JSON prompting, or revising the docs/02 §4 budget itself — do not
  quietly inherit the <1 s number into P1 acceptance criteria without a fresh measurement
  on the CUDA server path.
- `complete(msgs)` resets context each call (keeps only the ~283-token system prefix); `ask()`
  appends. For our own backend the equivalent choice is explicit: keep KV and append per-turn
  history vs re-prefill — design docs/07 §3.1 assumes prefix reuse, which is confirmed cheap
  here.
- NobodyWho anomaly (995 s turn) — if P4.02 ever uses Vulkan on this laptop, re-test sustained
  multi-turn load; may have been power/thermal, not software.
- Licence check belongs on the SAFE legal checklist only if we ever ship NobodyWho or a fork;
  current recommendation avoids it.
- **DCR (docs/07 §1):** the stack table names the extension `libqwenchan_llm`; role standards
  forbid the brand in shipped identifiers → rename to `libleila_llm` (also fixes the outdated
  "qwenchan" codename). Doc line: `LLM runtime (ship) | Own GDExtension wrapping llama.cpp
  (libqwenchan_llm)`.
